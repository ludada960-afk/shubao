# 生产验收分层规范

## 原则

生产验收必须与本次变更的影响面匹配。真实电商生成不是普通健康检查，它会创建真实任务、消耗上游中转站额度，并验证一条特定的电商交付链路。因此它只能作为高风险变更的门禁，不能作为所有前端改动的默认烟雾测试。

## 三档策略

生产部署脚本使用 `-ValidationProfile`：

- `auto`：默认值。读取当前发布提交相对父提交的文件清单。纯导航、布局、组件样式、静态展示、文档和测试改动跳过真实电商生成；其余改动进入完整电商门禁。
- `frontend`：显式确认本次发布不需要真实电商生成。适用于纯 UI、导航、文案、静态案例和不改变业务动作的展示修复。脚本仍执行构建、公开图库/视频合同、认证账务读取和 600 秒应用 Canary，但不创建电商任务。
- `full`：强制完整门禁。适用于服务端、账务、生成路由、资产持久化、画布、电商工作台、视频工作台或无法准确分类的改动。

## 高风险范围

以下任一文件变更都按 `full` 处理：`server/`、`shared/`、`scripts/`、`src/services/`、`src/store/`、画布、视频、Plog、Remake、电商工作台、内容生成、自由创作生成模型、依赖锁文件、Vite/PM2 配置。

原因不是这些文件一定会触发电商请求，而是它们可能改变共享 API、会话、任务、账务、构建或运行时行为。分类器无法确认影响时必须保守进入 `full`，不允许为了省额度而放过不确定改动。

## 低风险范围

只有完全由导航壳、布局样式、通用展示组件、静态图片、文档和测试组成的提交，才可以使用 `frontend` 路径。低风险验证仍包括：`npm test`、生产构建、`npm run check`、`npm run collab:check`、`git diff --check`、本地桌面/移动端浏览器检查，以及不产生计费的公开能力合同检查。

## 明确禁止

- 纯 UI、导航和文案改动不得自动调用 `verify-production-ecommerce`。
- 不得把真实电商生成当作“站点健康接口”或普通 API 冒烟测试。
- 不得用 `frontend` 覆盖明显涉及服务端、账务、生成、资产、画布或共享状态的变更。
- 不得因为某次全量验收历史上通过，就把它复制到所有后续任务。

## 什么时候仍然需要真实电商验收

当用户明确要求上线、或变更影响真实电商交付链路时，完整门禁仍然必要：真实输入上传、计划、生成资产、作品/画布持久化、积分冻结/结算/释放、稳定 URL、服务重启恢复和 Canary 稳定性都属于同一条交付链，不能只测其中一个接口。

## 当前导航任务的判定

导航壳层本身只涉及 `App.jsx`、`components/layout/`、`styles/` 和测试，属于 `frontend`。本次为了让“万物上身 / Plog / 海报 Skill”真正直达，又补了首页和共享客户端状态的启动意图接线；如果这些接线与导航壳层在同一个发布提交中，`auto` 会按保守规则判为 `full`。确认接线只改变入口选择、不改变生成/账务/服务行为后，才可以显式使用 `-ValidationProfile frontend` 跳过真实电商生图。不能把这个例外推广为所有首页或共享状态改动都跳过门禁。

## AI 视频验收补充

AI 视频的默认验收入口是 `npm run verify:video-acceptance`，对应零额度 L0 门禁；它验证平台标记、渲染对账、资产/分镜工作台和账务不变式，不提交任何供应商请求。线上临时 TUS 创建/删除属于 L4，仅在正式发布脚本中一次性执行，删除具备有限幂等重试。真实视频生成属于 L5，只能由用户明确批准，不是自动部署或普通 QA 的组成部分。完整矩阵见 `docs/architecture/ai-video-acceptance-gates.md`。
