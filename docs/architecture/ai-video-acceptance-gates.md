# AI 视频客观验收门禁

## 目的

验收要证明“这次改动达到契约”，而不是重复调用上游模型。默认门禁不创建视频生成任务、不提交供应商、不修改钱包，也不依赖一次偶然的截图观感。

## 分层规则

| 层级 | 触发条件 | 必做检查 | 上游额度 |
| --- | --- | --- | --- |
| L0 本地契约 | 每次 AI 视频改动 | 全量单测、构建、静态检查、任务/资产/分镜状态机、恢复计划、模拟渲染对账、`npm run verify:video-acceptance` | 0 |
| L1 本地浏览器 | UI、画布、上传、交互变更 | mock provider 下的 Playwright/browse：首屏、加载/失败态、选中派生工具条、删除联动、键盘、无溢出、控制台错误 | 0 |
| L2 预发布合同 | 服务端/API/存储变更 | 健康、公开能力目录、鉴权所有权、TUS 创建/偏移/删除、Range/304/HEAD、幂等/重试、账务只读；供应商适配器使用 fake | 0 |
| L3 线上只读 | 每次发布默认 | `/health`、公开图库/视频合同、PM2 稳定性、计费目录只读、锁与版本指纹 | 0 |
| L4 非计费线上金丝雀 | 只有发布脚本或人工明确开启 | 一次有预算的临时 TUS 创建/删除；删除只允许幂等重试，404 视为已清理；禁止 POST 生成、禁止扣费 | 0 |
| L5 真实生成 | 只有用户明确提供额度上限并同意 | 生成前后账务快照、供应商请求、结果交付、失败退款、作品/画布持久化和可复现配方 | 用户明确承担 |

## L0 的硬性通过条件

`npm run verify:video-acceptance` 必须输出并满足：

```json
{
  "profile": "local-no-paid-generation",
  "providerSubmissions": 0,
  "billingMutated": false,
  "paidGenerationRequested": false,
  "ok": true
}
```

该命令覆盖三个不调用供应商的证明：数据库平台标记与迁移检查、渲染 outbox/重试/超时/篡改对账、资产/分镜/项目/操作漏斗 pilot。它不是“假生成”，而是验证生成前后最容易出错的状态契约。

## 变更到门禁的映射

- 只改导航、布局、文案、静态案例：L0 + L1 + L3；不跑真实电商或视频生成。
- 改视频工作台 UI、状态机、上传或画布：L0 + L1 + L2；发布时默认不付费生成。
- 改供应商适配、任务提交、资产交付、账务、生产存储：L0 + L1 + L2 + L3；发布脚本才可进入 L4。
- L5 不属于自动部署门禁。任何“全量通过”都不得暗示真实视频已生成成功，除非报告中有用户批准的请求、供应商 requestId、账务前后快照和交付 URL。

## 证据格式

每次发布至少保留：提交 SHA、门禁层级、测试总数、`providerSubmissions`、`billingMutated`、`paidGenerationRequested`、线上版本指纹、健康结果、残余风险。截图只能作为视觉辅助，不能代替状态和计费证据。

## 本次故障的处理原则

线上临时上传删除是幂等清理动作。网络异常时最多有限重试；如果服务端已经删除而响应丢失，后续 404 表示目标状态已达到，不应把它误报为供应商或生成失败。上传创建不是幂等动作，不得因为网络异常自动重试，避免产生重复会话。
