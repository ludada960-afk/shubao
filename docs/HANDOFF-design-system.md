## 一、用户是谁、他要什么（最重要的一节）

用户是产品负责人，中文沟通，**不写代码但会逐条验收**。原话与执行口径：

| 原话 | 执行口径 |
|---|---|
| 「你绝对绝对不能忽略我任何的需求…一次性把它们全部都做出来…不准中间再停下来问我」 | 派活后**一次做完**，不要做一点就交差；只有需要权限、不可逆操作、产品方向冲突才停 |
| 「绝对不能有任何 bug」「不要做半成品」 | 每一处都要**实测过**；宁可少做并说明，也不交半成品 —— **半成品红着比没做更糟** |
| 「你现在做的很多东西影响到了其他的代码，形成了污染…你要有一个全局思维…一切都必须有一个总统筹来做把关」 | 你是**统筹**：管全局一致性、拦破坏性改动、维护知识库与门禁，不是闷头写一个页面 |
| 「UI 做得很丑…全是黑白极简风…间距、主次、大小也没调好」「别人懂得用圆角、叠放、毛玻璃、选中交互」 | 要**设计系统**（token + 组件规范 + 状态反馈），不是零散美化 |
| 「你要建立相关的知识库…你不要做出来的东西跟我们现在整个网站是格格不入的」 | 知识库要**可执行**（门禁/棘轮），风格要**全站统一** |

**汇报格式（他一直这么验收）**：先给**数字**（before → after），再给**证据**（实测 / 截图 / 变异测试），再给**提交 hash**。
**做不到的必须说做不到**，并给替代证据与局限；**不许把「部分达成」写成「完成」**。
他极度反感两件事：**① 说了做完其实没做完；② 因为一点小事就停下来问他**。

## 二、四条产品铁律（任何改动都不能违反）

1. **没有用户确认，绝不扣费**。挂载即扣费、空输入也扣费、点一下就扣 —— 都违规。验收用**余额变化**，不用返回码。
2. **定价只有一个来源 = 后端目录**（`server/billing/catalog.mjs` 的 `FEATURE_SKUS` + `quoteFeature()`）。前端不得有第二份参与计算的价目。
3. **老文档必须保持可读**（不要把历史文档删成孤儿引用）。
4. **绝不向用户暴露 上游 / 供应商 / 备用通道 / 中转 / 任务号 / 内部域名 / 密钥名**。
   ⚠️ **模型名是故意展示的**（视频模型下拉是标准答案）—— 判定要看它是否暴露「谁在背后供货」。
   用户可见的每条通道都算：JSX 文本 / aria-label / title / placeholder / toast / 下载文件名 / 服务端上屏字段 / 浏览器插件 UI。

## 四、这棵树有什么脾气（必须知道）

1. **只在这个 worktree 工作**：`F:\da\shubao\.worktrees\codex-ecommerce-stability`（分支 `codex/ecommerce-stability`）。
   仓库根 `F:\da\shubao` 是 master，落后上千提交 —— **永远不要在那里读或跑**。
2. **多条线共用一个 git index**（本会话最多同时 9 条），由此出过三次灾难：
   - 离线 patch 上下文过期 → **37 个文件被当删除应用**（Home.css 3585→935、EcStudio 1404→**1 行**），**构建全红而单测全绿**；
   - 一次文案修复把 8 个插件文件**整体改成 CRLF** → 1646/1486 的假 diff，真实改动被淹没；
   - 单文件半改状态挂了 **4 轮** → 其他所有线的验证结论全部不可信。
3. **纪律（RTK §3.1 共 16 条，摘要）**：
   - 一律 `git commit -F <msg> -- <pathspec>`；**严禁** `git add -A` / `-a` / `stash` / 裸 `commit`；
   - **`git write-tree` 不是隔离手段**（它写整个共享暂存区）；
   - **改完立刻提交**（未提交的改动会被别人的 pathspec 带走、被 reset 抹掉）；
   - **禁止**：PowerShell `Set-Content`/`Out-File` 写源码（会把文件压成一行）· 「整文件写回」做隔离 · 离线 patch 改代码；
   - **被截断的输出不能当作「文件里没有」的证据**（要证不存在必须打印计数）；
   - 报故障前**先重跑一次**（并发写入瞬时态、编辑器保存竞态都会造成假红）。
4. **提交前必须跑** `npm run precommit`（构建 + 12 条硬门禁），**绿了才提交**。
5. 本地 vite 用 **5199 或 5188**（5173 常被占）；QA 通道 `?qa=ec-canvas` / `?qa=ec-canvas-real` / `?qa=plan-launch` / `?qa=visual`。

## 五、设计系统现在长什么样（已建成，别重造）

### 5.1 唯一权威
| 资产 | 位置 | 守护它的门禁 |
|---|---|---|
| **token 唯一权威** | `src/styles/design-tokens-v3.css` | 同作用域重复定义（按解析值）、幽灵变量、对比度（按作用域取值） |
| **设计系统层** | `src/components/ui/`（13 文件）+ `.sb-*` 工具类 | `design-system-layer`（棘轮 + 键盘可达 + **禁止新建 `ds/` 第三套**） |

| **交互态** | tokens §22 + §17b 全局焦点基线（`:where()` 零特异性） | `interactive-state-coverage` / `focus-visible-baseline` |

### 5.2 关键概念
- **`:where()` 全局焦点基线**：零特异性 → 组件自写的 `:focus-visible` 与任何 `outline:none` **照样赢**，它只在「本来什么都没有」的地方生效。**Safari 对 `<button>` 不画 UA 焦点环**，基线就是为它加的。
- **棘轮（ratchet）**：基线与实测绑定、**只许向下**。迁一批就把基线改小 —— 不收紧 = 给回退留出合法空间。
- **门禁必须有「检测器自证」**：喂反例必须变红；**写完契约必须做变异测试**（把已知错误实现放回去，契约不红等于没写）。
- **契约锁判据不锁写法**（RTK §3.1-10）：底部操作栏的测试曾断言「必须有 `min()` 回夹」，而实测证明**那个 `min()` 正是窄屏偏移的根因** —— 测试当时在保护 bug。

### 5.3 裁定索引（`docs/design/40-decisions.md`，共 24 条）
常用：**D1** 紫=交互主色（品牌红仅标识色）· **D6** 圆角阶梯 · **D10** ink vs fill · **D11** 键盘可达硬门槛 ·
**D15** token 只能替换逐值相等的字面量 · **D16** 间距半档 2/6/10（拒绝 5/7/9）· **D17** 14px 入档、15px 退役 ·
**D19** 字号 11 档（10…48）· **D20** 暖棕=阴影色 / 玻璃白=玻璃色，alpha 先合成再比 · **D21** 暖棕描边 → 暖黑描边档 ·
**D22/D23** `-strong` 文字档（D22 只给 danger；D23 扩到「白底+页底」定义域，两者并存）· **D24** V2 token 家族只减不增、禁止当档位归并。
