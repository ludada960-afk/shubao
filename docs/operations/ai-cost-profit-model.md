# AI 成本与利润模型

本项目把用户积分、上游真实成本和现金收入分开记录。后台展示的是可审计的理论值，不能把赠送积分误认为已经到账的现金收入。

## 计量单位

- `ec_points` 的 1000 ledger units = 1 AI 积分。
- 当前长期套餐的最不利积分单价来自 `ec_studio_199`：199 元 / 760 积分，约为 0.261842 元/积分。
- 赠送给内测账号的积分属于促销补贴。它会真实扣除并产生上游成本，但不会被计入现金收入。
- 内容套餐使用独立的 `content_sets` 货币，不与 AI 积分混用。

## 收入、成本和利润

每一笔成功动作会保存 `sku`、功能、模型、提供商、积分消耗和上游成本快照。后台提供三种口径：

1. **理论收入**：消耗积分乘以当前套餐的最不利积分单价。这个数用于比较不同功能的商业价值。
2. **现金收入**：只统计已支付订单实际授予的积分产生的收入。赠送积分不会进入这一列。
3. **上游成本**：结算时保存的提供商报价，不能在报表刷新时用今天的报价覆盖历史记录。

理论贡献 = 理论收入 - 上游成本。

理论毛利率 = 理论贡献 / 理论收入。

服务端对可见动作执行 70% 的贡献毛利门槛，同时预留 3% 支付成本 allowance。内测阶段看到的“理论贡献”不是承诺利润；真正的现金利润还要扣除支付费、退款、存储、带宽、客服和失败重试等经营成本。

## 扣费与失败安全

- 任务创建前先校验权限、配额、素材和可用路由，再以幂等 key 冻结积分。
- 上游成功并且输出通过质量门后结算对应 item，并写入模型/提供商成本。
- 上游失败、超时、不可用或质量门拒绝时释放冻结，不扣用户积分。
- 同一个幂等 key 重放只返回原结果，不重复冻结、结算或释放。
- 视频方案分析默认单独收取 1 积分；同一用户、同一素材内容哈希、同一提示词和分析版本重复进入时复用结果，不重复收费。

## 并发和上游路由

图片与视频使用独立的公平队列和并发上限；视频的 Fast、标准、实验路线分别受路由熔断器保护。上游 65535 仍作为图片路线，IP233 的 Seedance 路线作为视频候选，不把两个中转站的可用率假设成永久稳定。没有有效视频凭据时，视频生成按钮保持禁用，分析流程仍可展示且不会触发付费生成。

后台可以按账号、功能、提供商、SKU 和模型查看动作次数、积分消耗、上游成本、理论收入、现金收入、补贴和贡献。这样内测数据能区分“用户真的用了多少”和“这部分使用是由赠送额度补贴的”。
