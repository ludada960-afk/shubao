## 需求 A：skill 子页面要做**该 skill 专属**的工作台

### 用户原话（逐字，保真）

> 「像这个小红书的我不是跟你说过吗？我们之前虽然是有做这些相应的功能。我们之前首页有做过四个板块的入口，
> 然后他们确实也做了很多相应的这些 skill 页面。但是**那一版首页那些已经是过去式了**。我们现在把这些 skill
> 放到这些子页面的目的是要结合他们对应的**专属工作台**定制的这些专属工作台去进行设计呀。你现在根本就
> 没有去定制相应的工作台，**你只是把以前老版的首页给挪到里面来了**，你这是完全不对的。」

> 「即便知渔他们没有这种 skill，我们没有可以抄的对象，我们也可以根据我们现在已经抄了他们几十个
> 工作台的这些模式去规划定制相应的工作台出来呀。这个问题**可能不止这个小红书图文有存在这种问题**，
> 可能图片生成和视频生成的他们**几十个子页面**里面可能也有类似的问题，我需要你**全部**去定制成我们现在
> 统一的那种抄知渔他们的那种方案。」

> 「他们相应的逻辑和模板我相信你肯定是知道的，并且你都抄了那么多了，你肯定是理解的，如果你不理解，
> 你就重新再去看一遍代码，把我们所有的这些工作台代码都去看一遍，你要了解他们是怎么去发挥这些相应的
> skill 的定制方案的。是怎么去发挥 skill 能力的？**让 skill 简单上手，能够快速的在用户手里去产出最佳的效果。**」

### 判据（做完了怎么算过）

- ❌ 不接受：把首页旧版四板块原样搬进子页面
- ✅ 要：每个 skill 有**自己的**左栏工作台，字段按**这个 skill 的能力**来设计
- 范围：**全部** skill 子页面，不只是小红书图文；图片生成 / 视频生成**几十个子页面**都要过一遍
- 知渔没有对应 skill 可抄 ⇒ 用我们已经抄过的那**几十个工作台**的既有模式来规划
- 目标不是"好看"，是**让 skill 简单上手、快速产出最佳效果**

### 调查入口（动手前必须先读）

- `src/skills/imageSkills.js` —— skill 声明与能力清单
- `src/components/media/WorkbenchShell.jsx` / `FieldRenderer.jsx` —— 共享工作台与字段渲染
- `src/styles/generate-cta.css` —— 主 CTA 与提示行的唯一真源
- 已抄知渔的工作台参考：`docs/design/64-quantv-video-skill-pages.md`（视频侧左栏实测）、
  `docs/design/83-*`（留影 AI 按钮规则）
- ⚠️ 已知隐患：`VideoStudio/index.jsx` 同时 import `Home/Home.css` 与自己的 CSS，两边都巨大且互相覆盖；
  `Home/index.jsx` **零 CSS import**，靠别人顺带引入（隐式依赖）。改工作台前先把这条理清。

## 需求 B：模型 / 分辨率 / 比例收进**两个按钮**

### 用户原话（逐字，保真）

> 「然后这些工作台的**模型选择**和相应的**分辨率比例**这些东西。我之前不是在让你去改那个概念设计方案的
> 时候，**已经有告诉你要全局都去改**吗？就是要把它们做成**两个按钮**，在两个按钮里面就可以去设置
> 所有方案的呀。你为什么现在全部都要让它**张开**出来呢？」

> 「我不是跟你说过**图片生成和视频生成全局**都要去按这种方式去处理吗？就是两个按钮涵盖绝大部分的可以
> 设置的这些样式进去啊。像**分辨率、比例**这些都是应该做进去按钮里面的。你是不是没有去把所有的子页面
> 都去整理一遍呀？我都跟你说了，图片生成和视频生成的**几十个子页面**都要去这样做呀。」

### 目标形态（用户第三张图就是标杆）

底部一行两个按钮，**默认收起**，点击才展开面板：

```
[ 🖼 生图模型   GPT Image 2…        ]   [ 🄰 画面规格   3:4 · 2K 高清   ⌃ ]
```

- 按钮上显示**当前值的摘要**（模型名截断、规格合成「比例 · 分辨率」）
- 面板**浮起**（popover），不是把左栏撑开
- 概念视觉方案页**已经是这个形态**了 ⇒ 它是现成的样板，不是新设计

### 反例（用户第二张图 = AI 换装页，现在是错的）

模型选择 7 项全平铺 + 分辨率 1K/2K/4K + 比例 6 项 + 生成张数，全部**张开**。

### 判据

- ❌ 不接受：左栏把这些控件平铺展开
- ✅ 要：收进两个按钮，点开浮层设置
- 范围：**图片生成 + 视频生成的全部子页面**
- 用户强调「我之前不是已经有告诉你要全局都去改吗」⇒ 说明**概念设计方案里已经定过**，
  这次是**补齐没做到位的页面**，不是重新设计。**动手前先去读那份概念设计方案。**

## 两条需求的共同点

都要求**全局**、**几十个子页面**、且**已经定过规范只是没铺满**。
所以第一步都是同一件事：**把现状盘清楚**（哪些页面已合规、哪些没），再决定改哪些。
不要一上来就逐页改 —— 那正是"每页一个样式"的老毛病。
