## 0. 结论先说（本轮最重要的三个判断）

### 0.1 「子页面」不是独立页面，而是**卡片点开的模态弹窗**

用户批注（58 · image.png #1）说的"视频创作的这个 skill 页面……他这里有一个教学示例"，指的是
**`/zh-CN/skill/` 列表页上点开任意一张 skill 卡片后弹出的详情弹窗**。实测证据：

| 判定 | 实测 |
|---|---|
| 卡片是不是 `<a href>`？ | **不是**。`<article data-skill-id="..." role="button" tabindex="0">`，**无任何 `href`**，点击走 React 事件 |
| 点了会不会换 URL？ | **不会**。`before = /zh-CN/skill/` → `after = /zh-CN/skill/`（URL 不变） |
| 那出现什么？ | 出现 `[role=dialog]` 弹窗，实测矩形 **874 × 779 @ (587, 123)**，两次点不同卡片均复现 |
| 全站有没有独立子页面 URL？ | **没有**。整站所有 `<a href>` 只有 8 条内链：`/zh-CN/`、`/projects/`、`/generator/`、`/library/`、`/skill/`、`/zh-CN/#explore`、`/docs/?flovatv=1`、`/agent-cli/` |

> ⚠️ 注意 `/zh-CN/generator/` 实测**会重定向回 `/zh-CN/` 首页**（`location.href` 落到 `https://flova.tv/zh-CN/`），
> 它不是一个可达的工作台页面。**创作台整体在登录墙后面。**

### 0.2 「教学示例」的形态 = **弹窗顶部的自动播放视频 + 下方完整 skill.md 教程正文**

这是本轮最关键的形态结论，**和用户想象的不完全一样**：

- 用户批注说"教学示例里面的这个视频它也是可以下载的" → **视频形态确认**，是 **CDN 上真实可下载的 mp4**（见 §1.3）；
- 但它**不只是视频**。弹窗 = **三段式**：顶部视频头图 → 中部 `skill.md` 全文（**图文教程正文**）→ 底部操作条。
- 中部教程正文**默认被登录墙遮住**（CSS 渐变蒙层 + 「登录查看」按钮），但**文字已经完整躺在 DOM 里**，
  所以本轮能把全文抄下来（见 §1.4）——这是本次取证最大的收获。

### 0.3 「代为撰写」**未取到**

公开面（未登录）**任何页面都没有出现"代为撰写"四个字**。逐页核验：

| 页面 | 含「代为撰写」 | 含「教学示例」 |
|---|---|---|
| `/zh-CN/skill/`（及其 20 个弹窗） | ✗ | ✗ |
| `/zh-CN/`（首页） | ✗ | ✗ |
| `/zh-CN/generator/`（重定向回首页） | ✗ | ✗ |
| `/zh-CN/#explore`（FlovaTV） | ✗ | ✗ |
| `/zh-CN/docs/` 全部 14 篇 | ✗ | ✗ |
| `/zh-CN/video-models/seedance-2-5/` | ✗ | ✗ |
| `/zh-CN/changelog/` | ✗ | ✗ |

**卡在哪**：`去使用 Skill` 与 `登录查看` 两颗按钮都带 `data-auth="1"`，实测点击后**不跳转、只弹登录注册浮层**
（浮层原文：「注册领 300 积分 / 立即登录领取」）。工作台在登录态内，**未登录无法进入**。
→ 详见 §2 的「未取到」专章，**不编造**。

#### skill.md 教程正文的结构（实测标题层级，两份样本一致）

教程正文是**分章节的结构化规则书**，实测出现的章节标题（**跨两条 skill 复现**）：

```
流程规划:      ← 阶段逻辑与依赖关系（含"依赖关系：2→1；3→2；4→3…"、"何时暂停：不要一次性运行所有步骤"）
故事板设计:    ← 如何设计关键元素 / 如何设计镜头 / 如何设计独立音频
媒体生成:      ← 元素资产生成 / 最终镜头视频生成（含"推荐模型：Seedance 2.5，分辨率 480p"）
提示词写法:    ← 图像生成提示词 / 视频生成提示词（含 Seedance 顺序：摄像机→主体→空间→音频）
剪辑与节奏:    ← 转场、配速、剪辑频率
```

**「流程规划」章节逐字样本**（商品宣传短片 V27）：

> 阶段逻辑与依赖关系：
> 1. 编写 Final_Video_Spec.md（标题、类型、比例、时长、视觉风格、语言、模型偏好）→ text_editor。
> 2. 生成故事板（关键元素、镜头列表、音频层）→ storyboard_designer。
> 3. 为所有元素生成图像 → media_generator。
> 4. 为每个镜头生成最终视频；参考该镜头的参考元素（第 3 步）→ media_generator。
> 5. 基于故事板生成所有音频层 → media_generator。
> 6. 资源就绪后进行最终剪辑；然后引导用户导出 → video_assembler。
>
> **依赖关系**：2→1；3→2；4→2,3；5→2；6→4,5。
>
> **何时暂停**：不要一次性运行所有步骤。在上述每个关键阶段（例如：规格确定后、故事板确定后、元素图像生成后、
> 关键帧生成后、镜头视频生成后、音频生成后）停下来，与用户确认，然后再进行下一步。
> 在继续之前，使用卡片或 reply_to_user 邀请用户审阅。

**「提示词写法」章节逐字样本**（跨 skill 稳定复现的硬规则）：

> 优先级最高、适用于所有 prompt 编写情况：当用户使用中文输入或是加载中文语言环境时，提示词 prompt 需要用中文书写。
> 但是 prompt 中有关旁白/对话的内容要严格遵循 Final_Video_Spec 中的 Output Language。
>
> 在视频提示词中，为每张参考图标记每个角色，以便 Seedance 能正确读取面部和造型。
> 使用产品图片标签（`<<<image_1>>>`, `<<<image_2>>>` 等）。然后按照以下 Seedance 顺序（**摄像机 → 主体 → 空间 → 音频**）追加运动/动态提示词。
>
> 包装符有助于模型区分 音乐、音效、对话 和 屏幕标题文字：
> - 音乐（描述正在播放的内容）：`(...)`，例如 `(fast-paced rock playing in the background)`
> - 音效：`<...>`，例如 `<distant dog barking>`
> - 口头对话：`...`；若台词不是项目原始语言，在花括号前标注语言，例如 `Says in Japanese: こんにちは`
> - 屏幕标题/章节/字幕文字：`【...】`，例如 `【Chapter One: Departure】`
>
> 注意：您必须始终在提示词中包含以下负面约束，以确保后期制作的输出干净：
> - 如果分镜脚本表明该镜头有单独的旁白音轨，请不要在视频提示词中写入旁白文本，以避免音频冲突。
> - 为防止模型添加不需要的背景音乐，您几乎应该始终包含 `'no music'`。
> - 字幕是在后期剪辑时添加的，因此您必须始终包含 `'no subtitles'`。

#### 教学示例 ↔ 工作台真实字段的对应关系

这是用户批注里要求的"**结合教学示例做深度匹配，按他的讲解 + 工作台里真实有的按钮和功能去做规划**"。
