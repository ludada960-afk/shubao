# 89 · 画布生态方向：现状对账 + 市场调研 + 方案（2026-09-27 批 CV）

> 用户原话（逐字，本批交代的原话全段在 `RTK.md` 的「2026-09-27 用户新批注」一节）：
> 「现在我们整体已经把原来首页的四个板块给改成了两个通用的板块……那现在我们在画布里面，
> 如果要去开发之前给出来的这几个生成的板块的话，**你认为我们应该怎么做会更好呢**？」

> 工作流集合成**模板**，然后通过这些模板去进行**进一步的增值收费**……」
> 「我们目前画布是**上个版本的东西**了……你觉得**是不是已经太老旧了需要去做一次全面的升级或者重构**？」

## 1. 结论先行（TL;DR）

1. **不需要推倒重来。** 我们的画布是**自研引擎**（`src/pages/EcCanvas/**` 里 React Flow / @xyflow **0 命中**），
   这一点与**知渔同构**（知渔也是原生自研：`docs/superpowers/specs/canvas-research/quantv-canvas-teardown.md`
   记「不用 React Flow，用原生 article + section」）；TapNow 与 liblib 才用 React Flow。
   ⇒ 「自研引擎」本身不是技术债，**不能拿"别人用 React Flow"当重构理由**。
2. **真正过时的不是引擎，是"画布 ↔ 新生态"的接线。** 今天用户拍到的两处失效就是这个：
   首页四板块收敛成两板块后，画布里还挂着**指向旧首页电商入口**的按钮（商品信息 / AI 规划）——
   它们连面板都没渲染（批 CU 已按用户口径拿掉）。
   ⇒ 要做的是一次**接线升级**（子页面 ↔ 节点 ↔ 资产 ↔ 计费），不是重画引擎。
3. **要往"工作流生产地"走，我们缺的正好是三层里的一层半**：
   · **应用节点**（一张节点=一条预设工作流）—— **已有**（`canvasActionRegistry.js` 的 `application-*` 4 项）；
   · **模板 = 真图结构 + 一键铺开**—— **有一半**：`WorkflowTemplateGallery.jsx`（259 行）是真的
     （按 graph.nodes / graph.connections 画缩略图 + 铺开节点），而
     `CanvasTemplateMarketplace.jsx`（167 行，100 套模板）**点选只弹一句 toast「已应用模板 X」、不铺任何节点**
     —— 这是一颗**假按钮**（违反本项目「不许放假按钮」的铁律，见 §5 第 0 步）；
   · **模板增值收费 / 解锁**—— **没有**（模板卡上的"价格徽章"是展示，没有任何扣费路径；
     本项目钱的铁律：没有用户批准不许新增收费项）。
4. **推荐路线 = B（接线升级 + 工作流层补齐），不选 A（只修 bug）也不选 C（全面重构成 TapNow 式）**。理由与代价见 §5。

## 4. 判断：要不要"全面升级或重构"

**结论：不重构引擎，做一次"工作流层 + 接线"的升级。**

四条依据（都可核）：
1. **引擎不是短板**：自研与知渔同构；且我们已有缩放层/世界坐标/portal 弹层/多选/打组/绑定/图层/焦点编辑器
   这些 TapNow 与 liblib 也没有全做到的东西（见 `canvas-overall-inventory.md` 的能力清单）。
2. **能力也不缺**：节点 12 类、派生动作 20+、生成框 4 个、资产/作品集两个 tab、账务 hold-settle 底座、
   审批门（不确认不扣费）——这些都是竞品没有的**账务级**能力。
3. **缺的是"把能力串成产品"的那一层**：模板是**假的一半**（见 §1.3）、
   skill 子页面与画布**没有互通的契约**、节点级成本显示**只有应用节点有**。
4. **重构的代价与风险**：`index.jsx` 8102 行 / 429KB，且画布是**用户天天在用的**生产面
   （今天他就在用）。推倒重来 = 现有 21 个 canvas 模型 + 52 个端点 + 全部画布门禁的迁移，
   而收益（换引擎）在 §4.1 已被否掉。**不值得**。

## 5. 方案（三条路线 + 推荐）

### 路线 A —— 只修 bug，不碰结构
成本最低；但用户要的"工作流 + 模板增值"一条都不落实 ⇒ **不满足需求**。

### 路线 B（推荐）—— **画布 = 工作流生产地**（接线升级，分期落地）

**第 0 步（先做，也是"不许放假按钮"的整改）**：把两套模板**合成一套真的**。
`CanvasTemplateMarketplace` 的 100 套现在点选只弹 toast —— 要么让它**真的铺开**（把模板升级成
`WorkflowTemplateGallery` 那种 graph 结构），要么**摘掉入口**。**不许让它继续以"点了没反应"的样子挂着。**
（这条不需要拍板：它是既有铁律。）

**第 1 步 · 一份声明三处复用（这是"联动"的地基）**
现在 `src/skills/*.js` 已经是**唯一声明源**（字段/规格/工作台/适配页），子页面按它渲染。
把同一个声明再投影一次 → **画布应用节点**：
```
skill 声明（唯一真源）
   ├─ → 子页面工作台（已有，批 CA→CT 一直在对账）
   ├─ → 画布「应用节点」（节点 = 这条 skill 的输入 + 参数 + 预计积分 + 生成）
   └─ → 模板（= 若干应用节点 + 连接 + 参数预设 = 一条工作流）
```
**收益**：首页/子页面新加一条 skill，画布与模板**自动**多一个节点类型，不再出现今天这种
"首页入口搬走了、画布还挂着旧按钮"。

**第 2 步 · 双向通道（画布 ↔ 子页面）**
- 子页面 → 画布：「送到画布」入口（把当前 skill + 已填参数 + 已上传素材变成一个节点）；
- 画布 → 子页面：节点上「在完整工作台里编辑」（打开对应 skill 子页面，参数带过去）。
⚠️ 这条要与"一个页面只能有一个主入口"的既有纪律对齐，避免又造重复入口（历史上已被用户点过名）。

**第 3 步 · 模板与增值**
- 模板升级为**真图结构 + 参数预设 + 一键铺开**（复用 `workflowTemplates.js` + `WorkflowTemplateGallery`）；
- 模板的**收费/解锁**是**钱的事**：在我们给出定价方案、用户明确批准之前，
  **一律不接扣费、不显示价格承诺**（铁律）。

### 路线 C —— 全面重构成 TapNow 式（React Flow + chip 注入工作流）
收益：交互更"现代"（hero chip 注入、模板市场结构）。
代价：8102 行的画布页 + 52 个端点 + 全部门禁重写；且**丢掉我们独有的账务/审批/多选/图层能力**（要重做）。
⇒ **不推荐**（除非用户明确要"以重写换体验"）。

## 9. 入口形态：**用户登录态实拍之后**的结论（2026-09-27 晚，批 CW）

> 用户原话（逐字）：「知渔那边他的画布的页面首先就是一个全是工作流模板的样式。你需要进入到真正的画布的话，
> 你就点上面的那个**我的画布**那个就可以进入到真正的画布里面去。然后你也可以任意的在他这个画布页面上
> https://laoyu.quantv.com/canvas?tab=featured **点击任意一个工作流也可以创建进入画布里面**。
> 这就是我说的两种方式，你自己帮我考虑一下，到底怎么做会更好？」
>
> 采集方式：用户本人登录态的 Chromium（CDP 9333），**只读 + 只走免费/导航入口**，
> 未点任何「解锁 / 立即生成 / 支付」；邮箱与手机号在落盘前已脱敏。
> 证据：`docs/design/data/competitor-canvas-live.json` / `-live-2.json` / `-live-3.json` + `.playwright-shots/cw/*.png`。

### 9.1 两家实测：它们**根本是两种生意**

| | 知渔 / quantv | 刘颖AI / liuyingai |
|---|---|---|
| 层级 | **三层**：模板墙 `/canvas?tab=featured` → 我的画布 `/canvas?tab=projects`（列表）→ 编辑器 `/canvas/editor?id=…` | **两层**：功能页（主图&详情图 / 爆款复刻 / 无限画布 / 电商视频）+ 画布本身 |
| 模板墙是什么 | **商品货架**：60 张卡、19 个类目、**解锁方式四档**（全部模板 / 免费解锁 / 会员免费 / 积分解锁 / 已解锁）；卡上有 官方·上新 徽章、「**一键解锁同款**」、作者名（实拍里出现 **聚爆AI / 问晓 AI** 两个第三方作者）、真实计数（如 点赞 209 / 复刻 77）、以及「**会员享 5 折，折后 2.5 积分**」 | **没有官方货架**。画布右栏只有「**个人工作流 / 团队工作流 / 灵感库**」，空态写「暂无工作流，选中工作组后点「创建工作流」保存」；画布入口里有「**上传工作流**」（导入） |
| 工作流归谁 | **官方 + 第三方作者**（平台解锁收费） | **用户自己**（个人/团队），外加"上传导入" |
| 编辑器里能不能挑模板 | **不能**（编辑器只有 添加/选择/移动/便签/历史 + 节点） | 能，是**右栏抽屉**（工作流/灵感库），不是全屏墙 |
| 引擎 | 自研（`react-flow` 命中 **0**） | 该页 `react-flow` 命中 **0**、`canvas: 2`（自绘） |
| 节点形态（知渔编辑器实测） | **文本节点**（730 字四镜脚本，带「去生图片 / 去生视频 / 聚焦 / 展开」）+ **视频节点**（720×1280、00:00–00:15）；顶栏「已保存 / ✦ 0.00 / 导出 / 任务日志」 | 空状态：「双击屏幕 画布自由生成」+ 生成图片 / 生成视频 / 生成文本 / 上传素材 / 上传工作流 |

⇒ 一句话：**知渔是"卖工作流的商店"，刘颖AI 是"存工作流的工具"**。用户描述的两种方式，正好各对应一家。

### 9.2 结论：**选 B（直接进画布 + 画布内有集合页），但把 A 的三个东西保留**

**主入口 = 画布**（不做"必须先过模板墙"），三条理由（都基于我们自己的现状）：
1. 我们的用户是**带素材来干活**的（首页 → 子页面工作台 / 画布），动机是"把这张商品图做成套图/成片"，不是来逛商店；
   多一道墙 = 每次多一次点击，而我们的画布**已经能直接干活**（12 类节点 + 4 个生成框）。
2. 画布入口**已经散在多个地方**（首页两板块、子页面、作品集），再造一个"必须先过墙"的入口会与既有的
   「一个页面一个主入口 / 不要重复入口」纪律打架（这条纪律用户点名过多次）。
3. 知渔之所以墙在前，是因为**它的墙就是它的收入面**；我们把收入面放在画布内**一样卖得动**——
   点模板 = 在当前画布铺开，少一次"跳出去再跳回来"的上下文切换。

**要保留的 A 的三个东西**（用户点名的两个 + 实拍发现的一个）：
- **「新建空白画布」按钮**（用户原话里点名要的那个，货架顶部必须有）；
- **模板直达 URL**（形如 `/ec-canvas?tab=templates`）：可分享、可投放、可做 SEO，
  这样"先挑模板再干活"在**链接层面**依然成立；
- **卡片形态照知渔那一屏**（实拍里最值得抄的一屏）：类目 chip + **解锁方式四档筛选** +
  卡上「官方/上新」徽章 + **真实点赞/复刻计数** + 作者名 + 主按钮「一键铺开同款」。

**明确不抄两点**：
- 不抄"墙挡在画布前面"（理由见上）；
- 不抄"卡上直接写价格"这种**未落地的价格承诺**——定价必须用户批准后才上屏（钱的铁律）。
