## 怎么跑的

`.tmp/audit-skills.mjs`：把声明源里 **92 条技能**（50 图片 + 42 视频）逐条打开子页面，
在 `.media-workbench` 里收集全部可点控件（button / role=tab / role=checkbox / select），
**逐个点一遍**，用「点击前后的 DOM 签名」判断有没有反馈。签名 = aria 状态 + 正文长度与哈希
+ 控件数 + 全文档 class 哈希。

**零成本**：本机后端(3001)未启动，/api 全失败；并且显式排除所有计费按钮
（`.media-workbench-submit` / `-paid` / `-parse`，以及文案含 生成/解析/购买/订阅/积分 的）。

## ⚠️ 这个工具有三类**已验证的假阳性**（比漏报更危险的是它让人以为「全都验过了」）

| 类别 | 例子 | 为什么假 | 怎么确认的 |
|---|---|---|---|
| 弹 **portal** | 卖点框的「放大」 | 弹窗挂在 `.media-workbench` 外面 | 手工点：`.media-field-expand-modal` 真的出现（dialogs:1）→ **是好的** |
| 弹**原生文件对话框** | 上传卡片、视频的图片/视频/音频卡 | 系统对话框不进 DOM | 按「按钮里有没有 file input」排除 |
| 需要**真实用户手势** | 视频的「全屏」 | 全屏 API 拒绝非可信事件（eval 里的 click 不算） | 手工点：is-fullscreen=false、aria-pressed 仍是 false —— **但这是 API 的门槛，不是 bug**，真人点击时无法用这个工具证伪 |

另外两个工具自身的坑（都是我自己踩的，已修）：
- **等挂载**：懒加载 SPA 固定 sleep 会收到 0 个控件，35 个技能全报「控件 0」= 假绿 → 改成轮询等控件出现；
- **自证**：一个都没点到时必须**响亮地失败**（process.exit(2)），否则「共点 0 个控件 / 0 个无反馈」会被当成「全都没问题」。
