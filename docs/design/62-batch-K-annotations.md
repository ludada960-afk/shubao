## 一、原话（逐字，按主题拆）

### 1) 收费：要收，定价由我定

>   因为现在这些价格其实都是你来定的，你会比我更清楚这些策略应该怎么弄。」

### 2) 「代为撰写」要**整段抄明白**
> 「你确定你已经看明白他们的代为撰写是怎么做的了，对吧？你到底有没有搞明白我之前跟你说的原理呀？
>   就是我们去了解他这个代为撰写是具体怎么一回事，然后你要把**他代为撰写的这几步里面具体是怎么做的，
>   整体都给他抄过来**，就是**包括他那些按钮是怎么做的一个 UI 设计**，还有**他们的这些详细的步骤是哪些**？
>   这些你全部要抄明白。」

### 3) 图片侧 = 预览；两边**本质是同一个东西**
> 「然后**图片生成这边是没有这个代为撰写的，这个分析方案的步骤是在那个预览的那个地方**……
>   这个**预览实际上就跟这个代为撰写是一样的东西**，只是在图片生成这边，你需要让用户先在工作台里面去
>   **配置好各种各样的设置之后，进行预览**，预览的话就会去**给到这个代为撰写的这些步骤**。
>   它实际上就是**一个设计方案**。然后再进行生成。」
> 「视频生成这边的话，代为撰写，它就是代为撰写。它的原理就是**帮你把这个视频的脚本给完善起来**。
>   他们这两套东西**本质上都是一个设计方案**的一个东西，只是在它里面它**有不同的入口**，
>   然后他所处的位置不同，只是这样而已。」

**我的理解（要落成的形态）**：
```
        入口不同                     同一条流水线                   出口
图片侧：配置面板里的「预览」 ┐                                  ┌→ 生成图片
                            ├→ ①素材理解(可纠偏) → ②方向偏好 → ③方案预览(可改) ┤
视频侧：提示词框旁的「代为撰写」┘                                  └→ 生成视频
```

> 「视频生成这一块，我对你的要求就是**要跟图片生成这边是一样的**。之前是怎么执行的，你现在就怎么执行。

## 二、我这一轮就定下来的（用户把定价权给了我）

### 「代为撰写 / 预览方案」的价格：**0.5 积分 / 次**
理由（三条，都是站内已有的事实）：
1. **与他们同档但略低**：知渔是 `0.60`（0.10/张素材分析 + 0.50/次拆解 + 0.10/条脚本生成）；
   我们取 0.5，比它低一档，用户在做"生成前的一步"时更容易点。
2. **与我们自己的付费动作同一支**：站内现有付费动作都是 0.2 那一档
   （一键解析 0.2 · AI润色 0.2 · AI推荐风格分析 0.2）。方案预览**比它们重**（要读全部素材 + 出整份方案），
   但不该高到 1.00（那是出一张正片的价）——**0.5 落在两者中间**。
3. **可预期**：一次一个数（不是"按张 × 按步"叠出来的），用户点之前就知道花多少。
   ⚠️ 素材数量**不**额外累加；失败不扣。

**建议的计费口径**（落地时按这个写进 billing）：
- SKU：`ec_plan_preview`，units 500，points 0.5
- 计费时机：**调用 LLM 之前先 quote、用户确认后扣**（与站内其它付费动作一致）
- 失败：不扣（沿用站内"失败不扣对应项"的口径）

## 三、执行顺序（我接下来按这个顺序做，不再发散）
1. **图片侧「预览」升级成「方案预览」三步**（= 把代为撰写的三步整段抄过来，入口留在配置面板）：
   ①素材理解（**可编辑纠偏**）→ ②方向/偏好（照他们三个维度的真实档位结构）→ ③方案预览（可改、确认后应用）→ 生成。
2. **视频侧「代为撰写」**：同一条流水线，入口在提示词输入框旁（文案可以不一样）。
3. **视频侧所有 skill 子页面**：按"图片侧的同一套标准"重做，工作台 1:1 抄，
   右边案例/历史**先留结构、内容等用户线上跑出来的真实案例**；封面先不做。
4. **图片侧子页面**回到同一套规格（60 号文档里的逐项）——用户明说"抄得很不到位"。

## 四、验收线（写在最前面，做完逐条自查）
- [ ] 每一个可点的东西都**真点过**（点击/打勾/下拉/切子按钮），每一步的**反馈**都记录下来；
- [ ] 下拉展开后的**每一个部分**、切换子按钮后的**每一个形态**都有对应实现；
- [ ] 布局/尺寸/间距/字体/按钮/选项 = 竞品数值（文案可不同，**规范必须一致**）；
- [ ] 功能逻辑打通：工作台怎么搭出这条 skill 的能力，背后实现要说得通；
- [ ] 零 bug（全量测试 + e2e + 线上复核）。
