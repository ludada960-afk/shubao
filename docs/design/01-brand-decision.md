## 0. 结论先行（TL;DR）

| 项 | 结论 |
|---|---|
| **病根** | 全站有**两套互斥的主色身份**：V2 声明「近黑极简，**无彩色主色**」(\`--accent: #0C0A09\`)，但代码里紫色被用了 **215 处**，且**画布侧(116) 比首页(99) 还多** |
| **推翻一个假设** | 「紫 = 品牌色」**不成立**。实测品牌资产（LOGO/吉祥物）**主色是红色 \`#FB5358\`**，占用 62.5% 像素；**全部资产中紫色像素仅 4.55%** |
| **裁定（D1）** | **交互主色 = 品牌紫 `--sb-brand-600` `#7C3AED`**；近黑**降级为中性强调**；**不直接改 V2 `--accent` 指向** |
| **裁定（D1-补）** | **品牌红 `#FB5358` = 「品牌标识色」**，**只用于品牌时刻**（logo / 吉祥物 / hero / 空态插画 / 营销物料），**不接管交互主色** |
| **保留的可逆性** | 若日后改以品牌红为交互主色，**只需替换 9 个 `--sb-brand-*` 值**（`50/200/400/500/600/700` + `ring` + `ink`），其余规范、组件、状态表**全部不动** → **可逆成本是分钟级** |
| **必须治的问题** | 「格格不入」的技术原因是**暖底(`#F5EFE4`, ~35°) 配冷紫(~262°)**。**解法是限定紫的使用面积与位置**（§2A 穷举清单），**不是换色** |
| **风险** | 改 `--accent` 指向 = 一次性影响全站所有按钮/链接/选中态（实测被引用 **56 处**）。**D1 明确不这么做** |

### 0.1 D1 裁定全文（三条理由，按权重）

> 摘自 `40-decisions.md` D1 补充裁定，**原文引用不改写**：

| # | 理由 | 说明 |
|---|---|---|
| **1** | **语义冲突成本高于收益** | 红已是全站「危险/删除/折扣」语义色；把「生成」这类主 CTA 改成实底大红，会与删除/报错**抢注意力**。行业先例（YouTube/Pinterest/Adobe）能用红做品牌，是因为它们**没有把红同时当危险色用在同一屏** |
| **2** | **用户从未抱怨紫色** | 用户抱怨的是「黑白极简、没有主次、没有状态反馈、格格不入」。紫是**已安装的既成事实**（215 处），把它推倒重来属于**未被要求的重大改动**，风险与工期都不划算 |
| **3** | **hue 之争是低杠杆问题** | 规范自己的权重表说**品牌色只占设计感 5%**（表面分层 40% / 排版 25% / elevation 20% / 状态 10%）。真正让界面变好看的是**表面分层与状态** |

**因此**：
- **交互主色** = 品牌紫 `--sb-brand-600`（D1）—— 用于主 CTA / 选中 / focus / 激活图标 / 关键数字
- **品牌标识色** = 品牌红 `#FB5358`（D1-补）—— **只用于品牌时刻**：logo / 吉祥物 / hero / 空态插画 / 营销物料
- **近黑** `#0C0A09` —— 降级为**中性强调**，用于正文/标题、反色面、图标描边、中性强按钮
- **禁止**：再新增任何未经 token 定义的紫色；品牌渐变（`--sb-brand-gradient` / `-gradient-3`）**只用于品牌时刻，禁止用于功能按钮**

> ✅ **我的实测发现被采纳为「必须治的问题」**，但**解法是限定面积与位置，不是换色**。
> 详见 §2A 穷举清单与 §2B 表面分层。

## 1. 证据：两套身份的事实核查

### 1.1 V2 token 的自我声明（你说的没错）

| 位置 | 原文 | 含义 |
|---|---|---|
| \`design-tokens.css:1\` | \`薯包AI Design Tokens V2 — 暖白轻奢\` | 基调 = 暖白 |
| \`design-tokens.css:2\` | \`对标 lingtuai.top 暖白米色 + 近黑极简 + 超圆角\` | **近黑极简**是明写的设计意图 |
| \`design-tokens.css:12\` | \`/* ── 强调色（近黑极简，无彩色主色）── */\` | **"无彩色主色"**——这是全站最重要的一句注释 |
| \`design-tokens.css:13\` | \`--accent: #0C0A09;  /* 主强调色(近黑) */\` | 主色 = 近黑 |

**推论（已验证）**：组件里写的 \`var(--accent, #7c3aed)\` —— **兜底值 \`#7c3aed\` 永不生效**，因为 \`--accent\` 已在 \`:root\` 定义为 \`#0C0A09\`。

### 1.2 但紫色是事实上的第二主色

实测紫色（\`#7c3aed\` / \`#8b5cf6\` / \`rgb(124,58,237)\` / \`rgb(139,92,246)\`）出现位置：

| 区域 | 命中次数 | 典型文件 |
|---|---|---|
| **画布 / 工作台** | **116** | \`EcCanvas.css\`(28)、\`index.jsx\`(21)、\`canvas-library.css\`(23)、\`CanvasWorkflowNodes.module.css\`(16) |
| **首页** | **99** | \`EcMode.jsx\`(15)、\`DesignDirection.jsx\`(10)、\`crossModeProductProfile.css\`(16)、\`EcProfileRail.css\`(16) |
| **其他** | **42** | \`app-shell.css\`(8)、\`PricingModal.jsx\`、\`Toast.jsx\` |

> **注意**：画布侧紫色**比首页还多**。所以不是「首页近黑、画布紫」的简单二分，而是**紫色已经渗透全站**，只是首页的**结构化组件**（按钮/选中态）被 \`--accent\` 拉住用了近黑，而画布侧直接硬编码了紫。

### 1.3 ⚠️ 决定性发现：品牌资产里**没有紫色**

我用 Node 直接解码 PNG 像素、统计主色分布（无第三方依赖）：

**\`public/images/LOGO.png\`（457×457，= appicon \`cropped.png\`）**

| 色值 | 占比 |
|---|---|
| **\`#F04048\` 红** | **53.3%** |
| **\`#F84048\` 红** | **19.1%** |
| \`#78A840\` 绿 | 5.8% |
| \`#101010\` 近黑（描边） | 3.0% |

**吉祥物 \`准备好了吗？.png\` 精确采样（62,543 px 红色簇加权平均）**：

\`\`\`
主色 = #FB5358    rgb(254, 82, 88)
\`\`\`

**全资产紫色检测**：扫描 \`public/images/\` 全部 PNG，紫色像素（\`B>G+20\` 且高饱和）**仅占 4.55%**，且只出现在 3 张图（\`cropped_10/19/7\`）——那是**生成的电商样图**，不是品牌资产。

> ### 🚨 结论
> **薯包的品牌色是红色 \`#FB5358\`（番茄红），不是紫色。**
> 紫色是一个**从灵图/竞品抄过来的、没有任何品牌资产支撑的"外来色"**，却已经占据了 215 处代码。

### 2.1 三方案对比（存档）

| E 电商行业适配 | ✅ 番茄红在电商里强势、喜庆、转化导向 | ⚠️ 通用 SaaS 感 | ⚠️ 过冷 |

### 2.2 ❌ 已否决：D1-A（品牌红接管交互主色）

> **D1 裁定否决了本方案**，理由见 §0.1（语义冲突 / 用户未抱怨紫 / hue 是低杠杆）。
> **但保留其可逆通道**：若日后改红，只需换 9 个 `--sb-brand-*` 值。
> 以下三条「支持理由」作为存档保留，**不代表最终决策**。

**理由 1 — 有唯一真源。** 品牌资产是**不可争辩的事实**：LOGO 和全部吉祥物都是番茄红。设计系统必须从品牌资产推导，而不是从竞品截屏抄。
> 实测：\`#FB5358\` 占吉祥物 62.5% 像素；紫色占全部资产 4.55% 且只出现在 AI 生成的样图里。

**理由 2 — 与暖米白底同属暖色域。** \`--bg: #F5EFE4\` 是暖米白（色相 ~35°），品牌红 \`#FB5358\`（色相 ~358°）与它同属暖侧；而紫 \`#7C3AED\`（色相 ~262°）是冷色，这正是「格格不入」的技术原因。

**理由 3 — 电商语境正确。** 番茄红在中国电商视觉里是「促销 / 热卖 / 主推」的强势色，与产品定位一致。

### 2.3 D1-A 的致命难题：红 = 危险色冲突（**否决的决定性理由**）

**这是本方案唯一的真实风险**，必须在规范里正面解决：

| 冲突 | 解法 |
|---|---|
| 品牌红要当主 CTA，但红也是「删除 / 错误」 | **两者用不同明度与不同用法**：<br>• **品牌红（动作）** 底 \`#E8544B\`，**实底填充**，用于主 CTA<br>• **危险红（语义）** 文字 \`#D0443C\` + 浅底 \`#FEF2F0\`，**永远不用实底大红** |
| 用户混淆 | **危险动作用「描边 + 图标 + 文字」三重标识**，不用填充；品牌动作用填充。**填充 = 邀请，描边 = 警告** |

> **行业先例**：YouTube、Pinterest、Adobe 都用红色品牌主色 + 独立的危险语义色，靠**填充 vs 描边**区分。这不是新问题，有成熟解法。

### 2.4 ✅ 裁定方案：D1-B（紫）——已采纳

> **D1 采纳的就是本方案**。以下「需要注意」事项仍然有效。

若你决定沿用紫（例如认为「紫已是既成事实、改动成本太高」），那么：
1. 必须**改品牌资产**（把 LOGO/吉祥物改成紫系）——否则永远存在「logo 红、UI 紫」的分裂；
2. 或**明确接受**「品牌红是 IP 形象色、紫色是 UI 交互色」的双轨制，并在规范里写明各自边界。

**但请注意**：用户抱怨的核心是「**黑白极简，没有符合视觉语言**」。选 D1-C（近黑）**不解决这个问题**，只会把现状正当化。

| \`--duration-*\` | \`0.12/0.2/0.35/0.5s\` | **改值** | \`100/150/200/300/400ms\` | V2 缺 150ms，且 0.5s 过长 |
| \`--nav-height\` | \`72px\`（窄屏 56） | 保留 | \`--sb-nav-h\` | ✅ |

### 3.2 废弃清单

| 废弃项 | 理由 | 替代 |
|---|---|---|
| \`--text-ghost\` / \`--text-invisible\` | 语义错位（文字 token 当分割线用） | \`--sb-border-subtle\` |
| \`.hero-gradient-text\` | **渐变文字**被 impeccable 检测器判为反模式 | 字重/字号强调 |
| \`--radius-lg: 30px\` / \`--radius-xl: 40px\` | 超圆角，实测过大 | \`20px\` 上限 |
| \`var(--accent, #7c3aed)\` 式兜底 | 兜底值永不生效，是**误导性代码** | 直接引用 \`--sb-brand\` |

## 4. ⚠️ 风险清单：改 \`--accent\` 指向的影响面

> **这是整个迁移最危险的一步。** 改一行，全站所有用 \`--accent\` 的地方同时变色。

### 4.1 受影响面盘点（实测）

\`--accent\` 在代码中被引用 **56 次**（\`var(--accent\` 全站统计，含 \`--accent-hover\`/\`-bg\`/\`-muted\`）。

| 受影响组件 | 表现 | 风险 |
|---|---|---|
| **所有 primary 按钮**（\`.btn-primary\`、顶栏「套餐」、生成 CTA） | 近黑 → 品牌红 | 高（主视觉全变） |
| **导航项选中态** | 近黑 → 品牌红 | 中 |
| **Logo 文字** \`color: var(--accent)\` | 近黑 → 红 | **高**（品牌字标变色） |
| **标题** \`--accent\` 用于 h1/h2 | 近黑 → 红 | **极高**（大面积文字变色，可读性骤降） |
| 积分数字、\`::selection\`、scrollbar | 近黑 → 红 | 中 |

### 4.2 分批落地策略（**四步，每步可独立验收**）

\`\`\`
Step 1（零风险）  新增 design-tokens-v3.css，只定义 --sb-*，不碰 V2
                 ✅ 验收：全站渲染与今天逐像素一致
                     ↓
Step 2（低风险）  新增 .sb-* 组件类，逐组件替换内联样式
                 每个组件改完单独验收，老组件保留
                     ↓
Step 3（中风险）  加「兼容别名层」，把语义清晰的老 token 指向新语义：
                 --red → var(--sb-brand)        ← 同值，零视觉变化
                 --bg-hover → var(--sb-hover-bg)
                 ⚠️ 这步看起来"没变化"，但把控制权交给了 V3
                     ↓
Step 4（高风险）  最后一步才改 --accent 指向
                 ⚠️ 必须：①先全站截图基线 ②改 ③逐页对比 ④准备一键回滚
\`\`\`

### 4.3 Step 4 的**安全前置**（缺一不可）

| # | 前置条件 | 为什么 |
|---|---|---|
| 1 | **先把"标题用 --accent"的地方改成用 \`--sb-ink-1\`** | 标题变色是最刺眼的回归。标题本就不该用主色 |
| 2 | **先把 Logo 文字固定为 \`--sb-ink-1\` 或品牌色硬编码** | Logo 变色影响品牌识别 |
| 3 | **建立全站截图基线**（首页 / 画布 / 作品 / 定价 各 1440+390） | 无基线无法判断回归 |
| 4 | **准备回滚**：改前 \`git stash\` 或独立分支 | 一改全崩时能 30 秒恢复 |

> **强烈建议**：Step 4 单独开一个分支 + 单独一次 commit，**绝不与其他改动混在一起**。

## 5. 近黑的降级规则（**D1 下的定位**）

近黑 \`#0C0A09\` **不是废弃，是降级**——从「主色」降为「中性强调」。

### ✅ 近黑保留使用的场合（穷举）

| # | 场合 | 取值 | 为什么必须是近黑 |
|---|---|---|---|
| N1 | **正文 / 标题文字** | \`--sb-ink-1\` \`#1A1614\` | 文字用纯中性是排版铁律，彩色标题是不可读的 |
| N2 | **深色反色面**（深色 chip、黑底 CTA） | \`--sb-l4-inverse\` \`#0C0A09\` | 「反色」需要真正的深色，红色反色面会像警告 |
| N3 | **图标描边 / 近黑线稿** | \`#0C0A09\` | 吉祥物描边就是近黑（实测 LOGO 中占 3.0%） |
| N4 | **中性强按钮**（次要 CTA，如「取消」的加强版） | \`#0C0A09\` | 当同一屏已有品牌红主 CTA 时，次要动作可用近黑实底形成对比 |

### ❌ 近黑禁止使用的场合

| 禁止 | 理由 |
|---|---|
| **主 CTA** | 近黑主 CTA 正是"黑白极简"的来源，是用户抱怨的对象 |
| **选中态** | 选中是"当前项"信号，应是品牌色（这是 §2A A2 的规定） |
| **大面积背景** | 近黑大面积 = 冷、重、与暖米白基调断裂 |

### 6.1 现状：窄屏只改了 8 个 token，且无依据

| 行 | token | 桌面值 | 窄屏值 | 缩放比 | 判定 |
|---|---|---|---|---|---|
| 333 | \`--text-4xl\` | 42px | 30px | 0.71 | ✅ 合理 |
| 334 | \`--text-3xl\` | 30px | 22px | 0.73 | ✅ |
| 335 | \`--text-2xl\` | 24px | 18px | 0.75 | ✅ |
| 336 | \`--text-hero\` | 62px | 32px | **0.52** | ⚠️ 过陡 |
| 337 | \`--nav-height\` | 72px | 56px | 0.78 | ✅ 触控友好 |
| 338 | \`--radius-lg\` | 30px | 24px | 0.80 | ✅ |
| 339 | \`--radius-xl\` | 40px | 28px | 0.70 | ✅ |
| 340 | \`--max-width-content\` | 1240px | 100% | — | ✅ |

**问题**：① 只调了大字号，**控件高度、间距、面板宽度都没调**；② \`--text-hero\` 从 62→32 跨度过大；③ 断点只有 768 一个，与现代手机（390）不匹配。

### 6.4 三条响应式铁律

| # | 规则 | 理由 |
|---|---|---|
| **R1** | **字号 ≤15px 不随断点缩小** | 12px 已是可读下限，再缩违反 WCAG |
| **R2** | **控件高度不随断点缩小** | 触控目标 44px 是硬下限（WCAG 2.5.5 AAA） |
| **R3** | **间距阶梯不随断点变** | 4pt 栅格是设计系统的骨架，变了就失去节奏感。只有**页面级 gutter** 可调 |

| 项 | 现状 | 规范 |
|---|---|---|
| **面板形态** | 桌面浮层，手机上也浮层（\`EcMode.jsx\`） | 手机改为**底部抽屉**（\`border-radius: 24px 24px 0 0\`） |

| **hover 态** | 全端用 hover | 触屏无 hover，**必须有 \`:active\` 反馈替代** |

## 7. 设计感来自结构，不来自上色（**硬要求**）

> **用户真实诉求是「有设计感」，不是「多上色」。上色 ≠ 好看。**

### 7.1 高级感的四个来源（按权重）

| # | 来源 | 具体做法 | 占比 |
|---|---|---|---|
| **1** | **表面分层** | L0→L1→L2-/L3 的色阶递进，每级可辨（≥1.06:1） | **40%** |
| **2** | **elevation** | 阴影层数编码高度（Vercel Geist 做法），静态元素默认无阴影 | **20%** |
| **3** | **排版主次** | 字号/字重/颜色三轴建立层级，而非靠颜色 | **25%** |
| **4** | **状态差异** | hover/selected/active/focus 四通道分离 | **15%** |
| **5** | 品牌色点缀 | 只占 ≤10% 面积 | **5%** |

> **品牌色是 5%，不是 50%。** 如果把品牌色当主角，画面会变成"到处是红的"——那是廉价感，不是设计感。

### 7.2 反模式（**明确禁止**）

| ❌ 反模式 | 为什么是反模式 |
|---|---|
| **给每个分组都加彩色标题** | 颜色通胀，层级消失 |
| **大面积品牌色背景** | 品牌色是「注意力货币」，大面积 = 通货膨胀 |
| **用颜色代替留白做分组** | 正确做法是留白 + 分组标题（Figma 属性面板是范本） |
| **彩虹渐变** | 全站最多 2 处（hero 标题 + 主 CTA） |
| **给静态元素加阴影"显高级"** | 阴影是**状态响应**，不是装饰。静态默认 \`--sb-shadow-0/1\` |

### 7.3 验收判据（可执行）

\`\`\`
① 截图转灰度后，层级是否依然清晰？        → 是 = 靠结构，✅
② 品牌色像素占比是否 ≤10%？               → 是 = 稀缺，✅
③ 把彩色全部替换为中性后，界面是否依然好用？ → 是 = 结构扎实，✅
   （如果去掉颜色就"散架了"，说明层级是靠颜色硬撑的）
\`\`\`

**第 ③ 条是最严格的检验**：D1-A 方案落地后，把品牌红临时换成灰色截图，界面应该**依然有清晰的主次和层级**——只是少了品牌情绪。如果变糊，说明 surface/elevation 体系还没做够。
