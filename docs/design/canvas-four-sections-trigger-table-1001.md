## 采集方法（别照抄错的那版）

每个板块：**左侧「+」→ 对应入口 → 创建前后 diff 节点 id → 选中新建的那个**。
⚠️ 第一版用「第一个 `[data-canvas-node-id]`」去选，四次都选中同一个商品原图节点，
量了四遍同一个面板 —— **探针失败，不是结论**。

⚠️ 量字号必须直接取 `<small>`（标题）和 `<strong>`（值）。
用 `querySelector('span')` 会取到**第一个 span = 图标容器**，量出来的是它的继承字号
（本轮据此得出过「标题 16px/400」这种假异常，第四次栽在同一类坑上）。

## 结论：只有两处不一致

### ① 视频侧的触发器比另外三个矮 5.44px、行距收成 0

根因是一条**专属覆盖**（`EcCanvas.css`）：

```css
.ec-canvas-video-controls > .ec-canvas-parameter-item > .ec-canvas-config-trigger {
  height: var(--cvl-control-compact, 32px);
  padding: 0 6px;
  gap: 4px;
}
.ec-canvas-video-controls > .ec-canvas-parameter-item > .ec-canvas-config-trigger .ec-canvas-config-trigger-copy { gap: 0; }
```

特异度 (0,3,1)，压过了其余三个板块共用的那条 ⇒ 实际上是**「三个一套 + 视频单独一套」**，
而不是四边各写各的。

**⚠️ 为什么本轮没有直接删它**：`test/canvas-control-slot-width-0917` 明确要求视频侧是 32px，
理由写在它自己的注释里：「视频侧那一档更矮：32px，**与同行控件同基线**」。
视频那一行除两颗触发器外还有模式切换（智能成片 / 首尾帧 / 爆款重构）等控件。
**要统一就得整行一起量**，不能在没看过那一行渲染的情况下只删这一条 ——
拿一个验证不了的改动去换「看起来统一」，比留着一个有据可查的高度差更糟。
（删掉后实测视频触发器确实变成 27.2，但同行其它控件的基线没有一起量。）

**下一步该做的**：把视频那一行**所有**控件的高度一起量出来，确认是「触发器该跟同行
统一成 27.2」还是「同行该跟触发器统一成 32px」，再动。

### ② 套图侧「套图方案」「商品规格」的值字号是 11/700，同面板的「技能」「生成配置」是 12/700

同一个面板内部就不一致。根因没查到底 —— `EcCanvas.css` 里 `.ec-canvas-suite-*`
的覆盖规则叠了十几层（`> button strong` / `> .ec-canvas-config-trigger` / slot 宽度等），
需要逐条追。

## 已经是统一的（不用再动）

- 面板宽 435.2 / 圆角 12 / `max-height` 800 / `overflow-y` hidden —— **四侧逐值相同**
- 触发器标题 11/600、值 12/700（比标题重，符合仓库 `panelVisualLanguage` 的主次阶梯）
- 图标 12.24

所以用户说的「没有做同等级的规划」，在这四个板块的**模型选择面板**上其实只剩上面两处；
如果他看到的是「四种长相」，问题更可能出在**面板内部其它区域**（素材区、参数行、底部按钮行），
那需要另出一张表。
