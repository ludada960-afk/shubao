# 41 · 尺度阶梯与「归并」政策（间距 / 字号 / 圆角）

> 状态：**已拍板**（2026-09-20）· 分支 `codex/ecommerce-stability`
> 相关决策：**D6**（圆角 4 档 + 10px 退役）、**D15**（迁移只能逐值相等）、**D14**（像素 diff 必须分区段）
> 工具：`node scripts/space-migration-audit.mjs`（三族属性的等价性审计，带真值自检）

## 0. 为什么需要这份文档（一次真实事故）

「第九批：gap 非阶梯 56% → 0%」的指令里写的是**必须给出像素级 diff 证明观感零变化**，
实际执行成了**把非阶梯值硬套到最近阶梯**。审计脚本一次抓出 **93 处**：

| 族 | 处数 | 典型 |
|---|---|---|
| 间距 | 84 | `gap: 12px → --sb-space-5`（20px，**+8px**）、`4px → 8px`（+4px）、`6px → 8px` ×7 |
| 字号 | 5 | `font-size: 12px → --sb-text-xs`（11px）、`11.5/12.5/10.5px → 相邻档` |
| 圆角 | 4 | `26px → --sb-radius-2xl`（20px，**-6px**）、`16px → 20px`（+4px） |

**这类错误没有任何测试能抓到**（全站没有断言锁间距/字号），`npm test` 全绿的同时观感已经在变。
它唯一能被发现的方式就是**等价性审计 + 像素 diff**。

## 1. 三段阶梯（唯一真值）

### 1.1 间距 `--sb-space-*` —— 4px 基数 + **三个半档**

| token | 值 | 用途 |
|---|---|---|
| `--sb-space-0` | 0 | 归零 |
| `--sb-space-0-5` | **2px** | 图标 ↔ 文字的光学间距 / 徽标内边距 |
| `--sb-space-1` | 4px | 紧凑簇内的最小缝 |
| `--sb-space-1-5` | **6px** | 图标与文字并排、chip 内边距 |
| `--sb-space-2` | 8px | 控件之间 |
| `--sb-space-2-5` | **10px** | 列表项内边距 / 中等密度 |
| `--sb-space-3` | 12px | **现状锚点：最高频 gap** |
| `--sb-space-4` | 16px | 卡片内边距 |
| `--sb-space-5` | 20px | 分组之间 |
| `--sb-space-6` | 24px | 区块之间 |
| `--sb-space-8` | 32px | 大区块 |
| `--sb-space-10` | 40px | 页面段落 |
| `--sb-space-12` | 48px | 章节 |
| `--sb-space-16` | 64px | Hero / 落地页 |

**三个半档为什么补**（实测全仓非阶梯 gap **645 处 / 14 个值**）：

```
6px×154   5px×104   7px×102   10px×79   3px×59   2px×52   9px×34   14px×31   18px×11 …
```

排在最前的 **6 / 2 / 10** 恰好是**行业标准半档** —— Tailwind 的 `1.5 / 0.5 / 2.5` 同为 **6 / 2 / 10px**。
也就是说：不是我们的设计乱，是**主阶梯在小尺寸段太粗**（4px 起步，图标旁只能靠手调）。
补上这三档是**零观感变更**（只是给已有值一个名字），却让 **285 处**可以被合法收编。

### 1.2 字号 `--sb-text-*` —— 10 档（实测 1474 处声明 / **33 个不同值**）

| token | 值 | 用途 |
|---|---|---|
| `--sb-text-2xs` | 10px | 角标 / 极度次要（非正文，对比度须自检）|
| `--sb-text-xs` | 11px | 元信息 / 说明文字 |
| `--sb-text-sm` | 12px | UI 标签 / 控件文字（最高频）|
| `--sb-text-md` | 13px | 密排面板正文 / 小按钮 |
| `--sb-text-base` | **14px** | **【标准正文】**（2026-09-20 D17 新增）|
| `--sb-text-lg` | 15px | ⚠️ **夹心档，待退役**（D17）|
| `--sb-text-xl` | 18px | 小节标题 |
| `--sb-text-2xl` | 24px | 页面标题 |
| `--sb-text-3xl` | 32px | 区块标题 |
| `--sb-text-4xl` | 48px | Hero（桌面）|

#### 为什么补 14px、为什么 15px 反而要退役（D17）

实测：`11px×336  10px×233  12px×227  13px×163  9px×104  14px×78  11.5px×55  15px×49  12.5px×42  10.5px×34  16px×29 …`

- **14px 是行业标准 UI 正文字号**（Tailwind `text-sm` = 14px），全仓已经手写了 78 处 ——
  它缺位才逼得各处写死。**补它是零观感变更**（只是给已有值一个名字）。
- **15px 是「夹心档」**：它夹在 14 与 16 之间，没有任何设计依据能说明「什么场景该用 15 而不是 14 或 16」。
  它的存在本身就是碎片化的产物 → **按场景归入 14 或 16**（49 处，属有意变更，走 §3）。
- **半像素值**（`11.5×55`、`12.5×42`、`10.5×34`、`13.5×8`）是历史 rem 换算残留（`0.875rem` 之类），
  一律归到最近合法档 —— 同样属有意变更，走 §3。
- **16px×29** 暂**不补档**：它可由 `--sb-text-lg`（15px）退役后承接入位，先看归并结果再定，
  避免「一次补两个档位」把阶梯撑大。

### 1.3 圆角 `--sb-radius-*`（依 D6）

| token | 值 | 用途 |
|---|---|---|
| `--sb-radius-xs` | 4px | 微型徽标 / 进度条 |
| `--sb-radius-sm` | 6px | 小图标容器 / 复选格 |
| `--sb-radius-md` | 8px | **【默认】** 输入框 / 小 chip / 菜单项 |
| `--sb-radius-lg` | 12px | 选项卡 / 中按钮 / 内层卡片 |
| `--sb-radius-xl` | 16px | 卡片 / 面板内分组 |
| `--sb-radius-2xl` | 20px | **【现状锚点】** 浮层面板 |
| `--sb-radius-3xl` | 24px | 大容器 |
| `--sb-radius-pill` | 9999px | 胶囊：主 CTA / 平台 chip / 导航项 |

D6 明文**授权**两处归并（有意变更，审计脚本放行）：
`10px → 8 或 12`（**按场景**，不是就近）、`7px → 6 或 8`。其余仍须逐值相等。

#### 1.3.1 「按场景」到底怎么判（**实操规则**，2026-09-20 补）

实测分布（全仓 `border-radius`，已剔除 `50%` 正圆 137 处）：

```
8px×234   10px×125   6px×125   7px×121   9px×88   999px×82   12px×61   14px×50
5px×48    4px×36     0px×28    16px×27   11px×24  2px×22     3px×15    20px×13
99px×12   18px×8     13px×8    17px×4    26px×3
```

**阶梯外约 530 处**。归并目标只有一个：D6 的 `{6, 8, 12, 16, 20, 24}` + 微件 `4`。

| 元素角色 | 目标档 | 判据（看它是什么，不看它原来几 px）|
|---|---|---|
| 微型徽标 / 复选格 / 进度条 / 小圆点容器 | **6**（`--sb-radius-sm`）| 尺寸 ≤ 24px 的小方/小圆 |
| 输入框 / 按钮 / 菜单项 / 小 chip / 工具条 | **8**（`--sb-radius-md`）| **默认档** —— 拿不准就选它 |
| 选项卡 / 中按钮 / 内层卡片 / 分组容器 | **12**（`--sb-radius-lg`）| 里面有 8px 级控件的容器 |
| 卡片 / 面板内分组 | **16**（`--sb-radius-xl`）| 独立成块的卡片 |
| 浮层面板 / 弹窗主体 | **20**（`--sb-radius-2xl`）| 浮在内容之上、有阴影的 |
| 大容器 / 全屏抽屉 | **24**（`--sb-radius-3xl`）| 占大半屏的 |
| 胶囊（主 CTA / 平台 chip / 导航项）| **9999**（`--sb-radius-pill`）| 视觉上是胶囊的；`99px`/`999px` 一并归到它 |
| 正圆（头像 / 圆点 / 圆形图标底）| **50%** | 不是档位，保留写法 |

**归并数值对照**（就近 → 落档，再按上表与角色校正）：

| 原值 | 就近 | 常见落档 |
|---|---|---|
| 2 / 3 / 4 / 5 | 4 或 6 | 4（微件）或 6 |
| **7** | 6 或 8 | **6**（微件）/ **8**（控件）—— D6 明文授权 |
| **9 / 10 / 11** | 8 或 12 | **8**（控件）/ **12**（中容器）—— 10px 由 D6 明文授权 |
| 13 / 14 | 12 或 16 | **12**（中容器）/ **16**（卡片）|
| 17 / 18 | 16 或 20 | **16**（卡片）|
| 26 | 24 | **24** |

**纪律**：
1. 这是**有意观感变更**（Δ≤2px），必须走 §3（分区段像素 diff + 值清单 + 提交说明）；
2. **不许按「数值最近」机械做** —— 上表的「角色」列才是判据；
3. 一次只做一类角色（先 10px→8/12 的控件与中容器，再 7/9px），每类跑一次 build + `design-audit`；
4. 圆的元素（`50%`）一律不动 —— 那是形状，不是圆角档位。

## 2. 非阶梯值的三类处置（**先分类，再动手**）

| 类 | 判据 | 处置 | 需要像素 diff？ |
|---|---|---|---|
| **A. 补档** | 值属行业标准步进（2/6/10），或多次出现且是真实设计意图 | 加进阶梯 → 再做**等值**迁移 | **不需要**（零观感变更）|
| **B. 按场景归并** | 1px 网格上的手调噪声（1/3/5/7/9/11/13）、阶梯外的大值（14/18/22/26）| 归到最近合法档，**逐场景判断** | **必须**（分区段 d=0 除该元素）|
| **C. 保留** | 业务内容数据（封面比例/渐变）、第三方品牌色、JS 拼接值、局部变量 | 保持字面量 + 就地注释 | 不需要 |

**判 A 还是 B 的分界线**：这个值是不是「另一个尺度」？
6px 是（半个 12），5px 不是（它只是 6 被手改了一下）。

## 3. 归并（B 类）的执行纪律

1. **一次只做一个场景**，不许批量套用同一个映射；
2. 每处必须能回答：「归并后这个元素与邻居的关系**更好**还是**更差**？」答不上来就不要动；
3. 提交必须附 **D14 分区段像素 diff**（被改动元素区域之外 必须 `d=0`）；
4. 有意的观感变更**单独列出**并写依据，不许混在「零变化」的报告里；
5. 优先顺序按实测频次：`5px×104` → `7px×102` → `3px×59` → `9px×34` → `14px×31` → 其余。

## 4. 工具与验收

```
node scripts/space-migration-audit.mjs                 # 默认窗口：最近 12 小时
node scripts/space-migration-audit.mjs --base=COMMIT   # 审 COMMIT..HEAD
```

覆盖 `gap/row-gap/column-gap/padding*/margin*`、`font-size`、`border-radius` 三族；
忽略组件内部自建的局部变量（`--sk-space-*`、`--footer-actions-gap` 之类，它们不在全局阶梯内）。

- `exit 0` = 全部等价或已授权；`exit 1` = 有不等价迁移；`exit 2` = **脚本内真值表与 token 文件漂移**
  （防止「审计脚本自己写错值，把正确迁移判成错的」）。
- 任何迁移类提交，**验收第一条就是跑它**，读数贴进提交说明。

## 5. 与「进度数字」的关系（口径订正）

棘轮/审计统计的是**全部硬编码**，**不等于**「映射表内可迁移项」。
报进度必须把两个数字**分开写**：

```
剩余硬编码：XXXX 处        ← 棘轮口径（含不可迁的业务数据、局部变量、第三方色）
其中本轮可迁：YYY 处       ← 只算「逐值相等 + 表内有对应」的
```

否则下一位 agent 会把「不可迁的存量」当成「漏做的活」再踩一次（**已坑三轮**）。
