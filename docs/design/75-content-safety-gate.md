# 75 · 内容安全闸门：两阶段设计（2026-09-24 批 AX 落地第一阶段）

> 用户口径（三条一起看才是完整要求，逐字）：
> ①「人脸不做检测好像也不行，因为现在监管很严格，就怕会有来我们平台搞**淫秽擦边**的用户，
>    我其实觉得我们甚至应该做**全面检测**，就是用户上传的**素材和提示词都应该先过一遍**
>    没问题再传输生成，其实也是**防止我们被中转站给 ban 掉**」
> ②「内容检测的话，**为什么还要重新花钱呢**，用户上传素材和提示词不是本来就要识别一次吗，
>    为什么我们还要再识别一次呢？**没有低成本的过滤方案吗**」
> ③「而且有这种内容肯定是要**直接拒**的」

②这一条把我的第一版方案否了：我原来说的是"额外调一次模型做审核"—— 那就是**多花一次钱**。
下面这份是照着他三条口径重做的：**从零成本开始，能不加调用就不加**。

---

## 一、为什么必须做（两个理由，第二个才是重点）

1. **监管**：《生成式人工智能服务管理暂行办法》《网络信息内容生态治理规定》都要求服务提供者
   对输入输出做**发现即处置**；《标识办法》那条讲的是"我们作为服务提供者的义务"。
2. **保护我们自己的上游账号**（用户点出来的这条最关键）：站内的图片/视频是经**中转站**出片的。
   中转站自己会因内容违规被封号；**我们被连坐封号的那一天，全站就停了**。
   ⇒ 所以这一道不是为了"好看"，是**保命**：能把违规内容挡在出站之前，就绝不放出去。

## 二、第一阶段（**已上线**，零成本）：提示词侧本地闸门

落点 `server/contentScreen.mjs`，接线三处（`/api/generate`、`/api/plog-generate`、
`server/videoGeneration.createJob`）。

| 项 | 做法 | 成本 |
|---|---|---|
| 判定 | **纯本地正则 + 词表**，五类：色情低俗 / 违禁品与违法交易 / 暴恐与极端 / 政治敏感与领袖形象 / 未成年人性化 | **0** |
| 时机 | **建单之前**（视频侧插在 `compileVideoRequest` **之后**，查 `prompt + negativePrompt` 整段） | — |
| 结果 | `400 CONTENT_BLOCKED` + 类别名；**不建单、不冻结积分、一个字节都不发上游** | — |
| 反绕过 | 先归一化（去零宽字符、全角空格）再判 | — |
| 护栏 | 词表**只收显式项**：内衣/泳装/美妆/裸色口红这类**正当商业词一律不收** —— 误杀等于把正常用户挡在门外 | — |

**为什么插在编译之后**：视频侧的提示词是「方案结构 + 用户文案 + 硬约束」编译出来的。
只查用户原始输入的话，把违规内容塞进"必须保留"那一段就能绕过去。

**为什么是 400 不是 5xx**：这是**客户端的输入问题**，不是我们的故障。上游监控/告警看到 5xx 会
当成我们的错，而这一类必须让人一眼看出"是内容不合规"。

## 三、第二阶段（**未做**，如实列）：素材侧 + 顺带判定

按用户②那条"别多花钱"，第二阶段的顺序是**先找免费的地方，最后才考虑加调用**：

1. **复用已有的 LLM 调用做顺带判定**（推荐，**成本 0**）：
   站内「一键解析」「生成方案预览」本来就要调一次 LLM。在那次调用的返回 schema 里加一个
   `safety: { ok, categories }` 字段，把判定**搭在已有的调用上** —— 不多花一分钱。
2. **翻译上游的内容策略拒绝**（**成本 0**，且这一条现在是**bug**）：
   上游因内容违规拒单时，我们现在多半把它当"生成失败"透出去，用户看到的是"失败了，重试"。
   要做的是**识别上游的内容政策错误码 → 回一句"素材不合规，请更换"**，并且**不重试**
   （重试只会继续撞）。
3. **图片分级**（**要花钱，所以放最后、且只做抽检**）：
   真的需要"每张图都过一遍"时，用最便宜的视觉模型**抽检**而不是全量；
   或者只在"命中过关键词的请求"上做分级（风险加权，成本降一个数量级）。
4. **我们自己的素材库**：站内已有资产（用户上传过的图/视频）可以记一个"已判定"标记，
   同一份素材不重复判（这也是"别人已经识别过一次"那件事）。

## 四、边界（不吹成"全面检测"）

* 第一阶段**只覆盖文本**。图片素材现在**没有**任何自动分级 —— 页面上不许写成"全面检测"。
* 词表是**黑名单**：它挡的是"写明了要什么"的那种，挡不住隐喻与拆分表达。
  真正的召回要靠第二阶段的模型判定；黑名单的定位是"零成本的第一道"。
* 未成年人那一类只拦"明确的性化表达"，不做人脸年龄估计 —— 那是另一个量级的工程与合规问题。

## 五、待用户拍板

2. 图片分级要不要上（要花钱）：上就按"抽检 + 风险加权"，不上就明说"素材侧只靠上游拒绝"。
3. 命中之后除了拒绝，要不要**记录并限流**（同一用户反复命中 → 人工复核）？
