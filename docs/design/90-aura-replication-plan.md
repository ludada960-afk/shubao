## 三、拟定做法（等 deep-dive 的量化结论落地后按它调整）

### 3.1 把"篇"变成一等公民（这是重构的核心，不是加开关）
现在工作台的心智是"**一次一张图**"（选主题+手法 → 生成 → 再换手法）。
要复刻 Aura，必须把**篇结构**变成输入项：一篇 = `主题意象（色板）` + `N 张，每张指定手法/构图/是否动图`，
**开工前就把这一篇的想法定下来**（正是用户观察到的"他一开始就把想法想好了"）。
勾选项里出现：对称对（左→右 / 右→左）、拼接页、杂志版式、空镜呼吸页、动图位（哪几张做成实况）。

### 3.2 「不露脸」改成**分级约束**（不是删掉）
按 deep-dive 数出来的比例改成三档可选：`完全不出现人物` / `可以有局部（手、背影、侧脸、墨镜）` /
`允许全身但不露正脸`，默认取实测最常见的那档；提示词里把"不出现面部"换成可执行的措辞
（例如"避免正脸与直视镜头；允许侧脸、墨镜、背影、手部"），并**用一次真实试跑对比 Aura 验证**。

### 3.3 动图（用户已选 A）与「一套」的收费口径
- 两者都是**独立 SKU、价格写在按钮上、点前弹确认、失败不扣**；
- 动图成本按上表（2~3 秒 ≈0.4~2.7 元 ⇒ 定价必须盖住 ≥70% 毛利地板，走 `assertCatalogMarginGates`）；
- 「一套」按**张**报价（一次勾 N 张就报 N 张），与套图（`image.product_suite`）同一口径。

### 3.4 先证明再重构
现在 **0 条产出**，等于"工作台做完了没跑过一张"。所以顺序必须是：
① 用**现行**提示词真跑一组（真实链路、真实扣费，控制在 5~8 张）；
② 与 deep-dive 的 Aura 事实表**逐张对比**（人物形态、构图、色板、留白）；
③ 按差距改提示词与篇结构（§3.1/§3.2），再跑一组复核。
—— 这一步是"能不能做出他那种效果"的**唯一证据来源**，也是避免我们继续凭感觉加开关的办法。

## 六、重构方案（不是加开关：把"篇"做成一等公民）

### 6.1 心智换掉
现在：`选主题（20 母体） + 选自 10 种手法里的 5~6 种 → 逐张生成成品图`。
改成：**一次任务 = 一篇**（这正好对应小红书"一篇笔记 = 一组图"）：

```
篇 = 主题意象（母体/色板）
   + 篇骨架（N 张的清单，开工前定好）
       每张：手法 · 版式 · 人物形态 · 是否动图 · 是否有画面文字
   + 素材池（可选：先出一池，再按篇重排/复用）
```

### 6.2 三层结构（对应实测的三层现实）
1. **单图层**：一张图的主体/场景/光线/材质（现有 brief 基本够，但要按 6.3 改人物档）；
2. **版式层（新增，最大差距）**：把 N 张单图拼成宫格 / 底片条 / 宝丽来画中画 / 品牌信息图 ——
   ⚠️ 必须**先出单图再拼**，不能让模型"一次画一整张九宫格"（分格线会画歪、格内内容互相渗透）；
   拼版这一步是**确定性渲染**（我们自己的模板，不调模型），所以顺手也能把"画面内文字/色卡/署名"做成可控的；
3. **篇层**：一张张排好顺序（封面第一张是什么、动图放第几张、空镜当呼吸页）。

### 6.3 人物形态：从一条禁令改成六个档（按实测分布给默认值）
`空镜（无人物）` / `只有手或手臂` / `躯干与腿部（不露头）` / `下半脸（额头以上出画）` /
`墨镜（把墨镜当造型元素）` / `背影或侧脸` —— **默认档 = 实测最高频那一档**，
正脸**仍然不做**（实测只有 1 张）。措辞从「不出现面部」改成"避免正脸与直视镜头；允许侧脸、墨镜、背影、手部"。

### 6.4 素材池与"一材两篇"
工作台要能**看一眼池子、按篇重排**：一次生成把素材放进"这一场 shoot"的池子，再从中挑图组成新的一篇
（同一张图可以出现在两篇里）——这正是他 12 组重复图的来源，也是**省成本**的地方。

### 6.5 收费（用户已定口径）
- 「一套」= 一张一张计价（N 张 = N 张的钱），按钮上写清单价与总额；
- 「这一篇的发布文案」= 独立 SKU（`ec_concept_copy`，0.5 积分/次），**默认随篇首发**（2026-09-28 批 DC 续-7），
  可关；关掉之后「再来一版文案」仍只花 0.5 —— **拆的是钱和重做，不是交付单位**（见 §7.5）；
- 「做成动图」= 独立 SKU（图生视频最短 5 秒档 ≈¥0.9/条 ⇒ 出片后本地裁到 2~3 秒，含 70% 毛利地板校验），
  **价格写在按钮上**、点前确认、失败不扣；
- 两者都不做"自动批量扣费"：用户勾几张就是几张。
  ⚠️ 续-7 补一条：**一次点击 = 一次确认 = 一笔总额**（图逐项 + 文案 0.5 相加写在同一个确认框里），
  但**冻结仍是分开的**（逐张 hold + 文案单独 hold）—— 用户看到一次总价，后台按张隔离失败。

### 6.6 交付顺序（每步都能单独验收）
1. **阶段一（能产出）**：篇结构 + 篇内清单（手法/人物档/动图位）+ 一次出 N 张按张计费；
2. **阶段二（像不像的门槛）**：版式层四种语法 + 素材池/多篇复用；
3. **阶段三（更远）**：品牌信息图版式模板化 + 跨图一致性锚定（同一模特/同一场景，用参考图锚）。

### 6.7 先证明再重构（顺序不能反）
现在这个技能 **0 条真实产出**。所以阶段一开始前，先用**现行**提示词真跑一组（5~8 张、真实扣费），
与深度调研的事实表逐张对比（人物形态/构图/色板/留白/版式），把差距变成数字，
再按 §6.2~6.3 改 —— 这一步同时也是"我们这条路走不走得通"的**唯一证据**。
⚠️ 这一条**尚未做**（见 §七 的"未做"清单）：本批改的是结构与档位，还没有一次真实试跑对比。

### 7.2 M4「做成动图」：**已做齐（2026-09-27 批 DC-4）**，打桩全绿、真跑留给用户本人

### 7.5 交付单位改成「一次下单 = N 张图 + 1 组文案」（2026-09-28 批 DC 续-7）

**为什么改**：小红书的发布单位是**一篇笔记**，不是一张图。前面几批把"一篇"做成了结构（篇标记、
一篇一张卡、可还原勾选），但**一次下单交出来的仍然只有图** —— 文案要用户自己另外想起来写，
于是"这一篇"在交付上还是没写完。竞品实测单篇 4~18 张、均值 10.3（`docs/research/2026-09-27-aura-deep-dive.md`），
一次就交完整篇图文。

**这一批的判据只有一条，最容易被做反，所以写在最前面**：
> 拆开的是**计费与重做**，不是**交付单元**。
> 一次点击仍然交付"一篇图文"，只是这"一篇"的图与文**从同一份 brief 并行出发**。

配套的三条硬约束（都有门禁，不靠自觉）：
1. **请求体里绝不传图片 URL**。文案是"同一次策划的两次渲染"，不是"看图说话"——
   看图写文案会退化成图片说明（"这是一张木桌上的白瓷器"），那是最烂的小红书文案。
   判据是纯函数 `buildSkillCopyRequest` 整个 JSON 里不许出现任何图片地址
   （`test/concept-set-post-0929.test.mjs` ⑤）。
2. **一次点击 = 一次确认 = 一笔总额**（`N 张 × 单价 + 文案 0.5 = X 积分` 写在同一个确认框里），
   但**冻结仍分开**：逐张 hold + 文案单独 hold ⇒ 文案失败只退 0.5，**不牵连图**；
   图里某张失败也只退那一张。`runPostCopy` 的 catch 里**不许碰** run / values / moduleOff
   （门禁 ⑦ 就是咬这一条）。
3. **文案跟随最终生成**（方案确认后的那次提交），**不跟 0.5 的方案预览那一步** ——
   预览那一步只出方案，出文案等于白花钱。

**幂等键的 attempt 语义**跟着改：随篇首发 = `0`，重做 = `1,2…`。
⚠️ 改之前 `Number(input.attempt) || 1` 会把首发那次**吞成 1**，于是"首发"与"第一次重做"
拿回同一组句式；服务端轮换的起点也一并从 `((n||1)-1)%total` 改成 `(n||0)%total`。

**顺带把"张数"从隐含约定变成写在脸上**（这是用户当面指出的第二件事：进页面一个手法都不勾、
按钮是灰的、整页没有一个数字说会出几张）：
三档规模预设（轻量 4 / 标准 6 / 完整 10，**默认标准**、进页面就勾好 6 张），
清单块标题写 `这一篇 6 张 · 已选 6/10`，主按钮写 `6 张 × 2 + 文案 0.5 = 12.5 积分`，
预览步在按钮下面写「这一步只出方案；确认后将出 6 张图 和一组发布文案」。
⚠️ 批 AW（"默认一个都不勾"，A+ 内容那条）与这一条**不冲突**：新加了声明侧的 `modulesPresets`，
`skillInitialModuleOff` 只对**有预设的那条技能**按默认档勾好，其他技能保持全不勾。

**同批修掉的六处界面问题**（用户批注图 1 / 图 2，全部**复用站内既有东西**，不新造第五种控件）：
① 模型选择换 `.sb-opt` 卡片行（抽 `ModelOptionRows` 共享组件，首页那边也换成它，全站一份实现；
`kind` 仍是 `select`，只加 `variant` 标记，**不改既有门禁口径**）；
② 参考图上移第一位（站内 44 个带上传的技能里 41 个这么排）；
③ 比例 + 分辨率同一行（`span:'half'` + 纯数字标签 `RATIO_BARE`，另补一条半宽列的密度覆盖）；
④ 版式族卡片的 hint 去内部分析口吻（「他的第二大族」「实测他 85%…」**是我们的话**），
分析**搬家**到结果区选版式族的那一行；
⑤ 结果区 14 颗药丸从 28px 提到 32px（同页最小控件就是 32px，页签字重提到 700）；
⑥ 左侧导航那"第二层紫"删干净 —— 静止态的品牌色渐变整条撤掉，
hover / 选中 / 任务在跑三处的 135deg 渐变与光晕**收成同一档**（原来这一列里同时有两套光晕）。

### 7.6 2026-09-29 批 DC 续-15：面板别跟着滚 + 连拍组推翻重做

**①「模型 / 画面规格」面板滚动时脱离**
根因：`ConfigTriggers` 每次 `scroll` 都重算 `top`，而 `.app-topbar` 是 `position: sticky`、滚过 120px 会加
`.is-compact` **改变自身高度** ⇒ 面板一边滑一边跳。
做法：`scroll` 监听**整条删掉**，改成**打开时量一次**、只在 `resize` 时重量。
实测：打开 `top=84` → 页面滚动后 `84` → 左栏滚动后 `84` → resize 后才重算（`108 / 420`）。

**② 连拍组：`前 2 张 / 前 3 张` → 清单里逐张标**（§七 表格第 ⑤ 行的完整复盘）
这一条是**我自己写错的注释**推翻了整个默认值：`skillRun.js` 里那句
「实测里连拍簇本来就是从第一张开始连着的」**与实测相反**。按 `TH=0.14` 重跑复现 74/402 后：
23 个簇只有 5 个含第 1 张、21 篇里 16 篇（76%）不含封面、74 张里 54 张（73%）落在不含首图的簇，
