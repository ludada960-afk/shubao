# 72 · 数字人：知渔的策略与我们的落点（2026-09-26 实查）

用户问：「数字人要不要用对口型的，你先看一下**知渔他们那边是什么策略**」。
下面是实查结论（知渔 DOM 实采 + 免登录接口 + bundle 登记表，出处逐条列出）。

---

## 一、知渔的数字人 = **换口型**（不是"文字凭空生成数字人"）

依据（都是原文/字段名，不是推断）：

1. **模型入参只有三样**：`GET /api/models` 里那条 id `cmqj69rtt0002pd8wkyvdzhm1`：
   `name: "Digital Human" / title: "数字人" / type: video`，
   `genParams`：`source_video_url`（type: referenceVideo，label「视频」）+ `source_audio_url`（type: referenceAudio，label「音频」）
   + `duration`（select，1~10 分钟带 priceMultiplier）。
   ⇒ **没有** text→avatar / image→avatar 这类参数，就是"给一段真人视频当模板，用音频驱动它说话"。
2. **形象只能自带**：页面「选择形象」下拉只有 `请选择形象 / + 从我的资产选择 / 已导入视频`；
   新账号下**没有任何内置虚拟形象**；导入成功的原文是「视频导入成功：已作为临时形象，可直接后续处理，或再生成口播视频」。
3. **音频侧叫"驱动音频"**：`驱动音频时长：xx / 10分钟`，超限文案「口播视频时长不能超过 10分钟」。
4. **后端会做人像检测**：运行时配置里的失败文案 `ICDetectVideoNoAvailablePerson → 未检测到人物，请修改后重试`
   —— 这是口型驱动链路的典型前置条件。
5. **整个 bundle 里 `对口型 / lipsync / heygen / hedra / sadtalker / wav2lip / musetalk` 全库 0 命中**：
   他们把"换口型"**包装成"数字人"卖**，界面上一句"对口型"都不提。

## 二、他们的完整产品形态（6 步流水线 + 一键自动）

| 步骤 | 内容 | 价格（原文） |
|---|---|---|
| 01 IP深度学习 | 爆款文案（口播/剧情 + 人设型/卖点型 + 行业人设/产品业务/卖点价格/其他要求）/ 视频学习（链接或本地视频，≤50M、3 秒~5 分钟、需含口播人声） | 0.25 / 识别 0.25，撰写文案 0.125，AI法务 0.125 |
| 02 音视频生成 | 音色三来源（系统/自定义克隆/资产库）+ 音量语速 + 生成语音；**选择形象（只能自带视频）**；生成口播视频 | TTS ≈0.125；**口播视频 2.40 积分/分钟**（会员 1.8 / 贴牌 1.5） |
| 03 视频编辑 | 自动剪气口 | 0.125 |
| 04 标题标签关键词 | 4 类词（重点/描述/行动/情感） | 0.125 |
| 05 字幕和音乐 | 自动字幕 + 字幕样式 + 高亮词 + 背景音乐 | 0.125 |
| 06 封面制作 | 自动生成封面（面板标"开发中"） | 0.125 |
| — | **一键自动模式（全流程）** | **3.15 积分**（= 各步之和，1 分钟视频） |

积分↔人民币：他们充值 ¥20 → 20 积分（**1 积分 ≈ ¥1**）⇒ 口播视频约 **¥2.4/分钟**。
⚠️ 页面气泡写的是「2.40 积分/**秒**」，与它自己的登记表（`priceUnit: "分钟"`、时长 1~10 分钟带倍数）**对不上**——
那是他们的文案 bug，真实口径是**积分/分钟**。（我们不必照抄这个错。）

## 三、我们能照抄什么 / 不该抄什么

**照抄（形态）**：
· **形象让用户自带真人视频**（不做虚拟形象库、零肖像权风险、成本可控）——与我们的判断完全一致；
· **按分钟计价 + 时长上限**（他们 10 分钟封顶）；
· **"主流程 + 小步骤"的定价结构**（主流程按分钟，文案/字幕/标签等小步骤各收一点）；
· **一键自动模式**（把流水线各步打包成一个按钮，用户不用逐步点）。

**不照抄**：
· 页面上「积分/秒」那种与登记表对不上的文案；
· 他们的价目绝对值跟我们不同锚（他们 1 积分≈¥1，我们 1 积分面值 ¥0.2618），照抄数字会差 3.8 倍。
