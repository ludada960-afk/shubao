# 86 · 生成结果放在哪、卡片长什么样、配哪些功能（设计稿 · 待实现）

> 2026-09-26。用户口径（逐字）：
> 「我不知道你生成之后是在哪里呢？是在历史那个地方吗？然后它会配备哪些功能呢？图片它会配备什么功能呢？
>  视频的话，它又会配备哪些功能呢？比如说是不是会有**重刷**的功能？有**删除**的功能，有**下载**的功能，
>  有**导入到我的资产**里面的功能，我不知道我们应该有哪些功能会比较好，这个你要帮我想清楚呀。
>  还有就是他们是不是也得有一个**遮罩的标签**这样？那这个标签应该备注是什么呢？……
>  它的**排版**，它的**时间**这些东西是不是也得加进去呢？我们现在这个**我的资产**还有**画布里面的新建画布**
>  功能他们那里其实已经做过很多相关的一些 UI 或者交互方面的设计了……你可以去用一些他们的素材过来，
>  然后把他们的一些设计思路也可以去整体的思考一下。」

## 一、先回答"生成之后在哪里"（现状，逐个事实核对过）

| 结果类型 | 落在哪 | 卡片上现在显示什么 | 现在能做哪些操作 |
|---|---|---|---|
| 图片（含套图/A+/详情图/电商专区…） | 子页面右栏**「历史」**页签，同时进**「我的作品」** | 封面 + 标题 + `N 张 · 时间` | **用这组参数**、**删除**；点封面看大图 |
| 视频 | 同上（按本机标记归到这条 skill） | 成片（自动播放）+ 标题 + `秒数 · 分辨率 · 比例`（**没有时间**） | **用这组参数**、**删除**；点封面看大图 |
| 小红书图文 | 同上 | 封面 + 标题 + `N 张 · 时间` | **用这组参数**（还原那句提示词）、**删除** |

数据来源：`src/pages/Home/SkillWorkbench.jsx`（渲染与动作）、`src/pages/MediaCreation/index.jsx`（筛作品/任务并拼卡片字段）。

**所以缺口是**：没有「下载」、没有「存到我的资产」、视频那条没有时间、成功的结果没有状态/类型标签、
动作平铺在卡片下方（画布库那种"悬停浮出"的成熟做法没用上）、没有按日期分组。

## 二、卡片长什么样（沿用站内已有的两套语言，不发明新的）

封面用现成的 `CaseCard`（4:3、封面铺满、底部自下而上白渐变、标题 + 副标题 + ›、hover 浮出预览窗、
视频卡进视口才播）—— 这是**子页面与首页已经在用的同一张卡**，不再另起一套。

```
┌──────────────────────────┐
│                          │
│        封面 / 视频         │   ← 左上角一枚状态标签（只有"不正常"时才出现）
│                          │
│  标题                     │   ← 一句话：作品标题 / 提示词前 40 字
│  规格 · 时间          ›   │   ← 副标题：`3 张 · 09-26 14:20` / `5 秒 · 1080P · 16:9 · 09-26 14:20`
└──────────────────────────┘
   hover 时右下角浮出图标动作（照画布库：悬停才出现，不占平时版面）
```

**三个排版决定 + 理由**：
1. **时间进副标题**（不是单独一行）：画布库的经验是"名称 + 时间 · 节点数"，一行读完；
   图片侧现在已经是 `N 张 · 时间`，只是**视频侧漏了** —— 补上即可，不新增行。
2. **动作改"悬停浮出图标"**（照 `CanvasLibraryModal` 的 `改名字 / 复制 / 收藏 / 删除`）：平时卡片干净，
   鼠标进来才出现。移动端没有 hover ⇒ 用"长按/点右下角 ⋯ 出菜单"（画布库同样的问题，一起改）。
3. **不显示"图片/视频"类型标签**：视频卡会自己播、右下有播放键，图片卡是静的 —— 一眼可辨，
   再贴一枚"图片"是噪音。**标签只用来标"状态"**（见下）。

## 三、那枚"遮罩标签"写什么（只标状态，不标类型）

| 状态 | 标签文案 | 出现条件 |
|---|---|---|
| 排队中 | `排队中` | 视频任务 `queued` |
| 生成中 | `生成中` | 视频任务 `processing`（图片是同步返回，没有这个态） |
| 生成失败 | `生成失败` | `failed` / 无结果 |
| 已过期 | `已过期` | 作品超过保留期被清理（见第五节） |
| 正常 | **不显示标签** | 有成品 —— 干净才是奖励 |

现在只有视频未出片时会挂标签（`badge`），文案直接用服务端状态英文/中文混着来 —— 统一成上表这五个词。

## 四、每类结果配哪些功能（用户点名的"重刷/删除/下载/存到我的资产"逐条给结论）

| 动作 | 图片（含图文） | 视频 | 说明 |
|---|---|---|---|
| **用这组参数**（= 重刷的第一步） | ✅ | ✅ | **已经有**。为什么不做成"一键重刷直接出片"：本站铁律是**扣费必须由用户再点一次**（`test/charge-requires-confirmation`）。现在的做法是"还原面板 → 用户点生成"，等价于重刷，且钱看得见。 |
| **下载** | ✅ 下载这一组全部图 | ✅ 下载成片 | **新增**。走已有的批量下载实现（画布里 `导出图片` 那条链路），不新写一套。 |
| **删除** | ✅ | ✅ | **已经有**。删的是**这条记录/这份作品**，不是模型产物本身 —— 文案要说清（现在只写"删除"）。 |

| 看大图 / 播放 | ✅ 点封面 | ✅ 点封面 | **已经有**（灯箱，图片可左右翻）。 |
| 分享 | ✖ 不做 | ✖ 不做 | 站内还没有分享链路（转发一律需要公开链接，那是另一件事）。 |

## 五、还需要一起定下来的三件事（我的建议）

1. **保留期**：作品现在是 **7 天**（工作区里已有提示「作品保留 7 天，请及时下载。」）。
   历史卡片上应该**也写这条**（现在只有工作区写了）——建议在历史面板顶部放一行同样的提示，
   并且**过期的那条不静默消失**，而是留一张灰卡 + `已过期` 标签（用户知道发生了什么）。
2. **排序与分组**：照画布库 —— **按日期分组（今天 / 昨天 / 更早）**，组内按时间倒序。
   现在是一整片网格、只按时间倒序，条数一多就找不到东西。
3. **筛选**：画布库有 `全部 / 收藏 / 最近 7 天`。历史面板建议先加**类型筛选**（全部 / 图片 / 视频）——
   视频与图片混在一条流里时，找视频要翻很久。收藏可以先不做（画布库的收藏是针对"要反复改的画布"，
   生成结果没这个诉求）。

## 六之二、保留期与"灰卡"的成本（用户 2026-09-26 追问，先答清楚再动手）

- 服务端现状：`server/worksRetention.mjs`，默认 **7 天**（`ASSET_RETENTION_DAYS` 可覆盖），
  到期**整行删除**（`DELETE FROM works WHERE id = ?`）—— 省空间的是这一步。
- "灰卡 + 已过期"要留下来的只是**一条极小的数据库行**（技能 / 时间 / 张数 / 一个过期标记），
  **不含图片、不含正文**，估算 < 1KB；对比一张 2K 图 1–3MB ⇒ 约 **0.05%**。
  列表是按需查询 + 分页（前端已有"显示更多"），**不占内存**；真要担心还可以给墓碑设上限
  （只留 30 天 / 每人最多 N 条）。
- 结论（建议）：**媒体照旧按 7 天清**（那是省空间的关键），墓碑只负责回答"我的东西哪去了"。
  实现要动清理链路（把 `DELETE` 换成"清空媒体字段 + 标记过期"）+ 一次迁移，所以**本批没做**。
  另一条路是"过期就不显示"（= 现状），代价是用户不知道为什么少了东西。

## 六之三、"重新生成"到底该是什么样（用户 2026-09-26 追问，核对后的结论）

用户问：「具体到要重新生成，应该让它**跳转回原来的相应子页面**吧，而且重新生成是不是也要**像做同款那样**，
把**素材和提示词和配置都填回去工作台**呢？」

**核对结果：这套机制站内已经存在，而且现在的行为就是它。**

- 历史卡片上的「用这组参数」（`MediaCreation.reuseHistory`）：
  - 图片：把 **整份面板值** `replay.panelValues` 写回工作台 —— 它包含**上传位的素材**
    （保存时写的是 `{...effectiveValues}`，而上传位的值就是 `{assetId,url,status}` 那组条目），
    所以素材、提示词、配置**一起回来**；
  - 视频：提示词 + 规格（时长 / 比例 / 清晰度 / 创作方式）写回创作台；
  - 图文：那句話写回输入框。
  - **一律不自动生成**，并明确提示「……确认后点「立即生成」——这一次会重新计费」。
- "跳回对应子页面"：历史面板**本来就在那条技能的子页面里**，用户点的时候人就在那一页。
  需要跳的场景是"从别处看历史"（例如「我的作品」），而那边现在没有"用这组参数" ⇒ 暂时没有这个缺口。
  以后要加，就统一走**已有的** `creationLaunch`（`kind: 'gallery-remix'`，首页案例「做同款」走的就是它：
  落到对应技能 → 预填素材与提示词 → 不触发生成），不要每个列表各写一套。
- **结论**：「做同款」与「用这组参数」本来就是同一条路的两个入口（一个从别人的案例带出输入、
  一个从自己的记录带出输入），文案与行为应该继续对齐。

## 七、这一稿里**没有**采纳的做法（免得以后又被问起）

- ❌ 历史卡上放"重新生成"直接出片：违反"扣费必须再点一次"。用「用这组参数」代替。
- ❌ 给结果贴"图片/视频"类型标签：视频会动、图片不会，标签是噪音。
- ❌ 历史卡做"收藏"：生成结果不是要反复经营的对象（要做也该做在作品/资产上）。
- ❌ 把"存到我的资产"做成弹窗选项目：多一步、且大多数用户只有一个项目。
