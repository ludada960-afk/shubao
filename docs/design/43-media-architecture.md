## 0. 一句话结论

把现在「四个板块 × 各自一套面板」改成 **「两个板块（图片生成 / 视频生成）× 一套工作台骨架 × N 个 Skill」**。
关键不是把页面合并，而是**把"配置"从页面里抽出来变成 Skill 的声明式契约** —— 只有这样才可能像竞品那样
批量做到 40+ 个 Skill，且视觉与交互不漂移。**页面数量从 12 个降到 2 个骨架 + 1 个声明文件/技能。**

### 3.1 两级结构

```
首页（卡片语言，保留现有"上行张开"三图卡）
├─ 视频生成   ← 放前面（你的批注 #1）
└─ 图片生成
        ↓ 点击
媒体板块（同一套组件，两处复用）
├─ 顶部：搜索/分类条（全部 · 电商 · 人像 · 海报 · 封面 · 修图 · 建筑室内 …）

        ↓ 点案例卡

├─ 左：配置区（按 Skill 契约渲染字段）+ 生成 CTA（含积分）
└─ 右：「示例」/「历史」双页签；示例卡 hover 放大、点击弹窗（你的批注 #13）
```

### 3.2 无限画布的位置

无限画布**保持独立入口**（它是"编辑器"，不是"生成器"）：一级导航保留，但它的**生成节点复用同一套 Skill 工作台**（`CanvasVideoComposer` / 图片生成器已经把逻辑对齐过一轮，继续收敛到同一契约）。

### 3.3 视频板块的收口（按你的批注 #9）

- 保留 **智能成片 / 首尾帧** 两个入口
- 「全能参考」= 现在的"参考"（三个素材卡：图片 / 视频 / 音频）
- 「爆款复刻」→ 变成 Skill（`video.remake`），从 Hub 进
- 上传区：**照我们自己图片侧的"卡片歪着叠放"语言**，不做左边上传右边输入；**上面素材卡、下面提示词**
- 配置面板：**模型 + 分辨率/画幅/时长** 两个面板起步；**默认生成声音**（上游 `generate_audio` 默认 true，把开关从主流程撤下，需要时进高级）
- 首尾帧**专属模型**：见 §5.3 —— 上游确有按能力区分的路线，但要做成"能力标签 → 可用模型子集"的映射，而不是写死模型名

## 4. 统一设计语言（这是防漂移的核心）

### 4.1 三层语言，各自唯一实现

| 层 | 内容 | 唯一实现位置（规划） |
|---|---|---|
| L1 卡片语言 | 入口卡（上行张开三图）、案例卡（封面+标题+hover 动效）、素材卡（歪着叠放） | `components/media/EntryCard` `CaseCard` `AssetDropCard` |
| L2 工作台骨架 | 左配置右内容、分组标题、字段行、CTA 行（积分在右） | `components/media/WorkbenchShell` + `FieldRenderer` |
| L3 状态语言 | 生成中/失败/重试、积分不足、未登录、空态、保存/发布 | 复用现有语义色与既有组件，禁止各页自写 |

**判据：图片板块与视频板块的 DOM 结构必须来自同一组组件**，差异只允许出现在 `fields` 配置里。

### 4.2 案例卡（两板块共用一份实现）

- 图片卡：hover 轻微放大 + 标题上浮（你批注 #13 的要求）；点击 → **弹窗可放大 + 左右切换**（比知渔更完整）
- 视频卡：hover → 静音、循环、**进入视口才开始加载**的预览播放（`preload=metadata` + `playsinline` + 只在 hover/视口内 `play()`）；点击 → 弹窗真播 + 「复用这个案例」
- 成本控制（你问的）：单条 ≤10 秒、静音、懒加载、同一时刻最多预加载 1 条；按 47 张封面 + 20 条视频估算，首屏额外流量 ≈ 0（视口内才加载）

### 4.3 门禁化（不靠自觉，靠测试）

新增契约测试（沿用本项目已有的"判据锁死"传统）：
1. 两板块的入口卡 / 案例卡 / 工作台骨架**必须来自同一模块**（源码级断言，禁止各自实现）
2. 配置字段渲染只能走 `FieldRenderer`（禁止页面里手写 model/resolution/count 控件）
3. 每个 Skill 的 `fields` 必须在注册表里声明；未登记字段不得上屏
4. CTA 文案与积分展示只有一处实现（防"图片侧和视频侧按钮不一样"复发）

## 5. Skill 契约（决定我们能不能批量扩产）

### 5.1 Skill = 声明式配置（不写页面）

```js
{
  id: 'image.product_suite',            // 归属板块 + 语义
  board: 'image',                        // image | video
  name: '电商商品套图',
  category: '电商',
  complexity: 'heavy',                   // simple | standard | heavy
  cover: { template: 'case-3up', accent: 'warm' },
  capability: { product: true, model: true, extra: ['sku', 'structure'] },
  fields: [ /* 声明式字段：模型/尺寸/数量/结构配置/SKU/商品信息 */ ],
  pipeline: 'ecommerceSuite',            // 指向已有的服务端引擎（复用现有 assetPlanner 等）
  cases: [ /* 示例：图片或视频，含封面与复用参数 */ ],
  history: true,
}
```

**新增一个 Skill 的成本 = 一个配置文件 + 一张封面 + 若干案例**，不新增页面、不新增面板。

### 5.2 三档复杂度（避免"每个 Skill 都做成电商套图那么重"）

| 档 | 字段量 | 例子 | 工作台形态 |
|---|---|---|---|
| simple | 1–3 | 海报设计、社媒封面、图片复刻 | 提示词 + 模型 + 尺寸数量；右侧案例为主 |
| standard | 4–6 | 白底图、场景图、模特试穿、视频智能成片 | 图片/素材卡 + 模型 + 尺寸 + 数量 |
| heavy | 6+ 且含子结构 | 电商套图、A+ 内容、详情图、爆款复刻 | 现有复杂面板（结构配置 + SKU + 商品信息） |

### 5.3 现有资产的迁移映射（不推倒重来）

| 现状 | 迁移为 |
|---|---|
| 电商生图 6 面板 | `image.product_suite`（heavy，字段照搬现有面板，引擎不变） |
| 小红书 种草图文 / Plog | `image.xhs_note` / `image.xhs_plog`（standard） |
| 自由创作 4 子板块 | `image.free` / `image.poster` / `image.social_cover` / `image.brand_keyvisual`（simple） |
| 视频 智能成片 / 首尾帧 | `video.smart` / `video.frame`（standard，首尾帧带专属能力标签） |
| 视频 爆款复刻 | `video.remake`（standard → 从 Hub 进） |
| 现有 5 个内置技能 | 直接成为 Skill（`image.white_bg` 等），字段沿用 |
| 画布各生成节点 | 复用同一 Skill 契约（节点里只放 fields 子集） |

**首尾帧专属模型**：上游目录里确实按能力区分（首尾帧/参考图/参考视频/音频）。做法：Skill 声明 `capability`，路由层按能力过滤可用模型 → 界面只显示能用的那几条。**不写死模型名**（写死就会像 9-16 那批"8 条调不通的假模型"一样翻车）。

## 6. 封面与案例的生产线（你的第 13 条批注）

### 6.1 封面模板：3 个族 + 统一槽位

| 模板 | 用途 | 版式 |
|---|---|---|
| `case-3up` | 案例型（电商套图、A+） | 左文案 + 右 3 图错落 |
| `hero-single` | 功能型（白底、试穿、修图） | 主体大图 + 角标 |
| `poster-style` | 风格型（海报、封面） | 整幅案例图 + 底部标题条 |

统一约束：**同一族的标题层级、留白、圆角、色板一致**；色相按类目分组（电商暖、人像柔、修图冷、海报高饱和）。

产出方式：我给你**每个模板的可复用提示词**（含槽位 `{主体}` `{背景/色相}` `{标题}` `{副标题}`），你用任意模型批量出图，风格由模板本身保证一致。

### 6.2 要不要做后台？——**要，但分两期**

| 期 | 做法 | 理由 |
|---|---|---|
| 一期（现在） | 我把 Skill 配置 + 封面提示词给你；你出图后我入库（图片进 CDN、写进 skill 的 `cases`） | 数量少（12 个以内），走代码提交可追溯 |
| 二期 | 做「Skill 与案例管理后台」：上传案例（图/视频）→ 选模板 → 自动生成封面草稿 → 填标题 → 预览 → 发布；支持排序/上架下架 | 40+ Skill、案例频繁更新时，走代码会拖死节奏；且需要审核与归属 |

**后台的核心价值不是"上传"，是"保证风格一致"**：模板 + 预览 + 校验（标题长度、封面尺寸、色板）→ 谁上传都不会跑偏。

### 6.3 视频案例怎么先占位（你说的成本问题）

- 先用**我们自己的公开示例**或合规素材占位（≤6 秒、静音、可在 hover 播放）
- Skill 配置里 `cases[]` 每条带 `placeholder: true` → 后台/清单可筛出"待替换"
- 你自己生成后替换：一条命令/一次后台上传替换封面与视频，**不动 UI 代码**

## 10. 现场取证（已登录态实访，2026-09-16）

### 10.1 关键发现：**一个页面渲染全部 Skill**

知渔的 Skill 页 URL 是 `/image-creation?id=<skillId>` —— **不是每个 Skill 一个页面**，
而是同一套页面按 id 渲染不同配置。这一点直接验证了本蓝图 §5 的结论：
**能不能批量做 40+ 个 Skill，取决于"配置是不是声明式的"，而不是"页面写得多快"。**
我们照此实现，新增 Skill 只需加声明。

### 10.2 Skill 页的真实结构（以「小红书爆款复刻」为例）

```
返回图片创作 › 电商专区 › 小红书爆款复刻
┌───────────────────────────────┬──────────────────┐
│ 参数配置                      │  [作品示例]      │
│  · 原图   （上传/从资产库选择）│   原图 ↔ AI作品  │   ← before/after 对比
│  · 参考图 （上传/从资产库选择）│   一张张切换     │
│  · 比例 *   1:1 2:3 3:2 3:4 4:3 9:16 16:9        │
│  · 清晰度 * 1K 2K 4K          │                  │
│  · ✨ 立即生成                 │                  │
└───────────────────────────────┴──────────────────┘
```

要点：
- 上传卡文案统一（`支持 JPG、JPEG、PNG，单张不超过 10MB`）、按钮统一（`选择文件 / 从资产库选择`）
- 必填项用 `*` 标注，字段名极简（就「比例」「清晰度」两个词）
- **复刻类 Skill 的示例用「原图 ↔ AI 作品」对比**，而不是单张成品图 —— 这比单图更能说明"这个 Skill 干什么"
- 右侧页签只有两个：`作品示例`（公共示例）+（登录后有）`历史` —— 与我们 P0 的骨架一致

### 10.3 Hub 分类学与封面规格

- **8 个分组**：精品推荐 · 电商专区 · 创意应用 · 游戏动漫 · 人像摄影 · 建筑室内 · 图片编辑 · 绘画模型
- **封面统一 4:3**：实测源图 1600×1200 / 2304×1728 / 2400×1792，列表里渲染约 274×205 —— **同一比例 + 同一卡片结构**，这是"风格一致"的机械保证
- 卡片只放两样东西：**封面图 + 标题**；分组标题分隔

### 10.4 对我们的直接结论

1. 我们的 Skill 页也走 `?id=` 单页渲染（不新增页面），封面统一 4:3、卡片只有封面+标题
2. 复刻/修图类 Skill 的示例一律做 **before/after**（比我们现在的单图示例更有说服力）
3. 分组直接借用已验证的 8 类骨架（电商 / 创意应用 / 人像摄影 / 建筑室内 / 图片编辑 / 视频玩法 …），按我们的能力删减
