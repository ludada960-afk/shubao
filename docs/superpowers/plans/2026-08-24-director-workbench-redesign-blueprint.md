# 薯包视频工作台重构蓝图 —— 从表单拼贴到导演台

> 2026-08-24 · 视频线程 · 基于对 MiniMax H3 官方 Skills、海螺 AI 短剧工作室（开源）、小云雀 AI、即梦 Seedance 2.0、可灵 Kling 3.0、LiblibAI/LibTV、腾讯 OnSolo、Sora Storyboard、Runway Gen-4 的公开资料调研。
> 性质：产品方向提案，待老板拍板后再动代码。

## 一、你的判断是对的：现在的布局不是行业范式

当前工作台截图暴露的问题（按严重度排序）：

1. **两套产品拼在一页**：上半是"单发表单"（选模板→传素材→写提示词→参数条→预览占位），下半又是"项目工作台 stepper"（项目→素材→分镜→候选→时间线→交付）。用户要在同一页理解两个心智模型。
2. **表单向导范式已过时**：头部产品全部转向"导演台工作区"——中央大画布/分镜板为主视图，AI 以对话+分步确认驱动，用户在**产物**上做决策而不是在**表单**里填空。
3. **缺一致性锁**：行业用角色卡/场景卡/锚定照片把"主角长什么样"锁死再开拍；我们只有素材绑定，跨镜头人物/产品一致性全靠运气。
4. **分镜表达力不足**：我们的镜头只有用途/时长/提示词；MiniMax H3 官方用的是六列标准镜头表（含逐秒指令与连续性链）。
5. **没有创作质量门**：我们有预算/合规预检，但没有 Hook 密度、连续性链、每秒指令覆盖这类"片子好不好看"的结构自检。

## 二、行业前沿到底怎么做（调研实证）

### 2.1 MiniMax H3 官方 Skills（最直接的对标，MIT 开源）

H3 不只卖模型，官方开源了 1 个提示词技能 + 8 个风格化成片技能（极简产品广告、3D 动画短片、纸艺定格科普……）。每个技能是一个可安装的声明式 `SKILL.md`，其内部流程高度一致：

- **强制启动问询 Gate**：一次性确认素材/款式/时长/画幅/风格模板/文案方式——模型选择不问用户（默认 H3），只在结果里展示。用户说"你看着办"也要把采用的默认值作为已完成问询展示出来再继续。
- **视觉锚定系统**：先做"产品事实摘要"，再用三张独立锚定照片锁视觉（主视觉/材质细节/结尾构图）；明确禁止四宫格拼贴（防止版式串进成片）。
- **角色卡 → 场景卡 → 六列标准镜头信息表** 的三级锁定：
  - 角色卡：三视图+表情+道具标注+"身份锁"+视觉 ID 备注，生成后必须让用户选「锁定并继续 / 重生成 / 调细节」，并警告改设定会连锁作废下游；
  - 场景卡：只放环境不放人，必含"连续性地标"（跨镜头必须保持屏幕位置的固定物，如门框/中岛）与光位基线；
  - 六列镜头表：`镜头编号&时长 | 连续性衔接 | 参考锚点(空间+身份) | Hook类型 | 镜头描述(每秒指令) | 音频与对白轨`。其中每秒指令必须覆盖五要素（动作/运镜/空间位置/音频线索/与下一秒交接），亚秒节拍用 `2.0–2.5s` 标记。
- **STEP 5.5 镜头表自检门（硬性）**：六项全过才允许画分镜——Hook 密度（每 3 镜至少 1 个反转/揭示/呼应）、单镜 ≤15s、单镜 ≤3 个有效角色、同场景锚点继承、每秒指令无空隙、连续性衔接逐行成链。通过后在表格顶部盖 `shot-table self-check: passed` 戳。
- **每一步都有可见产物 + 用户选项卡**（批准推荐项/重生成/调整），绝不未经确认跑完整条链路。

### 2.2 海螺 AI 短剧工作室（开源实现，验证了工程可行性)

React18+FastAPI 单仓库：LLM 导演 Agent 把创意自动转成多集剧本+结构化分镜脚本 → **每集最多 30 镜并行生成** → 角色一致性库独立管理角色档案 → WebSocket 实时流式进度。专为现代视频模型 6–10s 时长优化"让每一秒都有价值"。

### 2.3 其他对标

- **小云雀 AI**（字节生态，搭载 Seedance 2.0）：短剧智能体，10 万字剧本一键成片——"剧本进、成片出"的 Agent 心智。
- **腾讯 OnSolo**："一个人就是剧组"的 AI 短剧平台。
- **LiblibAI 2.0 / LibTV**：生图+视频+特效一体，一句话从剧本到成片的全自动拍片。
- **可灵 Kling 3.0**：主打多镜头影片生成。
- **Sora Storyboard / Runway Gen-4**：以时间线/故事板为第一公民的专业工作区。

**行业共识心智**：①对话式 Agent 当导演，人当监制；②先锁一致性（角色/场景/锚定图）再开拍；③分镜是结构化数据表不是一段提示词；④分步产物+选项卡确认，人在关键节点拍板；⑤分镜级并行生成+实时进度；⑥时间线只装被批准的候选。

## 三、差距诊断：我们有什么、缺什么

### 可以保留的底子（当初路线图押注 Flova 参考是对的）

- 域链 Project → SkillRun → Plan → AssetVersion → Shot → Job/Attempt → Candidate → TimelineClip → Export 完整且持久化，天然支持导演台所需的一切状态；
- SkillRun 就是声明式 DAG + 审批门 + 预算上限——与 H3 SKILL.md 是同一哲学的两个实现；
- 审批指纹、预算守卫、结算守卫、恢复/补偿、幂等 outbox 这些"平台可靠性层"行业里多数竞品反而没有做好。

### 必须重构的（表达层与数据深度）

| # | 缺口 | 现状 | 目标 |
|---|---|---|---|
| G1 | 信息架构 | 两套表单拼一页 | 单一导演台工作区（见四） |
| G2 | 一致性锁 | 仅素材绑定 | 角色卡/场景卡/锚定图实体 + 锁定状态机 |
| G3 | 分镜深度 | 用途/时长/提示词/运镜 | 六列镜头表（连续性衔接/锚点/Hook/每秒指令/音轨） |
| G4 | 创作质量门 | 仅预算合规预检 | 六项自检引擎（可计算的规则校验） |
| G5 | 交互范式 | 表单提交 | Agent 问询 Gate + 分步产物 + 选项卡确认 |
| G6 | 过程可见 | 生成记录列表 | 分镜级并行进度 + 流式状态 |

## 四、目标形态：薯包导演台（Director Workbench）

```
┌────────────────────────────────────────────────────────────┐
│ 项目切换 ▾   ·   保存状态 · 积分余额   ·   [预检] [导出]    │
├──────────┬─────────────────────────────────┬───────────────┤
│ 资产/一致 │      中央画布（双模式）          │  导演助手      │
│ 性库(左栏)│  ┌─ 分镜板模式: 镜头卡片墙 ─┐    │  (右栏)       │
│ ├ 素材    │  │ S01 8s ●已批  S02 6s ◐候选 │   │ · 启动问询     │
│ ├ 角色卡🔒 │  │ S03 10s○草稿 …           │    │   (一次性Gate) │
│ ├ 场景卡🔒 │  └─ 时间线模式: 已批准剪辑轨 ┘   │ · 本步产物     │
│ ├ 锚定图  │                                │   展示+选项卡   │
│ └ 音乐    │  [镜头详情: 六列表格编辑器]        │ · 自检报告     │
├──────────┴─────────────────────────────────┴───────────────┤
│ 时间线: S01▶ S02▶ S03▶ …  总时长 24s  预算 186/300 积分     │
└────────────────────────────────────────────────────────────┘
```

- **左栏=一致性库**：素材、角色卡（锁定后带 🔒 与"改动将作废下游"警告）、场景卡（含连续性地标）、锚定图、音乐——全部落到既有 AssetVersion 体系，新增卡片类型与 locked 状态。
- **中央画布双模式**：分镜板（创作期，看六列摘要卡）⇄ 时间线（交付期，只装已批准候选）。数据就是现有的 shots + timelineClips，换的是呈现。
- **右栏=导演助手**：承载启动问询 Gate、每步产物展示、选项卡确认（锁定并继续/重新生成/调整）、自检报告。技术上接既有 SkillRun 步骤与审批门——把"步骤推进"从隐藏 API 变成对话式可见过程。
- **底部时间线**：现有 timelineClips 直接映射。
- **六列镜头表编辑器**：shot schema 扩展 continuityLink / referenceAnchors{landmark,positions,exits,lighting} / hookType(受控词表) / perSecondDirectives[5要素] / audioTrack；存储为 shot 的 JSON 字段（已有 direction_json 先例），UI 渲染为结构化表格而非文本框。
- **自检门引擎**：六项规则全部可计算（正则/计数/跨行比对），挂进现有 preflight 体系成为"创作质量 preflight"，与预算 preflight 并列，输出可读的自检报告戳。

## 五、落地路线（每步独立可用、可暂停、不推翻已有可靠性层）

| 阶段 | 内容 | 复用 | 新建 | 出口证据 |
|---|---|---|---|---|
| R1 骨架 | 三栏导演台壳 + 双模式画布 + 现有功能重新归位 | 全部 store/routes | 新布局组件 | 截图对比 + UI 测试 |
| R2 一致性锁 | 角色卡/场景卡/锚定图 + 锁定状态机 + 下游作废联动 | AssetVersion、图像生成 | 卡片实体与锁定迁移 | 锁定→改动→stale 链路测试 |
| R3 六列镜头表 | shot schema 扩展 + 结构化编辑器 | shot JSON 先例 | 六列 UI + 校验 | 表格读写测试 |
| R4 自检门 | 六项规则引擎并入 preflight | preflight 体系 | 规则引擎 | 六项规则单测+失败样例 |
| R5 导演助手 | 启动问询 Gate + 分步产物+选项卡确认 | SkillRun 步骤/审批门 | 右栏对话 UI | 问询流 E2E |
| R6 并行与流式 | 分镜级并行生成 + 进度流 | job/outbox/attempt | SSE/WebSocket 进度 | 30 镜并发压测记录 |

R1-R2 解决"乱"；R3-R4 解决"浅"；R5-R6 解决"慢"。每个阶段结束时产品都完整可用，不存在半成品期。

## 六、商业化对齐

- 导演台直接服务两类付费场景：电商产品广告（对齐 H3 极简产品广告技能：锚定图+节拍分镜+画面内英文文案规范）与短剧/剧情号（对齐小云雀/OnSolo：剧本→分镜→并行成片）。
- 一致性锁是付费续用钩子：角色/场景资产沉淀越久，迁移成本越高，天然提升留存。
- 计费继续按成功交付秒数/成片，预算上限+审批门保证"预授权-结算-释放"商业模型不变。
