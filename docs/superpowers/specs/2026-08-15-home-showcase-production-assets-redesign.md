# 首页生产案例展示重做设计

日期：2026-08-15  
状态：已获方向批准，等待书面规格复核  
范围：首页电商生图、万物上身和自由创作中的案例展示区

## 1. 目标

把当前依赖多张窄卡片拼接的案例展示改成与真实交付物一致的展示方式，并以用户提供的图 2、图 6、图 7 为明确视觉基准：

- 商品套图右侧只展示一张完整的 1:1 合成成片，左侧说明保留。
- 商品套图案例由薯包正式生产链路完成两阶段生成，展示结果能够代表用户实际可获得的能力。
- 商品套图和万物上身顶部能力缩略图使用与容器比例匹配、内容完整且有视觉吸引力的素材。
- 万物上身两张轮播图分别表达“商品到多角度结果”和“商品加参考模特到上身结果”，不裁切输入或人物。
- 社媒封面固定为小红书、B 站、抖音三平台的对称构图，保持各自原生比例。

本次不是局部修补 `object-fit`。展示资产、目录契约、组件结构、响应式布局、放大交互和生产生成验证必须一起完成。

- `src/pages/EcCanvas/` 下当前未提交的 Canvas 改动。

- `RTK.md` 与 `.superpowers/sdd/progress.md` 中尚未归属本任务的并发改动。

本任务预期只修改：

- `src/pages/Home/ec/EcommerceWorkbench.jsx`
- `src/pages/Home/Home.css`
- `src/pages/Home/VisualCreationMode.css`
- `src/pages/Home/productionCaseCatalog.js`

若实现时发现必须跨入 AI 视频或 Canvas 边界，应停止该项，不通过扩大修改范围解决。

## 3. 方案选择

### 3.1 未采用：只调整 CSS

只调整宽高、`object-fit` 和卡片位置无法产生图 2 所示的完整合成成片，也无法消除多种原生比例被同一网格强行容纳的问题。

### 3.2 未采用：本地拼接全部展示图

本地拼接可以精确控制布局，但商品套图最终成片不再是正式生产模型的真实结果，不能满足“展示即实际能力证明”的要求。

### 3.3 采用：生产资产链与比例专用组件

商品套图使用两阶段正式生成；万物上身复用经过生产验证的完整输入和结果资产，通过专用横幅结构呈现；社媒封面按平台原生比例建立专用三列构图。该方案同时满足真实性、版式可控性、成本可控性和长期维护要求。

## 4. 商品套图

### 4.1 两阶段生产生成

第一阶段生成一套统一的 3:4 商品详情视觉，商品为当前珍珠白与香槟金真无线耳机。套图至少覆盖以下画面职责：

1. 品牌与商品主视觉。
2. 模特佩戴或使用场景。
3. 声学结构或产品爆炸细节。
4. 通勤、会议或居家等真实使用场景。
5. 续航、降噪、通话或佩戴等功能详情。

所有页面必须保持耳机、充电盒、颜色、金属装饰和结构一致。只使用可确认的卖点，不编造认证、价格、参数或品牌背书。视觉参考图 3 的奶白与香槟金体系、克制中文、留白和详情页叙事，但不得依赖一张白底图支撑整套质感。

第二阶段把第一阶段交付的稳定资产作为参考，生成一张 1:1 合成成片。构图参考图 2：上方为多张竖向详情面板，中央为放大的产品与充电盒，使用柔和光轨串联信息，右下角保留少量能力卖点。最终成片必须是一个独立、可持久访问的生产结果，不在浏览器中临时拼接。

### 4.2 失败与计费处理

- 每阶段使用独立且稳定的幂等请求键，并保存任务 ID、提示词、资产地址与结算结果。
- 第一阶段没有得到完整稳定资产时，不提交第二阶段。
- 第二阶段失败时复用第一阶段稳定资产，不重新生成第一阶段。
- 已有供应商图片时，质量意见只能用于人工判断或下一次明确重试，不自动再次调用生图供应商。
- 提交重试前先核对任务、供应商资产和钱包结算，避免重复扣费。
- 生产结果下载到项目前必须验证 HTTP、图片解码、像素尺寸和预期比例。

### 4.3 页面展示

`ProductSuiteShowcase` 保留左侧标题、说明和现有整体视觉语言。右侧删除商品母图、箭头和多卡片结果，改为单一成片按钮：

```text
┌──────────────────────────────────────────────────┐
│ 真实套图说明             ┌─────────────────────┐ │
│ 标题与简述               │                     │ │
│                          │  1:1 最终合成成片    │ │
│                          │  完整显示，可放大    │ │
│                          │                     │ │
│                          └─────────────────────┘ │
└──────────────────────────────────────────────────┘
```

成片使用 `contain` 完整显示，容器比例与图片一致，不允许裁掉边缘面板。点击图片打开现有键盘可访问的放大弹窗；Escape 关闭。单张展示不再显示左右切换按钮或“使用方向键切换”提示。

### 4.4 顶部能力缩略图

商品套图的三张扇形缩略图固定表达：

- 产品结构或爆炸图。
- 模特佩戴使用图。
- 商品真实场景图。

不得使用白底主图、透明 PNG 素材或简单产品抠图。目录为顶部缩略图提供独立资产数组，不再默认截取商品套图案例的前三项。

## 5. 万物上身

### 5.1 顶部能力缩略图

顶部三张图使用横向或接近 4:3 的展示专用素材。人物、服饰和主要动作必须在缩略图内完整可辨，不能直接把 9:16 长图放入横向框再裁切。

### 5.2 轮播一：商品到多角度成片

复刻图 6 的信息关系：完整服饰套装在左，转换箭头居中，四张同一模特、同一服装、同一街景的正面、动态、侧面和背面结果在右侧扇形展开。

- 左侧素材按完整原生比例显示，帽子、外套、上衣、裤装、包袋和鞋履不得缺失。
- 右侧人物至少从头到脚完整可见，不用固定高度裁切长图。
- 中央结果卡视觉权重最高，两侧卡片轻微旋转，内容本身不被裁掉。
- 整个关系在一个连续横向展示面内完成，不再使用若干宽高不一致的小卡框拼装。

### 5.3 轮播二：参考模特精准上身

复刻图 7 的信息关系：完整服饰套装、完整参考模特和完整上身结果从左到右排列，中间分别使用加号和方向箭头表达关系。

- 输入商品、参考人物与结果都完整显示。
- 三个内容区根据原图比例分配宽度，不用同一个固定框。
- 最终上身结果视觉权重最高。
- 两张轮播保持相同外框高度和稳定布局，切换时页面不跳动。

轮播继续支持自动切换、手动圆点选择、减少动态偏好以及整张内容放大。放大查看以当前轮播的完整横幅为单位，避免用户只能逐张查看而看不到输入与结果关系。

## 6. 社媒封面

第二组社媒封面固定使用以下顺序与构图：

```text
       小红书 3:4          B站 16:9          抖音 9:16
          /              ─────────             \
         /                 居中主图              \
   左向内倾斜                                右向内倾斜
```

- 小红书在左、B 站在中、抖音在右。
- 小红书和抖音拥有相同的显示高度与视觉重量，形成对称关系。
- B 站使用原生横图比例居中，不进入上下两行网格。
- 三张图的框严格跟随图片比例，图片使用完整显示，不产生左右留白或主体裁切。
- 桌面端允许轻微重叠形成扇形；移动端缩小间距和旋转角度，但保持顺序和对称关系。

第一组包含公众号的社媒案例保持自身资产内容，但复用同一条原则：框随图、原生比例、完整显示。不得用第二组的硬编码尺寸破坏第一组。

## 7. 资产与目录契约

`productionCaseCatalog.js` 为展示用途增加明确角色，而不是依赖数组位置：

- 商品套图：`sourceDetails`、`finalComposite`、`selectorPreview`。
- 万物上身：`source`、`reference`、`result`、`selectorPreview`。
- 社媒封面：资产保留平台标识或稳定 ID，由布局按平台语义定位。

所有新生产资产同时生成轻量缩略图。卡片和顶部缩略图优先加载缩略图，放大弹窗加载原图。目录中的比例必须与实际像素比例一致；测试发现不一致时直接失败。

## 8. 响应式与交互

- 1440px：完整横向叙事，商品成片和万物上身关系一眼可读。
- 980px 左右：缩小展示资产，不改变顺序，不通过裁切腾空间。
- 390px：说明区与展示区上下排列；商品成片保持正方形；万物上身横幅整体按比例缩放或采用等价紧凑布局；社媒三平台仍保持左中右语义。
- 所有可放大图片使用真实按钮元素，具有清晰 `aria-label` 和键盘焦点。
- `prefers-reduced-motion` 下停止自动轮播和位移动效。
- 动态内容不得改变展示框的稳定高度，避免页面切换跳动。

## 9. 验证

### 9.1 自动测试

- 商品套图目录必须恰好提供一个 `finalComposite`，且比例为 1:1。
- 商品套图展示 DOM 不再包含来源卡、箭头和多结果卡。
- 商品套图顶部三张缩略图的语义分别为结构、使用、场景，且均不是白底素材。
- 万物上身两张轮播的角色、顺序和结果数量符合设计。
- 社媒第二组的语义顺序为小红书、B 站、抖音。
- 目录声明比例与图片实际像素比例一致。
- 放大、关闭、手动切换和减少动态模式有契约测试。

### 9.2 浏览器验收

在 1440px、980px 和 390px 下逐项检查：

- 无横向页面溢出、重叠文字或坏图。
- 商品套图最终成片完整显示，点击可放大。
- 顶部缩略图没有白底图，且人物与商品没有被明显裁断。
- 万物上身两张轮播与图 6、图 7 的输入到结果关系一致。
- 所有人物和商品完整，框与图比例一致。
- 社媒封面顺序、对称关系和倾斜方向正确。
- 控制台无错误，所有可见图片完成解码。

### 9.3 生产链路验收

- 第一、第二阶段任务均可在生产任务与账务记录中追踪。
- 每个成功任务交付稳定资产，刷新后仍可访问。
- 失败重试不重复结算，不因质量意见自动新增供应商调用。
- 全量测试、生产构建、资源契约和公开审计通过。

## 10. 发布

实现、测试和独立复审完成后，只使用 `scripts/deploy-production.ps1` 发布。部署脚本负责部署锁、备份、构建、真实电商验证、Canary、健康检查和失败回滚。上线后再次完成桌面与移动端浏览器验收，并记录版本、任务 ID、测试数量、Canary、PM2 和公开健康结果。

本任务不触发真实视频生成。
