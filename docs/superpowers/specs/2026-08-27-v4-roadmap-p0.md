### D4. handle 7.8px 太小 + 80px 重叠 🟡 **半入库,需补 3 件事,升 P0 增量**

**V3 数据证据** (A06 实测):
- text 节点 source handle 实际尺寸 **7.8x7.8 px** (A06 §6.3)
- + extension handle 是 **80x80 px** (`.h-20.w-20`)
- 拖拽点稍微偏一点会命中 + handle,**它会创建新 command 节点而不是连线**
- 第 1 次尝试 32s 内 8 次 pointermove 滑过 svg/h-20 w-20/node-handle-plus-right,**没有产生新连线** (静默 no-op)
- 关闭网格吸附 toggle 后仍无 snapline (A05 §5.6)

**当前入库状态** (W1 4b4ab2b0):
- `.vcb-handle` CSS L401-402: `width: 8px; height: 8px;` (比 TapNow 7.8px 仅大 0.2px,**基本同尺寸问题**)
- 4 角 resize handle (`.is-tl/tr/bl/br`) 已分层
- `pointer-events: auto` 已加
- hover 显形 0.85 opacity + scale 1.4
- transition 120ms ease

**未补 (V3 A06 §6.8 启示 1,2,3)**:
1. **handle 应该更大** (薯包 v2 应 12-16px,目前 8px)
2. **无效释放应该有反馈** ("红色无效提示 + 抖动",目前静默 no-op)
3. **+ handle 与 connection handle 视觉分离** (目前 + handle 仍是 80px 覆盖在 handle 旁边)

**实现成本** (P0 增量):
- handle 尺寸 8px → 12px (CSS 1 行 `width/height: 12px;`,定位同步调整 4 行)
- 无效释放反馈: react-flow `onConnectStart`/`onConnectEnd` 监听 + 抖动 class + 红色 outline (CSS 30 行 + JSX 20 行)
- + handle 与 connection handle 视觉分离: 改 + handle 位置 (从 cover 改为右下角) + 显式图标 (CSS 20 行 + JSX 10 行)
- 测试 ~ 8 用例 (handle 命中/无效释放反馈/视觉分层)

**用户收益**: **画布核心交互** (A06 是"创建连线"的主路径),3 站都有问题,薯包抢先修 = 显著差异化

**V4 决策**: **升 P0 增量** — 改 handle 尺寸 + 失效反馈 + 视觉分离,3 件套

### D5. 拖拽 8px 损失 (浏览器 pointerdown 消耗) 📉 **P3 (低优先),非用户感知问题**

**V3 数据证据** (A05 实测):
- 1 步拖拽 (50px 请求) → 42px 实际 (损失 8px, 16%)
- 3 步 (180px) → 156px (损失 24px, 13%)
- 拖到边缘 (-278px) → -254px (损失 24px, 9%)
- 自动化测试每 ~5s 一次 pointermove,1 步拖拽总耗时 32 秒
- 8px 损失假设 = 浏览器驱动 pointerdown 1-2 像素 + react-flow 内部按下确认消耗

**用户实际感知**: **不感知** — V3 A05 §5.3 末注: "真用户拖动 50ms 内 5-10 个 move events,自动化测试的 5s/次根本测不出瞬时反馈" (A06 §6.8 #4 同注)

**motion 库评估**:
- motion (framer-motion) 集成 ~80KB gzip
- 解决的是"用户感知到的瞬时反馈",8px 损失自动化可见但用户不感知
- react-flow 内部已用 motion 处理节点创建/拖拽的 spring 弹性 (V3 §2.2 推断)
- 加 motion 库**没有实际收益**,只是给测试报告好看

**实现成本**: **不实现**
- 加 motion 库 = 80KB gzip (PWA 性能损耗)
- 8px 修正 = 0 (损失在自动化测试而非用户感知)

**用户收益**: 0 (用户不感知)

**V4 决策**: **P3 (低优先) / 不升级** — 8px 损失是自动化假象,真实用户不感知

### D6. quantv 中文 a11y (aria-label) 🟢 **P0 极低成本,直接抄**

**V3 数据证据** (A03-A08 batch JSON §interpretation):
- quantv connector `<BUTTON aria-label="从此处拉出连线">` — 3 站唯一显式中文 a11y
- "Connection drag did not create new connection. quantv connectors are BUTTON elements with explicit aria-labels (从此处拉出连线) — they expect a click+drag interaction but the test failed (likely the drag didn't release on a valid target)"

**当前入库状态** (W1 4b4ab2b0 已部分加 aria-label):
- `aria-label="画布工具"` (topbar)
- `aria-label="节点快捷操作"` (mini-toolbar)
- `aria-label="画布缩放"` (zoom slider)
- `aria-label="中央无限画布: 拖拽摆位卡片, 框选素材浮出生成条, 连线表达续写与首尾帧关系"` (主区)
- `aria-label="导演检查器"` (inspector)

**未补**:
- connector (handle) 没有 `aria-label="从此处拉出连线 / 连到此节点"`
- 边 (edge) 没有 `aria-label="从 X 节点到 Y 节点的续写链"`

**实现成本** (P0 极低):
- handle 4 角加中文 aria-label (4 处 ~ 8 行 JSX)
- 边 aria-label 动态生成 (1 处 ~ 10 行)
- 测试 ~ 3 用例 (handle aria-label 命中/edge 链可读)

**用户收益**: 屏幕阅读器用户可识别画布结构,符合 WCAG 2.1 AA。是"无障碍合规"低成本高回报项

**V4 决策**: **升 P0** — 极低成本 (< 25 行代码 + 3 测试),直接抄 quantv

### D8. TapNow + liblib 共享 React Flow + 0.3s spring CSS ✅ **已 P0 入库,无需升级**

**V3 数据证据** (V3 主报告 §1 §2):
- TapNow / liblib 都用 React Flow (节点前缀 text-/i- + 同一 handle class `.node-handle-plus-{left,right}`)
- quantv 是自研 canvas,不在 React Flow 阵营
- 通用 spring-bounce: 0.3s cubic-bezier(0.34, 1.56, 0.64, 1) (V3 §2 §2.2)
- 节点创建 = spring 弹性 (liblib 派生 ~300ms)

**当前入库状态** (W1 1ee0ee1a step1 + 4b4ab2b0):
- `chore(video-canvas): adopt @xyflow/react v12 as canvas engine foundation (W1 step1)` — 已加 package.json
- W1 (4b4ab2b0): hover scale `transform: scale(1.04)` + selected lift `translateY(-3px)` + 0.12s ease (var(--duration-fast))
- mini-toolbar 4px 6px padding + gap 2px
- context menu portal 浮层
- **未直接抄 0.3s spring cubic-bezier(0.34, 1.56, 0.64, 1)**,薯包用了 0.12s ease

**实现成本** (可选增量,非必须):
- 加 spring-bounce CSS 变量 `var(--ease-spring)` = `cubic-bezier(0.34, 1.56, 0.64, 1)`
- 节点创建/选中过渡用 spring (CSS 3 处 + 测试 2 用例)
- 约 10-15 行代码

**用户收益**: 节点创建/选中更"弹",与 TapNow/liblib 视觉一致。是行业最佳实践,非"抢先做"差异化

**V4 决策**: **不升级 (已 P0)**,spring-bounce 锦上添花属 P1 增量
