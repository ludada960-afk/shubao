## A. 对标证据

### A1 两支爆款视频的形态结论（前任逐帧拆解，维持有效）
- **A1《会拍片的AI导演》(CreativeOS 形态)**：对话流主干+右侧工件区；**导演决策卡**把视角/风格/镜权重做成显式选项，确认后才付费；定妆照强制带元数据卡（模型/尺寸/比例/来源）；批量生成一句话触发。
- **A2《百万爆款AI大片工作流》(Flora 式节点画布)**：几十个缩略图即节点的画布管资产生产与多模型调度，连线即数据流；**首帧参考 i2v 是用得最多的生视频方法**；分镜图即每镜首帧；候选打勾汇入下游；剪辑在外部时间线完成。
- **共同链条**：意图/剧本 → 资产设定（人/货/场定妆）→ 分镜（每镜一张首帧）→ 首帧 i2v 逐镜生成 → 时间线合成导出。头部作者只是用对话 Agent 或节点画布两种壳编排同一条链。

### A3 裁定（v2，替代前稿）
**任务链照即梦，承载形态照 PixVerse 画布，导演交互照 CreativeOS 决策卡。**
1. 链路层：带货是量产任务，「商品+脚本→标准化成片」路径最短，即梦链条（脚本/分镜→逐镜→成片管理）仍是最优骨架，且与我们 Project→SkillRun→Plan→Shot→Job→SelectedVersion→TimelineClip 领域链零冲突（roadmap Flova 参照）。
2. 形态层（本版关键修正）：前稿判 PixVerse 为「模板特效社区流、无画布」已失实——其官网现以**画布节点工作流**为核心叙事并配电商专用入口。加上 A2 证明头部作者真实作业面就是无限画布、Flora/Krea 已验证范式，**「无限画布内完成一切」不是非主流，而是 2024-2026 的确定趋势**；用户方向成立，应把画布从「上游资产加工层」升格为视频创作主区，EcCanvas 经验直接复用。
3. 能力层：可灵首尾帧/多图参考/数字角色为单镜生成天花板，海螺运镜指令降级为 chips，均作画布节点属性吸收，不作主结构。

## B. 视频板块重构蓝图

### 页面信息架构（文字版）
```
视频板块
├─ 项目列表页（成片管理）：封面/状态/版本/积分耗时；新建→工作台
└─ 创作工作台（三栏+底抽屉，取代瀑布三段）
    ├─ 顶栏：项目切换｜PLANNING/LIVE 开关（规划不扣费）｜积分｜导出
    ├─ 左栏·输入与方案(~300px)
    │   ├─ 素材带入：素材库选择器+「从 EcCanvas 发来」；保留「产品图N」客观命名
    │   ├─ 意图输入：一句话目标+卖点/时长/比例/口播音色
    │   └─ 方案卡 Plan：N 镜分镜逐镜可编辑；积分预估区间+【批准生成】审批门(VID-P1-04)
    ├─ 中央·无限画布（主区，react-flow 承载，复用 EcCanvas 交互资产）
    │   ├─ 节点四类：素材卡(assetId 引用)/镜头卡(shot)/候选卡(job)/成片卡
    │   ├─ 框选素材组→浮出生成条：智能成片/首尾帧/爆款重构/多图参考＋运镜chips＝老鱼AI动线
    │   ├─ 镜头卡间连线=续写/首尾帧链/转场（依赖可视化，对应 A2 数据流）
    │   └─ 候选卡就地并排对比，点选回填；失败就近错误+重试
    ├─ 右栏·导演检查器(~340px 抽屉)
    │   ├─ 决策卡队列：视角/风格/节奏/镜权重，确认才产生付费任务
    │   ├─ 任务事件流：按镜分组排队/成败/扣费结果
    │   └─ 改稿对话：自然语言微调当前镜（海螺运镜词作快捷 chips）
    └─ 底部·时间线抽屉：已选版本按镜序 trim/排序/换候选；音轨+字幕轨；【导出】→成片详情(版本对比/发布/remix)
```

### 组件清单
ProjectListPage / AssetPickerDialog / IntentForm / PlanCard(ShotPlanItem×N、CostBadge、ApproveGate) / CanvasBoard(AssetNode·ShotNode·CandidateCard·LinkEdge·SelectionToolbar·CameraMoveChips) / DirectorPanel(DecisionCardQueue·TaskEventStream·ChatTweaks) / TimelineDrawer(TimelineClip·TrimHandle·AudioTrack·SubtitleTrack) / ExportDialog / ProjectDetailPage(VersionDiff·PublishRemix)；MentionPromptField、计价报价链路原样复用。

### 与无限画布/素材库联动
- EcCanvas 与视频画布共享同一套节点交互资产；套图/万物上身产物一键发往视频项目入素材库并绑指定镜头首帧；
- 素材以 AssetVersion 语义绑进 Plan（人/货/场/音四角色），源版本变更向下提示不静默覆盖；一致性锁(lockAt)徽标化呈现于节点上；
- 成片经 gallery 发布走「过程预览→只读项目→clone/remix」闭环（TapNow 模式）；积分 hold/settle/release 沿用账务底座。

### 分期实施
- 第 1 期：三栏壳+左栏方案卡审批门+中央画布最小集（素材/镜头/候选三类节点、框选生成四模式、候选回填），单镜流先通；瀑布下线留一版 fallback。
- 第 2 期：决策卡队列+改稿对话+任务事件流；镜头连线（续写/首尾帧链）；时间线 trim/音轨/字幕/导出；成片详情页。
- 第 3 期：Canvas 双向投递与 AssetVersion 传播、Marketing Hub 式「商品图→套路成片」引导流、模板社区与 remix 发布闭环。

## C. 瀑布三段式问题清单与保留项

### 问题（为何必须换）
1. 上输入/中流程/下导演台纵向堆叠不对应当前任何主流 IA；中段是任务日志而非可操作对象，沦为滚动黑洞，三段各自滚动上下文断裂。
2. 导演台沉底=决策滞后于付费：先花钱后看方案，违背生成前方案审批红线（VID-P1-04 所补之洞）。
3. 缺少「镜头×候选」空间结构与依赖可视化：分支树纵向滚动成本高，只能嵌套列表硬塞。
4. 输入区纯表单（画幅/声音网格），无框选拖拽等直接操纵；与素材库/EcCanvas 无常驻联动入口，资产带入靠重复上传。
5. export/replay manifest 能力已在底层备好，但无「成片卡」概念，交付感弱于竞品作品列表。

### 保留项（资产，勿弃）
1. 一致性锁定(lockAt+批准版本)：领先多数竞品，画布化后是核心卖点；
2. PLANNING/LIVE 规划不扣费模式：转画布顶栏开关；
3. 预检/skill checkpoint/自检：收编进检查器卡片，不再作阶段门闩；
4. 「产品图N」客观命名与商品图×参考图语义：迁入左栏素材带入卡；
5. 就近错误+deliberate retry、积分预估、排队可视化：收编右栏任务流与方案卡；
6. provider-neutral 底座、队列、账务(hold/settle)、恢复机制、export/replay manifest：全保留，本次仅换表现层。

### 迁移验收指标
一条「商品图→圈选→出候选→连镜→导出」全程不离开画布工作台；旧瀑布入口保留一个版本期后下线。
