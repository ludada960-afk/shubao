# 生产案例与创作体验重设计规格

## 1. 决策摘要

- 万物上身与自由创作的展示案例必须来自薯包真实生产链路。案例制作同时承担端到端验收，不使用与线上能力无关的外部样图冒充结果。
- 先修复本地输入、计费、幂等、布局和结果契约，再发布候选版本并逐项运行真实案例，禁止在已知错误上浪费积分。
- 每个案例只提交一次初始真实任务。失败后先核对任务、供应商资产、冻结/结算/释放记录；仅在确认不会重复扣费后，使用同一幂等键执行 deliberate retry。
- 本轮不触发真实视频生成。视频工作台只做无付费的交互、文案、模型标识和接口契约验收。
- 12 个 `server/extension_tasks/*.json` 删除项、`.tmp/` 和 `scripts/diagnose-recent-ecommerce-jobs.cjs` 属于用户运行态，始终排除在提交之外。

## 2. 真实案例矩阵

### 2.1 电商入口与万物上身

- 首页“商品套图”使用真实电商生成结果组成宽幅、展开式作品序列，内容覆盖主图、场景图和细节图，左右都有视觉重量，不保留大面积无意义空白。
- 首页“万物上身”使用真实商品、参考模特和上身结果组成宽幅叙事，明确表达输入与输出关系。
- 万物上身展示区固定为“商品与穿搭 + 参考模特 + 上身结果”。三张图按各自真实宽高比展示，不裁切主体、不拉伸，不通过错误缩放隐藏模型生成内容。
- 加号与方向符号使用同一套原创视觉语言：紧凑、清晰、有方向性，但不复制竞品资产。
- 点击任一案例图打开同组灯箱；灯箱支持可见的上一张/下一张按钮、键盘左右键、Esc 关闭和边界循环。
- 商品颜色/材质、图案标识、人物与场景一致性不再作为可取消选项。它们改为三个强制生成原则，并在展示区以带有连接关系和状态反馈的优势组件呈现。文案不得作无法验证的绝对承诺。
- 商品、模特和场景上传槽位降低文字密度、增加内边距，保留角色、数量、状态和错误信息，但不重复解释显而易见的拖放动作。

### 2.2 自由创作四套能力

四套案例都必须经过当前生产图片生成接口，并能追溯对应意图、模型、任务 ID、积分结算和稳定资产地址。

| 能力 | 真实案例内容 | 首屏需要一眼表达的价值 |
| --- | --- | --- |
| 自由创作 | 同一主题的主体、场景和构图连续演化 | 从一句想法发展出可继续编辑的完整视觉 |
| 海报设计 | 包含可读中文标题、层级和行动信息的成品海报 | 不是纯背景图，而是能直接理解用途的海报 |
| 社媒封面 | 同一热点题材适配小红书、公众号、B 站/短视频封面 | 平台比例、标题密度和视觉重心随渠道变化 |
| 品牌主视觉 | 同一品牌资产延展为主 KV、横幅和方形传播图 | 保持核心识别，同时适应多尺寸传播 |

- 案例主题与左侧能力说明必须互相印证；切换后用户无需阅读长说明就能理解输入、输出和用途。
- 社媒封面不能继续使用无文字的泛化图片。若生产模型无法稳定生成准确文字，必须把该失败作为产品问题修复，不能用静态假案例掩盖。
- 案例可由多个真实生产结果在前端进行透明层叠、比例适配和顺序编排；编排不得改变或伪造模型实际交付内容。
- 四套能力的来源说明应能追溯 `awesome-gpt-image-2`、本地电商 Prompt-as-Code 技能和社媒卡片技能，但产品界面只展示用户价值，不堆叠仓库术语。

## 3. 统一工作台

- 自由创作复用电商生图已经稳定的上传区、提示词区、底部参数栏、报价和生成按钮结构，不再维护另一套位置与尺寸规则。
- 复用的是组件、状态契约和交互顺序，不是机械复制整页。自由创作保留最多 6 张参考素材、意图专属占位文案和按能力变化的参数。
- 展示说明区和案例视觉区处于同一连续背景图层；不得在渐变背景上再次放置突兀的白色图片底板。
- 所有固定格式控件使用稳定尺寸和响应式约束。桌面与 390px 移动端不得出现文字溢出、按钮漂移或横向滚动。

## 4. 视频入口

- 智能成片、首尾帧、爆款重构的选中项必须同时改变容器、图标、标题、描述和状态标记，选中标题不可保持浅灰。
- 主标题改为“把创意素材变成吸引人的短片”，长度接近原文但避免“可交付”带来的雇佣语境。
- Seedance 使用可识别的纯文字 `Seedance 2.0` 和薯包自有的中性视频模型符号。不得下载后滤镜改造官方商标并宣称规避侵权。
- 本轮仅验证素材、方案、报价、幂等和界面状态，不创建付费视频任务。

## 5. Canvas 交互与图层语义

- 智能分层完成后，容器节点只能表达父子关系和整体选取，不得继承源图 URL、媒体类型或可渲染图片字段。分层结果只渲染拆出的子层，不能在原位再复制一张原图。
- 生成期间，已提交动作的按钮必须显示进行中并不可再次点击；错误持续显示在对应操作附近，允许 deliberate retry。
- 图片节点在资源解码后以自然宽高比校准节点尺寸。容器边界贴合完整图像，不保留由陈旧宽高比造成的上下留白。
- 工具栏保留前部关键动作的文字标签；裁剪、分割、下载、删除等熟悉动作使用图标并提供 tooltip，避免工具栏无意义变长。
- 左键选中图片时显示连接加号及其快捷菜单；用户无需再次点击加号才能看到可派生动作。
- “移动缩放”进入图内聚焦编辑：遮罩非目标区域、显示可拖动对象边界、缩放/旋转控制和取消/应用。
- “图片标注”保留画笔、矩形、箭头、文字、颜色、线宽、撤销、重做、清空、取消和应用，并保证所有控制在当前视口可用。

## 6. 管理后台经营表

后台新增简单的单次经营测算表。每一行至少显示：

- 功能/模型与一次任务交付数量；
- 用户扣除积分；
- 每积分现金收入基准；
- 预计营收；
- 上游真实成本；
- 支付通道费；
- 预计利润；
- 利润率；
- 口径与数据更新时间。

计算口径固定为：

```text
预计营收 = 用户扣除积分 x 当前选择的每积分现金收入基准
支付通道费 = 预计营收 x 支付费率
预计利润 = 预计营收 - 上游真实成本 - 支付通道费
利润率 = 预计利润 / 预计营收
```

- 默认使用当前最低现金售价套餐的每积分收入，作为保守估算；后台允许管理员切换套餐或输入自定义基准。
- 赠送积分、现金购买积分和内测补贴必须分开显示。赠送积分不能算现金营收，其使用成本应计入补贴。
- 表格上方用一句话解释每个指标，下方提供按生成张数/视频时长或 SKU 的计算器。聚合经营指标与单次测算不得混为一张表。

## 7. 真实生产生成与修复循环

1. 用聚焦测试锁定素材角色、宽高比、幂等键、计费状态和案例元数据契约。
2. 完成本地浏览器桌面/移动端验收，确认不产生付费请求。
3. 通过 `scripts/deploy-production.ps1` 发布候选版本，并等待部署内测试、构建、健康、账务、真实电商任务和 Canary 完成。
4. 一次只运行一个计划案例，记录任务 ID、请求幂等键、报价、冻结/结算/释放、上游成本、稳定资产和成品质量。
5. 若失败，先判断是输入、供应商、资产持久化、轮询、质量意见、Canvas 交接还是计费问题；已有供应商图片时禁止自动重新调用生图供应商。
6. 修复并重新发布后，只有在确认未重复结算时才重试同一请求；不得通过新建任务规避失败态。
7. 成功资产进入正式案例目录和模型清单，重新构建并发布；每个案例 URL、宽高比、文字可读性和工作台联动都要被自动检查。
8. 按万物上身、自由创作、海报、社媒封面、品牌主视觉依次执行。不同候选版本不并发生成，确保问题可归因。

## 8. 测试与发布门槛

- 新行为先写失败测试，再做最小实现和聚焦回归。
- 运行完整串行测试、生产构建、`npm run check`、`npm run collab:check` 和 `git diff --check`。
- 使用真实浏览器检查 1440px 和 390px：首页切换、万物上身灯箱、自由创作四模式、视频选中态、Canvas 分层/选中/快捷菜单/聚焦编辑、后台经营表。
- 最终发布仍只能使用 `scripts/deploy-production.ps1`。发布后复核健康、公开审计、资源解码、账务、稳定任务和部署锁。
- 本轮真实付费范围只包括已批准的图片案例；不运行真实视频生成。

## 9. 完成定义

只有以下条件全部满足才算完成：截图中的每个问题都有可操作实现；真实图片案例来自当前生产链路并可追溯；发现的生成、计费或恢复错误已修复；案例已进入正式发布；Canvas 与后台通过实际交互验收；没有重复扣费、未授权视频费用、占位结果或被裁切的展示图。
