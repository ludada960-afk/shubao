# 薯包 AI 视频平台：证据、边界与路线选择

日期：2026-08-15

状态：待产品路线确认

关联路线图：`docs/superpowers/plans/2026-08-14-ai-video-platform-roadmap.md`

## 1. 这份文档解决什么问题

这不是一份“罗列 AI 视频功能”的愿望清单。它用于回答四个可执行问题：

1. 薯包已经有什么，真正缺什么。
2. 哪一家成熟产品适合作为主骨架，哪些产品只适合吸收局部能力。
3. 哪些开源与社区方案可以合法、稳定地复用，哪些只能作为设计参考。
4. 第一阶段该做什么、暂时不该做什么，以及每一步如何证明已经可交付。

证据分为三类：

- **已验证**：来自当前代码、生产验证、官方产品文档或公开产品体验。
- **官方宣称**：厂商公开页面提供，但未进行付费独立验证。
- **公开索引线索**：可确认文章标题、作者与摘要方向，未取得稳定全文；不得当成实现细节的唯一依据。

## 2. 薯包当前能力底盘

### 2.1 已经具备

薯包不是从零开始。当前代码已经有以下可复用底座：

- React/Vite 前端，Express 服务端，SQLite 持久化。
- 项目、不可变版本、父版本、检查点、恢复点和画布会话。
- 作品、回收站、生成资产、电商任务、重试与导出。
- 钱包流水、积分批次、预授权、结算、释放、用量事件和管理后台利润指标。
- 图片、电商、画布和视频的模型/供应商适配层。
- 视频的 `queued -> submitting -> processing -> completed|failed|needs_review` 状态机。
- 视频任务幂等键、启动恢复、路由级熔断、并发与用户公平队列。
- 供应商失败后的积分释放，未知提交结果进入人工复核而不是重复付费提交。
- 图片本地即时预览、对象存储、代理图和响应式图片交付。
- 首页案例的完整配方回填、稳定瀑布流、渐进加载和“做同款”。
- 管理后台按功能、SKU、模型统计成本、营收、理论贡献和失败释放。

### 2.2 当前视频产品的准确定位

现有 `VideoStudio` 是一个较可靠的**单次视频生成工作台**：

- 智能成片、首尾帧、爆款重构三种模式。
- 图片、视频、音频、首帧和尾帧输入。
- 生成前素材分析、镜头节奏、风险和阻塞项确认。
- 模型、比例、时长、分辨率、声音、种子、报价和积分预授权。
- 创建任务、轮询、历史、失败退款提示。

这套能力应该保留并下沉为未来“单镜头生成器”，不应推倒重写。

### 2.3 真正缺口

当前 `video_assets` 与 `video_jobs` 仍是独立的一次性任务数据，尚未成为项目版本体系里的一级对象。缺少：

- 项目级角色、场景、道具、服装、风格、声音和音乐资产及其版本。
- 分镜镜头、镜头依赖、候选版本、选定版本和被下游锁定的版本。
- 可持续编辑的时间线、逐镜头替换和最终导出版本。
- 声明式 SkillRun、步骤 DAG、人工确认点、成本上限和失败补偿。
- 供应商任务事件日志/outbox，避免“供应商已成功但本地结果丢失”。
- 可回看的创作过程、克隆项目和完整“做同款”。
- 低清预演 -> 人工选择 -> 高清交付的成本漏斗。

结论：薯包缺的不是再加几个模型按钮，而是把“一次请求”升级成“可恢复、可复用、可审计的视频项目”。

### 3.1 主骨架选择

**推荐以 Flova/TapNow 的“项目记忆 + 资产/镜头依赖 + Skill 工作流 + 人工确认 + 可回看创作过程”为骨架。**

原因：

1. 与薯包现有项目版本、画布、生成任务、积分和案例系统最吻合。
2. 能把现有一次性视频生成保留为“镜头生成能力”，降低重写风险。
3. 同时覆盖创作、可靠性、复用和商业增长，不只是增加模型。
4. 能自然承接“灵感发现 -> 查看创作过程 -> 做同款/克隆 -> 项目继续编辑”。

局部吸收：

- Runway/Firefly：候选版本、区间重拍和时间线交互。
- Higgsfield/Luma：首帧构图、镜头语言、关键帧和局部修改。
- Google Flow/Dreamina：Agent 向导和用户可复用工作流。
- Vidu/Kling：命名资产、多参考、主体与声音绑定。

## 4. 社媒与实战方法证据

### 4.1 已验证的创作方法

公开视频与案例共同指向以下稳定方法，而不是“写一条更长的提示词”：

- 先拆角色、服装、场景、道具、画面风格和声音资产。
- 先生成并批准资产版本，再让镜头引用已批准版本。
- 先做低成本关键帧/低清镜头，选择后再高清增强。
- 把长片拆成镜头，每个镜头保存目的、时长、景别、运动、引用资产、首尾帧和声音节拍。
- 不满意时只重拍镜头或时间区间，不重做整个项目。
- 将成功流程固化为 Skill，下一次替换主题和资产后复用。

### 4.2 “屿帆AI”公开线索

公开索引可确认该账号至少有以下方向：

- `AI演唱会`：先寻找有传播潜力的方向，再把全过程训练/整理为可复用 Skill。
- `AI视频“噪点”终极解决大法!`：针对大场景噪点、塑料感进行修复，并将有效过程固化为可复用 Skill。
- 公开视频涉及摄像机运动、人物自然说话、节奏、灯光和 Vibe Cutting。

这些内容可用于提炼能力方向：镜头语法、表演/口型、节奏、灯光、连续性、局部修复和 Skill 复用。

边界：目前只取得公开索引摘要和公开视频证据，没有稳定取得微信公众号文章全文。因此不能把文章中未见到的具体步骤伪装成已验证事实；后续若取得用户提供的原文或稳定公开全文，再补充逐条实现映射。

1. 优先采用稳定协议、SDK 和基础设施，不直接搬运竞品产品代码。

3. UI、领域模型、积分和任务可靠性继续由薯包掌控。
4. 每个依赖都必须有版本锁定、替代方案、失败降级和退出策略。

## 6. 三条可选路线

### 路线 A：模型市场 + 强化现有表单

做法：继续在现有 VideoStudio 增加模型、参数、模板和提示词。

优点：交付最快、短期改动小。

问题：

- 无法解决人物/服装/场景连续性。
- 无法保存项目记忆、镜头依赖和候选版本。
- 长视频失败时只能整单重做，成本和退款风险高。
- 案例无法成为可克隆的完整工作流。

结论：仅适合作为底层“镜头生成器”，不适合作为长期产品路线。

### 路线 B：先做无限节点画布与专业剪辑器

做法：直接复制完整节点工作流、多轨时间线和自由画布。

优点：能力上限高、展示效果强。

问题：

- 交互和状态空间过大，容易放大当前可靠性问题。
- 普通电商/内容用户学习成本高。
- 视频上传、代理转码、任务恢复和计费没稳定前，节点越多结果丢失面越大。
- 初期难以形成清晰的成功指标。

结论：不作为第一阶段；画布和时间线应随成熟工作流逐步开放。

### 路线 C：项目/资产/镜头优先的导演工作台（推荐）

做法：以 Flova/TapNow 为骨架，把现有 VideoStudio 下沉为镜头生成能力，先建立项目、资产版本、镜头、候选、时间线和 SkillRun，再逐步增加局部重拍与智能路由。

优点：

- 最大化复用薯包现有项目、画布、计费、供应商和案例系统。
- 将风险限制在单个资产或镜头，失败可局部恢复。
- 可形成“案例 -> 查看过程 -> 克隆项目 -> 再创作”的增长闭环。
- 既能支持电商短片，也能逐步扩展叙事、MV、教程等类型。

代价：必须先做数据迁移、媒体基础设施和任务可靠性，不能先追求花哨功能。

结论：推荐。

## 7. 推荐产品结构

### 7.1 一级导航

- **项目首页**：最近项目、模板、案例、失败/待确认任务。
- **导演台**：项目目标、计划、资产、分镜、生成进度和 Agent 对话。
- **资产库**：角色、服装、场景、道具、风格、声音、音乐；每项有版本和授权信息。
- **分镜台**：镜头卡、依赖资产、首尾帧、候选版本、成本状态和人工确认。
- **时间线**：只接收已选定镜头版本，支持排序、裁剪、替换、字幕、配音、音乐和导出。
- **创作过程**：步骤、提示、模型、参数、输入资产、结果、失败、重试、积分和决策记录。

### 7.2 渐进式交互

普通用户默认看到：

1. 选择模板或描述目标。
2. Agent 生成项目计划和成本区间。
3. 用户确认角色/商品/场景等关键资产。
4. 用户确认分镜。
5. 系统生成低清候选，用户逐镜头选择。
6. 选中镜头高清交付并进入时间线。
7. 导出成片，完整配方可保存为 Skill/案例。

高级参数放在“镜头设置/模型详情”中按需展开，不把模型供应商字段铺满主界面。

### 7.3 领域模型

```text
Project
  -> SkillRun
    -> Plan
      -> Asset -> AssetVersion
      -> StoryboardShot
        -> ShotAssetBinding
        -> GenerationJob -> GenerationAttempt
        -> CandidateVersion -> SelectedVersion
      -> Timeline -> TimelineClip
      -> Export
```

关键约束：

- 下游引用的必须是明确的 `AssetVersion`，不能隐式追随“最新版本”。
- 一个镜头可以有多个候选，但只有一个 `SelectedVersion` 进入时间线。
- 供应商任务只是 `GenerationAttempt` 的实现细节。
- 每次付费提交都有幂等键、预授权、attempt、供应商追踪 ID、结果持久化和结算/释放状态。
- 异步结果回来时，若项目/源资产已删除或版本已失效，应进入隔离/人工复核，不能污染当前时间线。

## 8. 声明式 Skill 的最低契约

Skill 不是一大段 prompt。最低结构包括：

- 输入 schema 与素材类型约束。
- 步骤 DAG、依赖和条件分支。
- 每步的能力需求，不直接写死模型名称。
- 模型路由偏好、允许降级和禁止降级项。
- 成本估计、总预算上限和每镜头上限。
- 人工确认点。
- 输出契约和质量门槛。
- 重试、回滚、退款和失败补偿。
- 版本、作者、许可证、适用场景和测试样例。

首批只做两个经过真实验证的 Skill：

1. 商品广告短片。
2. 对标视频拉片复刻。

不同时铺开大量未经验证的“课程玩法”。社媒方法必须先转成可测试步骤，再进入 Skill 目录。

## 9. 每个方向必须回答的两个问题

| 方向 | 会带来什么问题？ | 怎么做得更好？ |
| --- | --- | --- |
| Agent 自动规划 | 幻觉、遗漏约束、不可控成本 | 结构化计划、预算上限、关键节点人工确认、可解释选模 |
| 多模型接入 | 字段碎片化、质量不一致、供应商锁定 | 能力注册表、统一领域模型、适配器、近期成功率路由和降级策略 |
| 多参考一致性 | 参考越多冲突越大，不能保证服从 | 资产版本、命名引用、参考质量检查、2–4 个互补强参考优先 |
| 无限画布 | 节点膨胀、性能下降、用户迷失 | 项目/分镜为主入口，画布按任务开放，视窗虚拟化和资产清理 |
| 时间线 | 专业工具学习成本高 | 第一版只做镜头排序、裁剪、替换、音轨和导出；渐进展开 |
| 低清预演 | 预演与高清结果可能漂移 | 锁定模型/种子/资产版本，显示漂移风险，保留候选回退 |
| 局部重拍 | 供应商不支持、拼接痕迹 | 能力检测；不支持时降级整镜头生成；转场/光流/音频连续性检查 |
| Skill 市场 | 低质量、侵权、恶意步骤 | 审核、权限沙箱、许可证、版本锁定、成本上限、质量评分 |
| 项目记忆 | 错误偏好长期污染、隐私风险 | 显式可查看/编辑/删除，项目级隔离，敏感资产生命周期和授权记录 |
| 自动结算 | 结果丢失却扣费、重复提交 | 预授权、幂等、outbox、供应商追踪、成功结算、失败自动释放、人工复核 |

## 10. 分阶段实施与验收门槛

### P0：可靠性与媒体底座

交付：

- 统一媒体资产和版本；视频原文件、代理视频、缩略图和元数据。
- 本地即时预览、断点续传、后台持久化和代理转码。
- GenerationJob/Attempt、幂等、outbox/event log、断线恢复、取消、超时、重试和退款。
- 供应商能力注册表、模型路由接口和监控。
- 当前 VideoStudio 迁移到统一项目/资产/任务模型。

硬门槛：

- 同一幂等键不发生重复付费提交。
- 供应商成功结果可在重启、网络中断和回调重复后恢复。
- 失败不结算，未知结果不重提，人工复核可闭环。
- 上传首次本地可见不等待云上传；大文件可续传。
- 管理后台可按供应商/模型/输入类型看到成功率、首帧时间、交付耗时、重试率和每可交付秒成本。

### P1：资产、分镜和基础时间线

交付：

- 资产库和资产版本。
- 分镜卡、镜头资产绑定、候选版本和选定版本。
- 商品广告、图片成片、首尾帧成片三个向导模板。
- 低清候选、逐镜头确认和仅重试失败镜头。
- 基础时间线：排序、裁剪、替换、音频、字幕、导出。

硬门槛：

- 任一镜头可追溯到输入资产版本、提示、参数、模型、attempt、积分和选择记录。
- 替换资产不会静默改变已锁定镜头；必须显式重算受影响镜头。
- 项目刷新/重启后仍能恢复到相同分镜和时间线。

### P2：Skill、项目记忆和案例闭环

交付：

- 声明式 SkillRun 执行器。
- 商品广告短片、对标视频拉片复刻两个实测 Skill。
- 项目记忆的查看、编辑、删除和版本。
- 案例“查看创作过程/只读预览/克隆项目/做同款”。

硬门槛：

- 同一 Skill 版本和相同资产版本可重放，差异可解释。
- 克隆不会共享原用户私有资产或权限。
- Skill 的每一步有成本上限、超时、重试和补偿。

### P3：高阶编辑与智能路由

交付：

- 区间重拍、延长、跟踪替换、动作控制和多角色绑定。
- 基于能力、质量、延迟、成本和近期成功率的自动路由。
- A/B 候选、用户选择学习、团队协作和 API/CLI。

硬门槛：

- 不支持局部编辑的供应商有明确整镜头降级。
- 自动路由的质量/成本/延迟优于固定默认模型，并可人工覆盖。
- 用户偏好学习可解释、可关闭、可清除。

## 11. 明确不做的事

- 不承诺“任何输入都 100% 无 bug、100% 一致、100% 成功”。以可测 SLO、自动补偿和人工复核替代虚假承诺。
- 不在可靠性底座完成前大量接入新模型。
- 不把供应商专属参数直接写入核心项目模型。
- 不把所有摄影、模型和编码参数默认展示给普通用户。
- 不自动触发付费视频生成来“证明流程”。真实生产验证必须有预算、样例、预期产物和明确授权。
- 不把公开索引摘要、营销页上限或未核验社媒课程写成已验证实现事实。

## 12. 需要确认的产品决策
