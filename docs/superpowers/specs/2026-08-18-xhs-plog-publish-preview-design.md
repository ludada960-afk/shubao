# 小红书图文与 Plog 成品展示重构设计

## 设计状态

- 状态：已获用户确认，采用方案 C
- 日期：2026-08-18
- 范围：小红书图文、Plog 的输入区、生成结果区、灵感发现案例展示
- 不在本轮范围：电商生成逻辑、视觉创作工作台、AI 视频工作流

## 背景与问题

当前 XHS/Plog 的参考素材区使用了独立的 `ContentReferencePicker`，与电商工作台已有的素材上传模板并不一致。它把素材压缩成 58px 缩略图和两个通用小卡片，造成三个问题：

1. 用户看不出素材上传与生成结果之间的关系；
2. XHS/Plog 的视觉语言与电商工作台分裂；
3. 生成结果只强调图片，无法直观看出产品交付物是“9 张配图 + 一篇可发布文章”。

电商工作台已经验证了角色上传、批量添加、横向素材轨道、删除、预览、建议说明和生成结果总览等交互模式。本次设计只把这些模式复用到内容创作，不再建立第二套上传语言。

## 用户目标

用户输入一句话，并可选上传风格参考或自己的生活素材后，应立即理解：

- 系统会生成一整套 9 张图，而不是一张孤立图片；
- 系统同时会生成标题、正文和话题标签；
- 风格参考用于借鉴视觉气质，用户素材用于保留真实人物、物品、空间或生活细节；
- 生成结果可以整体浏览、查看单张原图、复制文案和下载整套。

## 设计原则

### 复用优先

XHS/Plog 使用电商工作台的素材上传骨架和结果总览语言。允许抽取通用能力或增加配置项，但不复制一套近似 CSS，也不继续保留当前独立的缩略图轨道。

### 成品优先

首屏默认展示“整套可发布内容”，不是九张散图。图片总览、文章信息和数量状态必须在同一个视觉单元中出现。

### 预览分层

默认用电商套图式总览说明产物；用户需要确认发布细节时，再进入小红书笔记式预览。两种预览共用同一份结果数据，不生成第二份内容。

### 自由生成，稳定交付

9 张图的生成逻辑继续使用动态创意方向，不把内容锁死为固定赛道模板。展示层只负责把结果组织成可理解的成品，不改变生成器的创作自由度。

## 方案结构

```text
输入工作台
  ├─ 复用电商素材上传骨架
  │   ├─ 风格参考（最多 3 张）
  │   └─ 我的素材 / 生活素材（最多 6 张）
  ├─ 一句话输入
  └─ 生成设置
       ↓
生成结果
  ├─ 成品总览（默认）
  │   ├─ 9 张图拼版
  │   └─ 标题 / 正文 / 标签 / 数量
  ├─ 9 张原图
  └─ 发布预览（小红书笔记式）
       ↓
灵感发现
  ├─ 案例卡片展示成品总览
  └─ 详情展示图片、文章和复用入口
```

## 输入区设计

### 组件策略

以电商的 `SupplementAssetDeck`、`SupplementImageCard` 和上传建议模型为视觉及交互基准。实现上优先把现有组件扩展为可配置角色，而不是在 `ContentReferencePicker` 中继续维护另一套样式。

需要支持的配置项：

- 左右角色标题和副标题；
- 角色数量上限；
- 角色色彩标识；
- 已带入素材数量；
- 上传建议列表；
- 单图预览和删除回调。

小红书配置为“风格参考 + 我的素材”，Plog 配置为“风格参考 + 生活素材”。上传行为、卡片尺寸、横向滚动、拖拽、批量选择、删除和预览保持电商模板一致。

### 用户可见文案

- 风格参考：借鉴色调、光线、构图和材质，不复制图中主体
- 我的素材：保留你上传的人、物、空间或生活细节
- 生活素材：保留这段生活中的人物、物件、环境和真实痕迹

生成按钮旁增加一条可读状态提示，根据当前输入动态显示：

- 没有上传图片：将根据文字生成完整图文
- 有风格参考：会借鉴参考图的视觉气质
- 有我的素材：会在相关页面保留你的主体或生活细节

不在生成前展示内部 prompt 或供应商参数。

## 结果区设计

### 默认视图：成品总览

结果区使用与电商套图展示一致的“左侧说明 + 右侧完整视觉”结构，右侧不放单张封面，而放一个 9 格成品总览板：

- 3×3 图片网格，包含封面和 8 张内容图；
- 每格保持自己的图片比例和可识别主体；
- 封面显示轻量的“封面”标识；
- 右上角显示“9 张配图”；
- 点击总览板进入发布预览；
- 不把九张图重新合成为服务端图片文件，优先使用可访问、可点击的 HTML/CSS 总览，避免文字和图片质量损失。

左侧信息区显示：

- 小红书图文 / Plog 类型标识；
- 生成标题；
- 正文摘要，过长时截断并提供查看完整文案；
- 话题标签；
- “9 张配图 · 1 篇正文”的交付说明；
- 查看发布预览、查看 9 张原图、复制文案、下载整套四类动作。

Plog 使用同一总览组件，但可以根据生成结果使用更松散的生活碎片排列；不在结果区硬编码五套固定风格模板。排列由结果的 `layout` 或生成导演信息驱动，缺省时使用稳定的 3×3 网格。

### 原图视图

点击“查看 9 张原图”后展示可滚动的 9 张图片列表或网格，每张图支持：

- 单图放大；
- 单图下载；
- 显示页面序号和镜头职责；
- 保留现有实际生成提示词的内部数据关联，但默认不直接打扰普通用户。

### 发布预览

点击总览板或“查看发布预览”后打开小红书笔记式预览：

- 顶部为封面和标题；
- 向下浏览 8 张内容图；
- 正文和话题标签放在图片内容之后；
- 桌面端使用窄栏笔记阅读容器，移动端全宽；
- 提供返回总览、复制文案和下载整套动作。

发布预览是阅读和确认状态，不伪装成真实的小红书发布页面，不增加账号、点赞、评论等与任务无关的交互。

## 灵感发现设计

灵感发现卡片的封面字段优先使用成品总览图或可复现的总览布局，而不是只取第一张图片。打开案例详情时，沿用结果区的三个层级：

1. 成品总览；
2. 9 张原图；
3. 文章标题、正文和标签。

“做同款”继续使用案例保存的原始输入、参考素材角色和提示词。作品保存仍然按用户归属隔离：普通用户生成的私有作品不会自动公开到灵感发现；只有明确发布为案例的作品才进入公共案例列表。

## 数据与接口

结果层统一读取以下字段，兼容现有 XHS/Plog 返回结构：

```js
{
  type: 'xiaohongshu' | 'plog',
  title: String,
  body_text: String,
  hashtags: String[],
  images: [{ url, label, page_id, shot_role, prompt }],
  cover_prompt: String,
  image_prompts: [{ page_id, prompt, shot_role, reference_use }],
  referenceAssets: { style: String[], source: String[] },
  preview: { layout: 'grid' | 'scrapbook' | 'editorial' }
}
```

兼容要求：

- 旧作品只有 `cover_url` 或字符串数组时，仍可降级显示；
- 旧 XHS 结果的 `cover_prompt` 和 `image_prompts` 继续保留；
- Plog 新结果必须保存封面和每张图片的实际提示词；
- 展示层不修改原始图片 URL，不把提示词拼接进公开正文；
- 下载动作使用现有文件交付机制，不新增未授权的外部存储。

## 空状态、加载和失败

- 未生成：继续显示输入工作台，不提前渲染空的 9 格结果板；
- 生成中：结果板显示 9 个占位格，并在已有图片到达时按页填充；文章区显示“正在整理标题和正文”；
- 部分失败：保留已成功图片，明确显示失败页序和重试入口，不把部分结果伪装成完整成品；
- 完全失败：保留用户输入和上传素材，显示可操作的失败说明；
- 旧作品缺少文章字段：只显示已有图片，并以“暂无正文”作为明确降级，不抛出空白区域。

## 可访问性与响应式

- 所有总览、原图、发布预览和下载动作使用真实按钮或链接；
- 图片有基于页序和职责的 `alt` 文本；
- 图片放大支持键盘关闭；
- 桌面端保持电商工作台的宽度和间距，移动端总览板切为 3 列缩略图，文章信息移到下方；
- `prefers-reduced-motion` 下不依赖旋转、漂浮或连续动画表达层级；
- 拖拽上传仍提供点击上传的等价路径。

## 验收标准

### 输入区

- XHS/Plog 的上传区域与电商素材上传模板在结构、卡片尺寸、间距、删除、预览和建议信息上保持一致；
- 风格参考和我的素材的业务语义仍然清楚，不把两种素材混成一个数组；
- 旧客户端字段和旧作品仍可用。

### 结果区

- 用户无需点击多个页面即可看懂“9 张图片 + 文章”的完整交付物；
- 默认结果是一张总览板，不是九张散落卡片；
- 总览板、原图视图和发布预览共用同一份结果数据；
- 标题、正文和标签可见，复制文案和下载整套动作可用；
- 每张图片的实际提示词仍然保存并可被案例复用。

### 灵感发现

- XHS/Plog 案例首屏展示完整成品概念；
- 案例详情能查看图文完整内容；
- “做同款”不会丢失原始输入、素材角色或提示词；
- 私有作品不会因为展示组件改造而自动公开。

### 验证

- 新增组件契约测试，覆盖 9 格总览、文章字段、降级字段和交互入口；
- 运行 XHS/Plog 生成、作品持久化和提示词回归测试；
- 运行构建检查；
- 在桌面和移动视口进行本地浏览器截图核对；
- 不触发付费视频生成，不改变电商生成计费路径。

## 分阶段实施

1. 抽取/扩展电商素材上传骨架，替换 XHS/Plog 当前独立上传组件。
2. 建立共享的 `ContentPublishPreview` 数据适配和成品总览组件。
3. 接入 XHS/Plog 结果状态、加载、部分失败和完整文章展示。
4. 接入原图视图、发布预览和下载/复制动作。
5. 更新灵感发现案例卡片与详情复用链路。
6. 添加契约测试，完成桌面/移动视觉验收。

## 设计决策记录

- 采用方案 C：默认成品总览，点击后进入发布预览。
- 不使用服务端重新生成的拼版图片作为唯一结果；优先使用 HTML/CSS 总览，保证文字可读、图片可点击、单图可下载。
- 不复制电商 CSS；通过共享组件或配置化扩展复用电商模板。
- 不把 XHS/Plog 固定成一套赛道版式；生成逻辑仍然动态，展示层只负责让交付物可理解。
