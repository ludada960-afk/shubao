# 电商创意工作流与四方向方案重构规格

## 1. 目标

把第二步从四张泛化“风格卡片”升级为四套针对当前商品的可执行创意方案，并让用户确认或修改后的方案完整贯穿商品套图生成链路。

这次不是增加一段更长的提示词，而是补齐以下闭环：

```text
商品图 + 参考图 + 用户描述 + 套图配置
  -> 两阶段有界创意分析
  -> 四套差异化、具体、可编辑方案
  -> 用户确认
  -> Campaign Bible
  -> 依赖明确的逐图计划
  -> GPT-Image-2 逐图生成
  -> 客观质量检测与定向修复
  -> 完整套图交付
```

适用范围只包括电商生图。小红书图文模式、视频、工作流导入和批量任务不在本规格内。

## 2. 调研结论

### 2.1 可复用的方法

小红书视频及其飞书资料展示的有效方法不是“一条万能提示词”，而是可复用工作流：

1. 先分析商品定位、目标受众、核心卖点、竞争优势、视觉关键词、色彩、场景和总体方向。
2. 商品精修必须保留外观、颜色、比例和结构，只改善瑕疵、材质、光线、边缘和商业质感。
3. 在复杂场景前建立可信的多角度商品认知。
4. 先建立主视觉，再让模特图、场景图、营销图和详情图继承同一视觉标准。
5. 详情页先拆成明确的信息模块，再逐屏生成，不能一次生成整张长详情页。
6. 最终将过程总结为可重复执行的工作流，而不是只保存一张成片。

OpenAI 当前图片指南和公开 GPT-Image-2 实践进一步支持：

- 明确每张输入图的职责和顺序。
- 使用结构化的主体、构图、材质、光线、文字和约束字段。
- 小步、定向修改比整张反复重做更稳定。
- 短而明确的文案及清晰的空间指令更可靠。

### 2.2 对现有系统的判断

现有正式引擎已经具备 Product Truth、Campaign Bible、Asset Plan、逐图提示词、质量门、两次定向修复、整套结算和稳定资产存储。继续沿用这些经过生产验证的边界。

现有主要缺口：

- 第二步只返回标题、描述、视觉关键词和粗略图片类型说明。
- 返回数量可能是三套，也可能是四套。
- 没有商业目标、受众、商品呈现策略、逐张职责、资产依赖、一致性锁和风险约束。
- 前端只允许编辑一段描述，用户看不到系统到底准备生成哪些图。
- 确认后只把标题和描述拼成文本传给引擎，大部分设计信息丢失。
- Asset Planner 按通用品类职责规划，无法消费用户选中的具体逐图方案。

## 3. 产品原则

1. **默认即专业**：普通商家只上传商品图并说一句需求，也必须得到完整、可用的四套方案。
2. **高级用户可控**：资深设计师可以编辑执行说明，但不用面对模型或实现参数。
3. **不把风险推给用户**：分析、重试、质量修复和失败回滚由系统处理；用户只看到可继续的明确状态。
4. **事实与创意分离**：Product Truth 决定什么不能改，创意方案只决定如何表达。
5. **配置是权威**：第一步选定的图片类型、数量和比例不得被模型改变。
6. **方向必须具体**：每套方案要说明卖给谁、解决什么购买问题、如何呈现商品，以及逐张要做什么。
7. **差异来自商业策略**：四套方案不能只是换配色，至少在商业目标、构图语言和场景策略上有明显差异。

## 4. 创意方向数据契约

服务端只向前端返回规范化后的 `CreativeDirectionPlan`：

```js
{

  id: 'dir_1',
  title: '品质结构证明',
  one_liner: '用结构和材质证据建立高品质认知',
  commercial_objective: '提升高意向用户对做工与耐用性的信任',
  audience: '重视品质、结构与长期使用价值的用户',
  visual_tone: ['克制', '精密', '可信'],
  visual_system: {
    palette: ['#F4F1EB', '#262626', '#A98B68'],
    lighting: '...',

  preview_colors: ['#F4F1EB', '#262626', '#A98B68']

```

### 4.1 强制不变量

- 始终返回恰好四套有效方案。
- `id` 唯一且稳定，标题不为空。
- `deliverables` 的角色、数量和比例严格来自第一步配置。
- 每个分组的 `shots.length` 与 `count` 一致。
- 每张图都有独立标题、目的、执行方式、变化点和依赖。
- 四套方案的商业目标、构图语言、场景策略不得完全相同。
- 所有数组和文本经过长度、原型污染、重复值和非法颜色清理。
- 模型缺字段、少返回、返回重复方案或 JSON 不合法时，由确定性规范化器补齐，不让用户看到残缺方案。
- 创意文本不能成为商品事实来源；正式生成仍由 Product Truth 拦截尺寸、成分、认证、结构和功能幻觉。

## 5. 两阶段有界分析策略

第二步在一次用户操作内依次完成轻量视觉观察和纯文本方向规划，避免把多图识别、长篇规划和完整逐图清单压入一个容易超时的大请求：

- 第一阶段只观察最多四张商品图和四张参考图；商品图使用较高视觉细节，参考图使用低细节提取风格，并在提示中标明各自索引范围。
- 第二阶段只接收第一阶段的结构化观察、用户文本、平台、品类、SKU、真实产品参数和套图配置，不再重复传图；模型只规划四套差异化方向骨架。
- 两阶段都返回严格 JSON，不要求模型生成预览图；确定性规范化器按第一步权威配置补全每个角色、数量、比例和逐图职责。
- 整个操作继承现有 75 秒浏览器生命周期和服务端总超时；阶段请求有独立的短超时与有界重试，取消会贯穿两阶段。
- 视觉阶段短暂失败时，首次分析使用明确的回退观察继续生成四套可用方向；付费重新分析若任一阶段降级则回滚计费并提示重试。
- 不在第二步重复调用生图模型。
- 正式生成仍运行权威 Product Truth 分析，这是安全与持久化边界，不复用低约束的创意分析作为事实源。

## 6. 前端体验

第二步仍以 2×2 方案网格展示，但每张卡片必须让用户在扫描时理解：

- 方向标题与一句话定位。
- 商业目标和目标受众。
- 视觉关键词与真实配色。
- 商品呈现策略摘要。
- 与当前配置完全一致的图片分组，例如“1 白底 / 3 主图 / 1 素材 / 5 详情”。
- 展开后可查看每一张图片的名称和职责。
- 整套执行说明可直接编辑，编辑会自动选中该方案。

卡片不显示“模型、JSON、工作流节点、Token”等开发实现文案。移动端改为单列，文本不得溢出。

## 7. 生成链路

### 7.1 Campaign Bible

选中的完整方案编译为 Campaign Bible：

- 商业目标、受众、视觉关键词、色板、光线、构图、镜头、背景、字体意图、信息密度、氛围、文案语气。
- 商品呈现策略。
- 一致性锁、禁止风格和风险约束。
- 用户编辑后的执行说明优先于原始说明。
- 完整逐图清单以防御性副本保存到任务快照。

### 7.2 Asset Plan

第一步配置仍决定类型、数量、比例和费用。方向方案只覆盖每张图的创意职责：

- 以 `role + roleIndex` 匹配 `deliverables[].shots[]`。
- 方案标题成为最终图片标题，方案目的和执行方式进入 `shotIntent`。
- 用户没有指定的字段继续由现有品类策略安全补齐。
- 详情图保持逐屏独立生成；前一阶段资产可以成为后一阶段的视觉参考，但商品原图始终是身份权威。

### 7.3 依赖图

```text
product_truth ─┬─> white / transparent / SKU
               ├─> hero / main KV
reference_style┘        │
                        ├─> scenario / model / marketing variations
                        └─> detail modules (one screen per asset)
```

依赖用于明确提示词职责和未来扩展，不允许把一张生成图变成商品身份的唯一来源。

## 8. 质量、失败与计费

- 保留现有技术规格、商品一致性、文案与 Logo、平台规范和视觉质量检查。
- 失败只重做失败图片，最多两次，用户不重复付费。
- 上游瞬时不可用先按既有有界策略重试，不把“质量分析不可用”误判成商品不合格。
- 只有整套配置数量全部稳定交付才结算；部分失败释放未交付额度。
- 生产 UI 不再出现“验收不过关、本张未计费”作为正常流程；系统在后台修复，真正不可恢复时给出清楚的重试状态。

## 9. 兼容与迁移

- 旧方向对象仍可通过规范化器转换，缺失字段使用确定性默认值。
- `/api/ecommerce/design-directions` 路径保持不变。
- `/api/generate-ecommerce` 和任务恢复协议保持兼容。
- 旧任务快照继续使用原 Campaign Bible；新任务写入 `schemaVersion` 和完整方案。
- 小红书模式不读取本契约。

## 10. 验收标准

1. 任意合法输入都返回四套完整方案。
2. 第一套不等于其他三套的换色版本。
3. 图片分组、数量和比例与第一步以及费用报价完全一致。
4. 用户修改执行说明后，任务快照和每张提示词都能看到修改结果。
5. 每张成片有准确中文标题、角色、比例和像素尺寸。
6. 相同角色的多张图具有不同职责、镜头或场景，不再同质化。
7. 详情图逐屏规划并生成，不生成一张伪长页。
8. 商品原图、参考图和生成资产职责不混淆。
9. 旧任务恢复、账务、作品、画布导入和稳定图片 URL 不回归。
10. 全量自动化、生产构建、桌面与移动浏览器验收、真实生产部署全部通过。
