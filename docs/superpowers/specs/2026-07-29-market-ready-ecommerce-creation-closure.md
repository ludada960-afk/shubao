# 面向市场的电商创作闭环设计

## 1. 目标

在保留现有项目版本、耐久生成任务、账务冻结结算、稳定作品资产和画布基础能力的前提下，完成面向电商卖家、美工设计师、小红书与 Plog 创作者的市场化创作闭环。

最终流程必须满足：输入可理解、费用可预期、任务不中断、数量不失控、每张图有独立商业职责、结果即时保存、失败只补失败项、画布操作可理解、完成后新任务回到空白状态。

## 2. 已完成并必须保留的基础

- 服务端项目、不可变版本、恢复检查点、生成任务和账务状态是唯一事实源。
- 首页新访问与已完成任务默认空白；只有未闭环任务进入显式恢复区。
- 登录在原位置完成，不默认跳转；当前内存输入在登录期间保留。
- 每张通过质量门的图片立即进入“我的作品”，稳定 URL 不依赖上游临时地址。
- 生成数量由服务端计划和报价共同约束，任务拥有幂等键、租约和进程恢复能力。
- `gpt-image-2` 负责图片生成；`gpt-5.6-terra` 负责默认视觉理解。
- 正式结果必须通过技术、商品一致性、文字/Logo 和视觉质量门。

这些基础不得被新 UI、本地缓存或兼容代码绕开。

## 3. 产品原则

1. 用户界面只展示用户需要作决定的信息，不展示“内测、白名单、无限额度、AI 内部规则、模型降级、方向由 AI 定义”等内部实现。
2. 用户主动刷新或已完成一轮任务后，首页是空白的新任务；登录、额度不足、网络中断或生成中断才产生可恢复任务。
3. 视觉分析失败时停止规划和生图，解释可操作原因，不扣生成积分，不使用 Mock 冒充真实识别。
4. 计划几张就只提交几张上游任务，禁止隐藏候选图、联系表、五宫格或未报价的批量生成。
5. 一张成片只承担一个主要沟通目标；同套图片共享商品事实与品牌调性，但镜头、信息职责和使用场景必须有可解释差异。
6. 已成功的图片不可因其他图片失败而重生成；失败项只补跑自己，且自动修复最多一次，之后由用户决定。
7. 所有高频命令必须有即时反馈；所有图标按钮必须有可访问名称和悬停提示；禁止浏览器原生 `alert`、`confirm` 和 `prompt`。
8. 未实现或无法诚实交付的能力不显示为可点击功能。

## 4. 视觉理解

### 4.1 两类独立分析

产品素材和参考素材不得混成一段普通视觉描述。

`ProductTruthAnalysis` 只提取商品本身：

```js
{
  category,
  productName,
  silhouette,
  colors,
  materials,
  components,
  visibleText,
  logos,
  confirmedFacts,
  uncertainFacts,
  forbiddenMutations,
  sourceAssetIds,
  confidence
}
```

`StyleReferenceProfile` 只提取可迁移视觉语言：

```js
{
  palette,
  lighting,
  composition,
  cameraLanguage,
  typographyIntent,
  informationDensity,
  backgroundLanguage,
  mood,
  prohibitedTransfers,
  sourceAssetIds,
  confidence
}
```

`prohibitedTransfers` 至少包含参考图中的商品、人物身份、品牌、Logo、价格、参数、认证和原文案。参考图只能影响风格，不得污染商品事实。

### 4.2 模型、缓存和失败

- 默认视觉模型为 `gpt-5.6-terra`，环境变量只允许显式替换为已审核模型。
- OCR、小物体、复杂多图冲突和低置信度结果可以升级到更高质量模型，但不得静默升级产生未报价成本。
- 分析按原始资产内容哈希、模型、Prompt 版本和分析类型缓存；同一输入不重复收费或重复调用。
- 正式任务禁止 Mock。未配置视觉服务、非 JSON、超时或低置信度都返回结构化失败。
- 用户可确认或修正不确定商品事实；高风险参数、功效、认证、尺寸和 SKU 只能来自用户或可信 OCR。

## 5. 套图导演与精确生成

### 5.1 规划链

```text
Product Truth
→ Style Reference Profile
→ Campaign Bible
→ 平台与品类蓝图
→ 独立镜头计划
→ 精确数量报价
→ 逐张生成
→ 单图质量门
→ 套图差异质量门
→ 失败项补跑
```

每个计划项必须包含：名称、用途、平台位置、主要沟通目标、镜头、构图、场景、证据等级、允许文字、比例、生成尺寸、导出尺寸、费用和唯一计划 ID。

### 5.2 图片职责

- 白底图：单一商品主体、纯白背景、完整轮廓、无场景装饰和未经确认文字。
- 主图：首图负责商品识别和核心卖点；其余主图分别承担使用场景、功能利益、材质/工艺或适用人群，不得只是微调背景。
- SKU 图：只表达用户确认的颜色、款式、组合和规格，不生成不存在的 SKU。
- 详情图：按品类选择场景、结构、材质、功能、尺寸、步骤、对比或品质证据；没有证据时不得生成爆炸图、内部结构、认证或参数。

单张产品图仍可生成安全的视角、尺度、场景和使用关系变化；涉及背面、内部、拆解或隐藏部件时必须有素材证据，否则改用不虚构结构的镜头。

### 5.3 差异质量门

套图完成前比较：主要沟通目标、镜头类型、相机方位、主体尺度、背景语义、人物角色和文案职责。同质项不能作为成功结果结算。系统只重做冲突项，不扩大总数量。

## 6. 成本与计费

- 报价来源是服务端冻结的资产计划，不接受前端自报数量或价格。
- 视觉分析、方案刷新、单张生成、重新生成、AI 改图、分层和 4K 输出分别计价。
- 方案方向允许有限次数的低成本刷新；超过免费次数后，在执行前明确展示积分。
- 所有 Provider 尝试记录内部真实成本；普通用户只为质量门通过并稳定交付的项目结算。
- 重新生成只针对当前图片，执行前展示费用；失败或未交付释放对应冻结额度。
- 特权账号的内部结算方式不得改变市场化界面文案和报价展示。

## 7. 任务连续性

- 点击受保护的“下一步”时直接打开产品登录弹窗，登录后继续原命令。
- OTP 重发倒计时不移除邮箱输入或返回入口；关闭、退出和重新登录时清空旧验证码。
- 生成任务离开当前页面后继续运行，并出现在全局任务入口；入口显示任务名称、完成数、总数、失败数和可继续动作。
- 每张通过质量门的图片立即写入作品和项目结果版本；刷新或断网后从服务器恢复，不从页面内存猜测。
- 已完成任务归档后清空首页编辑器；未完成任务只进入折叠恢复区，不自动注入新编辑器。
- 错误必须显示在当前任务和对应图片附近，同时可进入统一通知中心；不能只在页面顶部短暂出现。

## 8. 结果工作台与画布

### 8.1 结果关系

产品素材组成一个左侧“产品素材组”。所有生成图片是右侧并列子资产，每张分别连接到素材组；结果之间没有主次链，也不互相串联。

只有用户对某张成功结果执行新动作后，才产生新的动作节点和输出节点。草稿、运行中、失败和纯动作节点不能继续派生。

### 8.2 命令体系

- 图片悬停只显示两个最高频动作：`调整生成要求`、`重新生成`。
- 左键选择后显示轻量直接操作：下载、图片信息、加入引用、删除。
- 右键显示完整上下文命令，但所有命令来自唯一动作注册表，与端口拖线共享同一执行器、价格和可用条件。
- `商品图改造` 是按提示要求生成新图片的工作流名称；不再使用含糊的“智能二创”。
- `图片信息` 合并名称和用途编辑，避免重复命令。
- 动作选择器与连线使用画布世界坐标；平移缩放时共同移动，菜单在视口内可滚动，连线端点吸附实际端口中心。

### 8.3 真实能力

- `智能扩图` 必须先让用户选择目标比例并输入扩展要求，再显示报价并执行。
- 画面分析只能报告语义区域，不能冒充可编辑图层。
- 只有实际生成透明图层资产和蒙版后，才显示“可编辑分层”和 PSD 导出。
- PSD 必须经过结构解析验证，至少包含两个独立图层；扁平图片改后缀不算 PSD。
- 文字图层使用确定性排版，支持内容、字体、字号、颜色、对齐和位置编辑；字体按商品调性从许可字体注册表选择。

## 9. 对话框、文案和视觉系统

- 登录、定价、删除、重命名、扩图参数、重新生成和错误恢复全部使用统一产品对话框。
- 套餐页明确分为“小红书/Plog 内容套数”和“电商/画布 AI 积分”，每个功能在执行前显示消耗单位。
- 登录页只写用户完成登录所需内容，不披露访问名单、测试阶段或内部权限。
- 全站颜色按语义统一：主命令、成功、警告、错误、中性；工具栏不得为不同按钮随意分配高饱和颜色。
- 图片是核心内容，卡片尺寸稳定，加载、失败、悬停、选中、放大和键盘左右切换都有统一状态。
- 桌面和 390x844 移动视口不能出现文字截断、控件遮挡、菜单不可滚动或主要操作不可达。

## 10. 保留与清理

- 临时上传与未引用中间文件保留 24 小时。
- 未完成项目和恢复检查点保留 7 天。
- 已完成作品默认保留 30 天，并在作品中显示到期时间。
- 用户主动保留、账务争议、运行任务、有效画布会话或组合文档引用的资产不得删除。
- 项目版本长期保留资产元数据、哈希、用途和过期状态，但普通完成版本不永久保护二进制文件；超过 30 天且没有其他保护引用时，文件可以到期，界面明确显示已过期而不是伪装成仍可打开。
- 清理采用标记、隔离、再次检查、删除四步，不能直接按目录批量删除。
- 旧本地草稿和画布缓存只做一次兼容读取；迁移后删除旧索引，不把旧状态自动注入新任务。

## 11. 发布顺序

1. 视觉分析服务与参考图隔离。
2. 套图导演、精确数量和差异质量门。
3. 全局任务入口、错误就地反馈和完成后清空。
4. 结果工作台与唯一画布动作注册表。
5. 确定性文字、真实分层、PSD 和资产保留。
6. 全站文案、套餐信息、对话框和视觉一致性审计。
7. 完整回归、桌面/移动浏览器 QA、真实视觉分析、真实生成、账务闭环和生产部署。

每个阶段必须是独立可测试、可提交、可回滚的里程碑。任何阶段不得以未实现的后续能力作为当前成功条件。

## 12. 验收

- 同一批商品图和参考图能产生相互隔离的 Product Truth 与 Style Reference Profile。
- 智能套图计划的数量、报价、Provider 提交数和用户最终状态项完全一致。
- 每张交付图有唯一职责；白底、主图、SKU 和详情图满足各自约束，套图无联系表和同质重复。
- 离开页面、刷新和服务重启后任务继续；已成功图片仍在作品中，失败项可单独重试。
- 完成任务后首页为空；只有未闭环任务出现在折叠恢复区。
- 画布素材组扇出关系、端口、菜单、派生规则、扩图参数和两项悬停快捷命令符合规格。
- 所有用户决策使用产品对话框；不存在浏览器原生弹窗、内部阶段文案或无说明图标。
- 真实分层和 PSD 通过结构验证；未具备真实图层时功能明确不可用。
- `npm test`、生产构建、协作检查和差异检查通过。
- 浏览器 QA 覆盖 1440x900 与 390x844，以及登录中断、额度不足、页面切换、错误、放大浏览和画布平移缩放。
- 生产只通过 `scripts/deploy-production.ps1` 发布；发布后 PM2、健康接口、公开 API、带登录视觉分析、至少一个真实生成任务、账务冻结/结算/释放、作品稳定 URL 和完整金丝雀均验证通过。

## 13. 非目标

- 不在本轮建立全新的微服务平台。
- 不承诺模型可以从单一视角真实还原不可见结构。
- 不展示无法验证效果的高级功能。
- 不自动调用未报价的高价模型。
- 不用增加更多按钮替代对现有工作流的简化。
