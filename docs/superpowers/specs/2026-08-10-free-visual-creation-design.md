# 自由创作与首页四域架构设计

**日期：** 2026-08-10
**状态：** 已授权自主实施
**目标：** 在不继续堆叠垂直产线的前提下，为海报及未来通用图片场景提供一个可扩展、可理解、可交付的创作入口。

## 1. 决策摘要

首页长期固定为四个产品域：

1. `电商生图`：围绕商品事实、套图规划和电商交付的完整工作流。
2. `视频生成`：围绕镜头、时序素材和视频交付的完整工作流。
3. `小红书图文`：围绕内容理解、分页叙事和图文交付的完整工作流。
4. `自由创作`：以对话和参考图为输入，生成单张或一组通用图片的开放工作台。

海报不作为第五个顶层域。`海报设计`、`社媒封面`、`品牌主视觉`等能力属于自由创作内的“创作配方”。只有拥有独立输入事实、独立多步流程、独立交付物和独立账务生命周期的能力，才可以晋升为顶层产品域。

这一结构解决两个问题：既让用户现在就能明确找到海报能力，也防止未来每增加一个场景就继续增加首页卡片。

## 2. 调研结论

### 2.1 竞品四卡入口

`marketing.k-fashionshop.com` 的有效交互是：四张固定扇形卡片、悬停单卡上移 16px 并扶正、点击后不跳路由而原位切换工作台。其卡片之间没有推挤或复杂联动。

不复刻的问题：该站移动端依赖约 1440px 的最小页面宽度，390px 视口需要横向滚动后才能看到卡片；键盘焦点没有当前态语义。薯包保留扇形节奏，但必须响应式缩放、无横向溢出，并使用 `tab`、`aria-selected` 与清晰焦点态。

### 2.2 角色选择与 Skill 展示

竞品的“设计师角色”选择把能力藏在人物名字后面，用户无法在选择前判断输入会保留什么、结果长什么样、适合什么任务。自由创作不采用角色人格作为主信息架构。

小红书海报 Skill 案例有效的原因是每个能力都用结果封面、转换机制、适用场景和多个示例解释。创作配方必须回答三件事：

- `保留什么`：例如商品主体、原始照片或文字层级。
- `结果长什么样`：例如留白编辑海报、真实照片与手绘涂鸦组合。
- `适合什么`：例如活动海报、上新封面或品牌视觉。

### 2.3 本地能力边界

本地 `guizang-social-card-skill-main` 擅长文章理解、分页规划和固定设计系统，但当前是 Agent 流程，不是稳定的在线生成 API；不能在产品里声称已提供一键 5-9 页完整卡片生产线。本次如实交付单图/多图通用生成和海报导向配方，未来再把多页规划器作为独立能力接入。

## 3. 用户体验

### 3.1 首页入口

- 四张卡从左到右固定为：电商生图、视频生成、小红书图文、自由创作。
- 初态采用交错扇形；鼠标悬停或键盘聚焦时，当前卡扶正并上移，邻卡不移动。
- 点击后在同一页面切换工作台，不产生路由跳转或滚动突变。
- 当前域有可见边框与 `aria-selected=true`，但不改变卡片占位尺寸。
- 视频入口素材采用参考站的透明底三层叠卡语言：前景案例卡与后方色彩卡保持同一组倾角和层级，不制作不透明背景的三联画，也不让单一人物成为整组入口的绝对视觉中心。

### 3.2 自由创作工作台

首屏直接是可用工具，不是功能说明页。结构从上到下为：

1. **创作配方画廊**：横向/响应式卡片，显示真实风格预览、名称、结果描述及三项能力说明；默认选中自由创作。
2. **参考素材区**：支持 0-6 张图片，上传后可预览、删除；0 张即文生图，有图即参考图创作。
3. **对话输入区**：用户描述主体、场景、构图、文字需求及约束；配方只补充专业方法，不覆盖用户事实。
4. **参数底栏**：模型、画幅、清晰度、数量和预计 AI 积分；生成按钮是唯一主动作。
5. **结果区**：逐槽显示生成中、成功或失败；部分成功不被失败项抹掉，可仅重试失败项；成功图片可下载或进入画布继续编辑。

### 3.3 首批创作配方

| 配方 | 保留什么 | 结果长什么样 | 适合什么 |
|---|---|---|---|
| 自由创作 | 用户描述与参考图主体关系 | 由提示词自由定义 | 概念图、插画、场景与开放需求 |
| 海报设计 | 核心主体、品牌信息与文字层级 | 完整构图、明确视觉焦点、可读排版区 | 活动、上新、节日与线下海报 |
| 社媒封面 | 主体辨识度与标题优先级 | 移动端一眼可读、强焦点、留出标题安全区 | 小红书、公众号与短视频封面 |
| 品牌主视觉 | 品牌调性、产品身份与关键色 | 可延展的统一场景、材质和光影语言 | Campaign KV、发布会与主题传播 |

预览图只表达风格和构图预期，不承诺逐像素复制。产品文案不得把尚未安装或未 API 化的外部 Skill 伪装成可用能力。

## 4. 生成与恢复架构

### 4.1 复用现有耐久链路

自由创作复用签名的 `/api/canvas/regenerate`、模型目录、账务报价、生成任务幂等、稳定资产存储和 Canvas 导入，不使用旧的非耐久 `/api/regenerate-image`。

客户端对每次生成创建稳定 `runId`，每个结果槽使用 `${runId}:${index}` 作为逻辑请求键。已成功槽不重发，失败槽用同一键重试，确保服务端任务与扣费可重放且不重复。

### 4.2 明确创作意图

请求新增：

- `creation_intent: 'visual' | 'ecommerce'`
- `skill_id: 'free' | 'poster' | 'social-cover' | 'brand-kv'`

它们进入请求指纹和任务快照。`visual` 使用服务端白名单配方构建通用视觉提示词；缺省仍为 `ecommerce`，保持现有 Canvas 行为完全兼容。服务端不接受客户端直接提供隐藏系统提示词。

### 4.3 部分成功与作品

- 前端以槽为单位保存 `pending / generating / completed / failed`。
- `Promise.allSettled` 或等价逐槽执行保留所有成功结果。
- 至少一张成功即可创建/更新同一件 `workType: 'visual'` 作品。
- 全部成功为 `completed`，部分成功为 `needs_review`。
- 作品保存稳定生成资产 URL、配方、用户提示词、模型、画幅、清晰度和请求槽键。
- Canvas 作品筛选增加 `自由创作`，并可把结果作为普通图片节点继续编辑。

## 5. 失败与边界状态

- 未登录：在报价前打开现有登录流程，不上传、不生成、不扣费。
- 提示词为空：在本地阻止提交并聚焦输入框。
- 参考图上传失败：保留其余已上传素材，指出失败项，可重试。
- 余额不足：显示服务端真实错误和充值入口，不吞掉已成功结果。
- 队列繁忙/断网：显示可重试状态，复用原槽请求键。
- 页面切换：工作台本地状态保持；刷新后的服务端重放由稳定请求键兜底，本期不新增全局草稿自动恢复。
- 生成结果：只信任服务端稳定 URL；不把 `blob:`、`data:` 或临时上传 URL保存为作品输出。

## 6. 视觉与响应式规则

- 沿用当前白色、紫色强调与中性灰设计系统，不创建新的品牌主题。
- 工具工作台保持紧凑、可扫描；不使用嵌套卡片或宣传型大段说明。
- 配方预览使用真实图片素材和固定比例，标题不压图，最长中文词在移动端换行。
- 桌面四卡约 148-168px 宽；移动端在可用宽度内缩到约 80-92px，仍完整可见且不横向滚动。
- `prefers-reduced-motion` 下取消扇形入场和悬停位移动画。

## 7. 市场化指标

- 首页四域点击率与回访选择率。
- 自由创作从进入到首次生成的完成率。
- 配方选择分布、配方切换后生成率。
- 部分失败率、失败槽重试成功率、重复扣费为零。
- 生成结果下载率、进入 Canvas 率和作品二次打开率。

## 8. 本期不做

- 不新增第五张“海报”顶层卡。
- 不接入视频到自由创作。
- 不声称已实现外部海报 Skill 的多页完整流水线。
- 不新增聊天历史、多人协作或模板市场。
- QA 不触发任何真实付费生成。

## 9. 验收标准

- 首页四卡在桌面和 390px 移动端完整可见，无水平溢出；交互、键盘和减弱动效均可用。
- 视频入口图使用透明底三层叠卡参考素材；自由创作入口图使用同一视觉语言，并能直接表达通用视觉与海报能力。
- 自由创作提供配方预览、0-6 张参考图、提示词、模型、画幅、清晰度、数量、真实积分预估和明确生成状态。
- 通用请求不含电商专用前缀，现有电商 Canvas 请求保持原语义。
- 请求意图与配方进入服务端幂等指纹；失败槽重试不重跑成功槽。
- 自由创作作品可保存、筛选、下载并进入 Canvas。
- 聚焦测试、完整测试、生产构建、协作检查、空白检查和桌面/移动端浏览器验收全部通过。
