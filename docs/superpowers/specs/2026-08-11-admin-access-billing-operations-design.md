# 管理后台、账号权限与成本利润核算设计

## 目标

把封闭内测从环境变量白名单和无限额度切换为数据库驱动的运营系统：管理员可以管理账号、分配四个产品板块权限、发放和回收积分；所有 AI 消耗必须进入统一钱包账本；每次调用同时记录积分、成本、收入口径和成本可信度。

## 产品边界

四个用户功能权限：

- `ecommerce_image`：电商生图和其生成型编辑能力
- `video_generation`：视频任务创建、视频模型能力
- `content_generation`：小红书/内容成套生成
- `visual_creation`：自由创作及其图片生成能力

管理员权限独立于产品权限。画布是跨产品工作区，具体生成动作继承所属产品权限；管理员页面使用独立的 `admin` 权限，不通过前端隐藏来实现授权。

## 账号模型

新增数据库账号访问表及权限表，账号状态包含 `active`、`suspended`、`invited`。邮箱是当前唯一登录主体，表结构保留未来 user id 扩展空间。角色至少包含 `owner`、`admin`、`tester`，角色用于后台能力，产品权限使用显式集合保存。

权限决策只在服务端执行：请求从签名会话得到邮箱，再查询账号状态和权限。请求体、查询参数和客户端 localStorage 中的邮箱不能改变授权主体。

默认迁移：

- `867550189@qq.com`：`owner/admin`，四个产品权限，300,000 `ec_points`
- `240485042@qq.com`：`tester`，四个产品权限，100,000 `ec_points`

两个账号不再拥有无限额度。旧的环境变量无限额度只作为兼容期禁用开关，不作为新授权来源。

## 积分和计费

继续复用现有 wallet、credit lots、holds、settlements、releases 和 idempotency 结构。新增的运营能力只通过 `grant`、`revoke` 和现有流水接口改变余额，禁止后台直接更新余额字段。

每个计费动作必须具备：

1. 服务端生成的 SKU 和 catalog version
2. 预扣 hold
3. 上游成功交付后的 settle
4. 上游失败、超时或安全拒绝后的 release
5. 稳定的 action id 和幂等键
6. 账号、功能、模型、供应商、路由、请求参数摘要和成本来源快照

批量工作流只在最终交付完整结果后结算，部分失败按现有工作流规则释放未交付部分。管理员权限不绕过积分检查。

### 收入和利润口径

- `credit_face_value`：按当前或结算时积分售价折算的理论收入
- `cash_revenue`：真实支付订单产生的收入，不把管理员赠送积分当现金收入
- `promo_subsidy`：赠送积分被消耗时的理论收入价值，单独统计
- `provider_cost_cny`：上游成本，保存金额、币种、来源和可信度
- `contribution_cny`：现金收入或理论收入口径减去上游成本和支付费后的贡献

成本可信度枚举：

- `provider_reported`：上游逐请求直接返回的实际费用
- `provider_balance_delta`：可关联的账户余额差额
- `token_calculated`：按实际 token 用量和官方单价计算
- `catalog_fixed`：按供应商合同/中转站价格快照计算
- `estimated`：只能依据规格预估，必须在界面明确显示

DeepSeek 使用响应 usage 和官方余额接口；视频中转站若只返回任务 ID，则使用 `catalog_fixed` 或 `estimated`，不伪装成真实扣款。后台同时显示成本来源、成本快照版本和数据更新时间。

## 管理后台

### 总览

展示活跃账号、积分消耗、理论收入、现金收入、赠送积分补贴、上游成本、贡献利润、毛利率、失败率、队列长度和供应商可用性。支持时间范围和功能筛选。

### 账号管理

账号表展示邮箱、状态、角色、四项权限、可用积分、冻结积分、累计消耗、上游成本、最后活跃时间。账号详情展示权限变更、积分发放/回收、账本、计费事件和管理员审计日志。

操作均需填写原因并写入审计日志：邀请、启用、冻结、恢复、修改权限、发放积分、回收积分、设置过期时间。

### 成本分析

按账号、功能、SKU、模型、供应商和日期聚合。提供“现金收入口径”和“理论收入口径”切换，避免内测赠送积分制造虚假营收。支持 CSV 导出和成本异常标记。

## 安全和并发

- 管理接口要求服务端 admin/owner 角色；普通 tester 即使知道接口也不能读取其他账号数据。
- 账号、账本、权限变更使用数据库事务和幂等键。
- 生成请求先扣额度再入供应商队列；同一 action 重试不得重复扣费。
- 供应商响应不确定时保留 `needs_review`，禁止自动重复提交造成双重成本。
- 生产环境不显示供应商密钥；后台只能显示供应商名称、连接状态、余额快照和最近同步时间。

## 验收标准

1. 两个迁移账号的余额分别为 300,000 和 100,000，均为普通可扣余额。
2. 任一生成型 API 没有对应产品权限时服务端返回 403。
3. 成功生成扣除正确积分，失败生成不产生净扣除，重复请求不重复扣除。
4. 后台发放和回收积分可在账本和审计日志中还原。
5. 后台能区分现金收入、赠送积分补贴、供应商成本和估算成本。
6. 未授权账号不能访问后台和跨账号账务数据。
7. 完成全量测试、构建、生产 canary、远程审计和只读业务验收后才发布。
