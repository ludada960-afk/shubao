## 0. 一句话结论

这是一条**"素材图 → 反推提示词 → 换装 → 动作参考视频 → 分镜脚本 → 成片"的六段式带货视频流水线**，
全部在**一张无限画布上用手工拖拽 + 连线 + `@引用`**搭出来；
用户全程不需要写工作流定义、不需要写代码，唯一需要理解的"语法"是 **`@图片1` / `@文本1` = 第 N 条入边**；
搭好之后**选中几个节点 → 设为分组 → 点运行**，就等于把这套流水线存成了一个可复用模板。

### 4.0 全局流程讲解（0:20–1:08）

`[逐字稿]` 0:30–1:05 原文口述的链路（这就是作者自己的心智模型）：

> "首先要生成这样的视频，我们肯定要先有一个模特 → 所以我在**开始节点**这里上传了一个模特的参考图
> → 我们在这里是先**反推**出了这个模特参考图的提示词 → 然后用 **image 模型**根据这里的提示词生成了这样的一个模特图片
> → 然后再生成了模特的**三视图** → 有了模特之后，我们在这里上传了**穿搭的参考图**，然后我们让模特穿上了上传的穿搭参考图
> → 再上传一个**动作参考视频**，用大模型**反推出这个视频的分镜脚本** → 最后根据模特穿搭图 + 动作参考视频 + 反推出来的视频分镜脚本，来生成最后的视频。"

> （`[逐字稿]` 里"开始节点"是作者对最左侧素材节点的口语称呼，**不是画布里的一个节点类型【未确认】**）

### 5.4 `@` 引用 = 入边编号（**本教程的核心语法**）

- 节点指令框里输入 `@` → 弹出**可引用资源列表**，条目形如 `27649823984.jpg` + `图片1`。`[帧OCR T=168]`
- 引用的编号 **按入边顺序自动生成**：第 1 条入边 = `图片1/文本1/视频1`，第 2 条 = `图片2`……
- 换装节点里 `@图片1`=模特、`@图片2`=服装；成片节点里 `@图片1`=模特穿搭图、视频用"这个视频是参考视频"指代、`@文本1`=分镜脚本。`[帧OCR T=534/566]`
- **含义**：连线不携带类型信息，"数据流"完全靠**序号 + 自然语言**软串联 —— 用户不需要理解端口，但也**没有类型校验**。

## 7. 对我们产品的功能要求推导（按依赖顺序）

> 结论先行：**要复刻这个效果，难点不在"画布"，而在"让一张画好的图能按拓扑一次跑通"。**
> 下面按**上线依赖顺序**排列，前一层不做完，后一层做不了。

### P0 · 画布内核（不做完后面全是空中楼阁）

| # | 能力 | 为什么这条视频要求它 | 验收口径 |
|---|---|---|---|
| P0-1 | **无限画布视口**：平移 / 缩放 / 框选 / 多选 / 网格或空白双击新建 | 视频全程在缩放（100%→151%）与框选多选 | 缩放不丢精度，100 节点下 60fps |
| P0-2 | **节点数据模型**：`kind / x / y / w / h / title / meta` | 5 种 kind（文本/图片/视频/音频/应用）+ 可改名标题 | 一份 JSON 可完整还原画布 |
| P0-3 | **连线模型（边）**：至少 `{id, from, to}`，**并预留 `order`** | 用户靠"第几条入边"决定 `@图片1/@图片2` | 调换入边顺序能改变 `@` 编号 |
| P0-4 | **节点卡片 UI 骨架**：标题栏 / 媒体区 / 动作条 / **输入槽胶囊** / 指令框 / 参数行 / 价格行 / 状态行 | 视频里每个节点都是这个结构，用户靠它读状态 | 骨架统一，换 kind 只换槽位 |
| P0-5 | **右侧 `+` 端口拖拽建连**：拖出线 → 松手弹出"下游节点类型"菜单 | 视频最核心的动作（"拉出来一条线，选择图片"） | 拖线 ≤100ms 跟手 |
| P0-6 | **撤销栈**：`Ctrl+Z`，≥80 步 | 连线/移动/参数改动频繁，无撤销没法用 | 撤销后价格/状态一并回滚 |

| # | 能力 | 说明 |

### 7.x 三个必须做的**设计决策**（对比结论，不是功能）

1. **边要不要带类型/端口？**
   他们**不带**（只 `from/to`，靠 `@图片1` 软引用）→ 实现简单、用户易上手，但**模板之间不可组合、改连线会静默出错**。
   → **建议我们带"弱类型"**：端口不强制，但连线后要**校验能否喂给下游**并在边异常时高亮（他们的边有 `is-invalid` 态，可参考）。
2. **"一键"应该是什么？**
   视频证明用户心里的"一键" = **选中 → 设为分组 → 运行**，**不是**打开一个独立的工作流编辑器。
   → 我们应把"分组运行"做成第一类公民（含报价、拓扑执行、失败分段重跑、改参后下游失效）。
3. **提示词从哪来？**
   视频里所有提示词都靠**两条反推链**产生：图→提示词、视频→分镜脚本；用户只需要会 `@`。
   → 我们的**反推类 SKU 是这条链的入口**，必须在画布上是一等节点动作（"从这张图反推提示词"= 一次点击）。
