## 0. 一句话目标

把现在**四个互不相通的工具**（电商套图 / 小红书图文 / 视频工作台 / 无限画布），
变成一个**节点化创作台**：用户把「文本 → 图片 → 视频 → 音频 → 成品」用线连起来，
点一次就跑通全链；每一步都能单独重跑、单独换模型、单独看价格；跑出来的成品能直接复用成下一个商品的输入。

**这就是用户说的"节点之间可以联动、串联、派生，最后服务成一个生态"的工程含义。**

### 0.1 目标效果（B 站教程 BV1odbo6AEri 逐字稿还原，第一手）

UP 主的完整流程（女装带货口哨舞视频），我按逐字稿逐节点还原：

| 步 | 节点 | 输入 | 关键提示词/参数 |
|---|---|---|---|
| 1 | **模特**（两种来源） | 上传模特参考图 或 用内置模板 | ① 无模特：`添加 → 图片 → 自定义 → 模特生成 → 选模板 → 生成`；② 有参考图：先拉出**文本节点**引用 `@图片1`，提示词"分析这张图片…从主体内容/场景设定/风格/色调/构图/视角/细节 描述，并加入 iPhone 拍摄质感（真实自然光、手机镜头）"，模型 豆包2.0 + **深度思考** |
| 2 | **生成模特图** | 文本节点（`@文本1`） | 模型 图片2，比例 9:16，1K |
| 3 | **三视图** | 模特图 | 拉线 → 图片节点 → 自定义 → 模特生成 → **三视图模板**，16:9 1K |
| 4 | **服装** | 上传穿搭图（优先白底图） | 没有白底图就用提示词"生成图片中所有穿搭的商用白底展示图，不要有任何文字/包包"，1:1 |
| 5 | **模特穿衣** | 模特图 + 服装图（**两条入边**） | "图片一是模特，穿上图片二的所有的搭配，随意摆 pose，画面分两部分：正面和侧面，分别标注文字"，图片2 1:1 1K |
| 6 | **动作参考视频** | 上传参考视频 | 拉出文本节点 → 提示词"生成这条视频包括**镜头角度、肢体动作、面部表情、眼神目光**的所有提示词和**时间节点**"，全能语言模型 + 深度思考 |
| 7 | **生成成片** | 模特穿搭图 + 参考视频 + 分镜脚本文本（**三条入边**） | "图片一是模特，这个视频是参考视频，让模特按照参考视频跳舞，动作轻快干净…真实自拍质感" + 脚本；比例 9:16，**时长对齐参考视频的 7 秒**，720p |
| 8 | **复用（最关键）** | 选中 1-3 号节点 → **设为分组** → 点**运行** | "它会从反推提示词节点开始，依次运行这三个节点"；换模特 = 替换图片；换服装/换视频 = 替换素材后重新提交 |

**这三条是产品化的关键结论**（比"能做节点"重要得多）：

1. **反推是整条链的发动机**：图→提示词、视频→分镜脚本，用户不需要会写提示词，只需要会`@引用`。
   （我们有 `ec_reverse_prompt` 200/次 与 `video_plan_analysis` 1000/次，**这两个 SKU 就是这条链的入口**。）
2. **`@图片1`/`@文本1` 是用户唯一的"编程语法"**：连线即变量，入边序号即编号 —— 与知渔完全一致。
3. **"分组 + 一键运行"才是用户嘴里的一键**：UP 主全程没用"工作流"这个词，他说的是"选中三个节点 → 设为分组 → 运行"。
   我们要做的不是"工作流编辑器"，而是**让一张已经画好的图能一键按拓扑跑起来**（= 我们 P0/P1 的执行引擎）。

### 0.2 目标流程在我们产品里的样子（同一个流程，我们的形态）

```
商品素材上传(source_group)
  ├─→ [反推节点] 图→提示词（ec_reverse_prompt 0.2）        ← 用户不用写提示词
  ├─→ [模特节点] 模板：近景模特/三视图（内置模板库）
  ├─→ [换装节点] 双入边：模特 + 服装白底图（ec_image_2k 1/张）
  ├─→ [视频脚本节点] 参考视频→分镜脚本（video_plan_analysis 1）
  └─→ [成片节点] 三入边：模特穿搭图 + 参考视频 + 脚本（video_* 27~57）
        ↓ 选中全链 → 设为分组 → 运行（按拓扑自动跑，失败只重跑那一段）
```
**和 UP 主手工流程的唯一区别：我们把"商品事实（卖点/合规/尺寸/平台规格）"挂进这条链**，
所以同一套图换个商品就能复用，而不是每次重新写提示词。

## 1. 三家对标，我们各自学什么（结论先行）

| 对标 | 它最强的地方 | 我们要学的 | 我们不学的 |
|---|---|---|---|
| **知渔 AI 画布** | 把图论包装成用户看得懂的一件事：**节点自带"输入槽 + 指令 + 模型 + 参数 + 次数 + 预计积分"**；40 个图片模板 + 19 个带货视频模板即节点；导出/导入 JSON | 节点 composer 的形态、一键模板、价格透明、快捷键/小地图/吸附/80 步撤销 | 它的模型是黑盒（"智能图片 G2 臻享版"）；它的模板不可解释 |
| **即梦 AI** | 单点生成能力强 + 视频生态（Seedance 2.5 超长 30–180s、统一参考 50 个、数字人两条产线、TTS/音乐）+ **技能广场 186 个技能**（带使用量/点赞/作者/二创溯源）+ 输入框三件套 `@`/\`/\`技能/Agent 模式 | 视频与音频节点的**参数面**、**技能市场**的玩法、首屏只暴露 3 个决策点的克制 | 它是通用创作工具，不做"商品事实"；画布还在"全新画布"宣传期（未成熟） |
| **B 站教程流程**（口哨舞女装带货） | 一条**可复现的带货视频流水线**：素材图 → 分镜脚本 → 逐镜生成 → 换装/动作 → 拼接 → 成品 | 把这条流水线**产品化成模板图**（一键铺开节点 + 连线 + 参数） | 手工拖拽的繁琐（我们要"一键铺开，再进微调"） |

**我们的差异化（必须守住）**：商品事实（产品档案/卖点/合规护栏/尺寸锁/平台规格）。
知渔的模板是"一段提示词"，我们的模板应该是"**一段提示词 + 一套约束 + 一条可执行图**"。

### 1.1 即梦新版视频（BV11fYx6eEuc）第一手视觉解析要点

- **输入框就是"技能入口"**：占位文案 `上传参考文献、输入文本或 @ 使用正文或 / 调用技能`；
  一排开关 `Agent模式 / 自动 / 技能 / @`；技能以 chip 形式直接躺在输入框下方
  （`/微表情导演 Hot`、`/电影级长镜头运镜 New`、`/大师风格`、`/叙事短片导演分镜`）。
- **技能广场上线**："一键调用电影教科书级创作技能" —— 技能被当成**货架商品**在卖，而不是高级设置。
- **侧边栏三类资产**：`资产 / 主体 / 对话（历史会话）/ 画布（历史画布）` —— "主体"是**角色/主体一致性**的载体
  （这正是带货视频里"同一个模特"的解法）。
- **全新画布**的宣传语是"全流程创作 一站式完成"，说明**连即梦也认为画布是终点形态**。
- 生成交互是**对话式**（"生成一个法师研究卷轴的图片" → 返回`角色设定`+`主题表达`结构化文案），
  不是表单式 —— 与我们"节点 + composer"的路线可以互补：**首页对话式，画布结构化**。

## 2.3 假能力清单（做生态前必须处理，否则是空中楼阁）

调研中发现**界面上看起来有、后端其实是假的能力**。做节点生态之前必须先清掉，否则模板一铺开就是"假流程"：

| 能力 | 表面 | 真相 | 处理 |
|---|---|---|---|
| **TTS 配音** | 画布动作「TTS 配音（5 provider：火山/阿里云/ElevenLabs/Azure/MiniMax）」+ 生成音频节点 | `server/services/ttsBridge.mjs` 是 **mock adapter**：返回 data-URL 占位音频，不调任何真上游、**不收费**（`mockAudio: true`，路由注释自己写着 "mock audio"） | 二选一：**接真上游并计费**（推荐，音频是视频生态的必要零件）或 UI 明确标"示意/内测" |
| **chainService 前两步** | "1-click 视频模板" 4 步链 | 第 1/2 步 `deriveScript`/`deriveKeyframes` 返回 **占位数据**（mock） | 用真 LLM/VLM 替换，或标灰 |
| **`/api/canvas/tts`、`/api/canvas/one-click-video`** | 动作注册表里有 `execute.route` | **后端不存在这两条路由**（悬空） | 接线或删掉元数据 |
| **批量下载** | 规格函数 `downloadNodeMediaBatch` 已写好 | 全仓 0 引用，UI 无入口 | 接线（Quantv 也没有，是我们的加分项） |

> 结论：**P3 的音视频节点族开工前，必须先做"假能力清理"**（接真上游 + 计费，或在 UI 上诚实标注）。
> 这也是"每一个走上游的功能都要收积分"这条原则的反面：**不走上游的功能不能假装走过**。

## 3. 总体架构建议

### 3.1 分层（重要：不要再造第三套画布）

```
┌─ 表现层 ─────────────────────────────────────────────────┐
│ EcCanvas（唯一画布宿主）  VideoStudio 节点画布 → 迁移为画布的"视频视图"  │
├─ 编排层（新） ───────────────────────────────────────────┤
│ canvasGraphEngine（前端调度器）：拓扑/就绪/stale/重跑/进度聚合          │
│ graphRunService（后端宿主）：落库 job、CAS 租约、并发、幂等、计费预扣     │
├─ 能力层（已有，接进来即可） ──────────────────────────────┤
│ 20+ 执行原语：生图/变换/抠图/分层/OCR/反推/TTS/字幕/套装/视频任务/音频   │
│ 电商流水线 ecommerceEngine（作为"高价值复合节点"被图调用）              │
├─ 资产层（已有） ─────────────────────────────────────────┤
│ generated-assets + 产品档案 + 作品集 + 溯源（每个节点输出=一条资产记录） │
├─ 计费层（已有） ─────────────────────────────────────────┤
│ quote → hold → settle；每个节点动作一个 SKU；失败自动 release           │
└──────────────────────────────────────────────────────────┘
```

**关键决策：VideoStudio 的节点画布不再平行演进，而是作为"视频视图"并入同一套节点模型**
（它现在有 asset/shot/candidate 三类节点、端口不可拖、与 EcCanvas 后端不通——这是最大的架构债，
不合并的话以后每加一个视频能力都要做两遍）。

### 3.2 节点类型体系（保留现有 kind，补齐语义）

| 类别 | 节点 kind | 输入 | 输出 | 执行成本 |
|---|---|---|---|---|
| 素材 | `source_group`、上传、资产库 | — | image/video/audio | 免费（上传只占存储） |
| 文本 | `text`、`text-composer` | text/image | text | LLM：按 token（0.2 起） |
| 图片 | `image-composer`、`smart-remix`、`remove-bg`、`extend`、`inpaint`、`translate`、`upscale`、`layer-workbench` | image/text | image | 0.2~3.2 积分/次 |
| 视频 | `video-composer`（含首尾帧/参考视频/续写/换装/数字人） | image/text/video | video | 12~57 积分/条 |
| 音频 | **新增** `audio`（TTS/配音/对口型/音乐） | text/video | audio | 待定价（建议 1~3） |
| 应用 | `application`（模板/智能体：一键套图、一键带货视频） | 任意 | 任意 | 按内部节点合计 |

**新增的只有"音频"，其余 kind 我们已经有了**——缺的不是类型，是"边会跑"。

### 3.3 边 = 数据通道（N2 的落地方式）

```ts
// 现状：connection = { id, fromNodeId, fromPort:'out', toNodeId, toPort:'in', relation:'reference' }
// 目标：relation 决定语义，执行器按 relation 注入 inputs
relation: 'reference'  // 素材引用：上游 output 作为"参考图/参考视频"（@图片1）
        | 'derived'    // 派生：上游 output 直接成为本节点主输入（文本→图、图→视频）
        | 'input'      // 明确槽位输入（多图合成、首帧/尾帧）
```
- 执行前：`collectNodeInputsFromEdges(node, edges, nodes)` 按入边顺序组装 `inputs`（顺序即 `@图片1/@图片2`）。
- 校验：沿用 `isEdgeInvalid`，类型不符直接画红线并禁止执行（已有能力，只差接线）。
- 兼容：保留 `sourceNodeIds[0]` 回退，老图不炸。

### 3.4 执行引擎（N1/N4/N5/N8/N9）

**前端调度 + 后端宿主**（路线 B，能力地图 §9.3 的正解）：

1. 前端 `canvasGraphEngine`：算 ready 集（入度已满足且未 stale）→ 提交给后端 → 订阅状态 → 聚合进度。
2. 后端 `POST /api/canvas/graph/run`：收 `{documentId, nodes, edges, targetNodeIds, mode}`；
   - 落库 `canvas_graph_runs`（复用 jobStore 的 CAS 租约：`ecommerceEngine/jobStore.mjs` 的成熟模式）
   - 拓扑序执行，每个节点动作 → 现有执行原语；计费走 quote/hold/settle（**先报价后执行，失败 release**）
   - 状态回写：节点级进度（`queued/running/succeeded/failed/stale`）+ run 级汇总
3. **失败只污染子图**：下游标 `blocked`，无关分支继续跑。
4. **stale 传播**：上游产物变化 → 沿出边标 `stale` → UI 提示"3 个下游需要重跑"，一键按拓扑重放（只重跑 stale）。
5. **断点续跑**：关页面/断网后回来，run 状态从库里恢复（这是前端引擎做不到的，也是"跑 20 分钟视频链"必须的）。

### 3.5 模板 / 技能 / 智能体：三合一

现在有三套东西在做同一件事：一键模板（Quantv 式）、技能（我们已有）、application 节点。
**统一为一种东西：`Workflow Template（工作流模板）`**
```jsonc
{ "id": "tpl:video:口哨舞女装", "name": "...", "kind": "video",
  "nodes": [ /* 预置节点 + 相对坐标 */ ], "edges": [ /* 预置连线 */ ],
  "slots": [ { "nodeId": "n1", "role": "商品图", "required": true } ],   // 用户只填槽
  "skills": ["builtin:image:fashion_editorial"],                        // 附带技能（复用现有技能系统）
  "estimateUnits": 78000 }                                              // 预估总积分（跑前展示）
```
用户点一个模板 → 图上直接铺开节点与连线 → 只需拖入商品图 → 点运行。

**模板必须三件套（知渔二遍深挖结论：模板 = 图 + 便签教程 + 一键同款，缺一不可）**：
1. **图**：预置节点 + 连线 + 参数（用户只填槽）；
2. **便签教程**：贴在画布上的说明（他们用 5 张便签写"哪张图放哪、哪句话不用改"）；
3. **一键同款**：跑完能"再复制一份到我的画布"继续改。

**模板分三层（照抄，但我们的 L2/L3 要可解释）**：
| 层 | 内容 | 收费 |
|---|---|---|
| L1 提示词片段 | 可读可改的提示词模块（我们的技能系统就是这一层，已具备） | 免费 |
| L2 单节点模板 | 一个节点 + 预置提示词 + 参数（对应知渔的 image 40 / video 19） | 随节点动作计费 |
| L3 完整工作流 | **一整张可运行的图**（知渔有 272 个 featured 画布，详情接口直接给全文 prompt） | 不单独收费，只收内部节点 |

**技能系统不废弃，而是成为模板的"风格槽位"**（内置技能 = 官方模板的风格参数；用户技能 = 可挂到任意生成节点的风格覆盖）。

### 3.5.1 【最高价值】节点 composer 必须由服务端 schema 驱动

知渔的模型清单里 `genParams.params[]` 是一份**声明式参数 schema**：
```jsonc
{ "type": "select|referenceImages|referenceVideo|referenceAudio|prompt|voiceClone",
  "options": [...], "priceAddon": 0, "priceMultiplier": 1.0,
  "requiredTip": "上传 1 张正脸图", "showCondition": "..." }
```
**加一个模型 = 加一行数据，前端零改动。** 我们现在是前端硬编码参数控件（每个动作写一遍），
这是"以后每加一个模型/能力都要改前端"的根因。

→ 我们的做法：`server/billing/catalog.mjs` 旁边新增 `server/canvas/nodeModels.mjs`（模型 + 参数 schema + 计价加成），
前端 `canvasNodeComposer` 按 schema 渲染。**这一步做完，视频/音频节点族才有扩展性。**

### 3.5.2 `@图片N` 的编号就是连线位置（不是占位符）

知渔的媒体条按模态各自从 1 编号（文本1/图片1/视频1/音频1），**拖拽排序 = 改编号**。
所以"变量"在图里是**位置**，不需要用户理解模板语法。
→ 我们已有 `collectNodeInputsFromEdges` 的设计正好对上：按入边顺序生成 `@图片1..N`，拖拽改顺序即改引用。

### 3.5.3 边的三态与失败语义（对齐全套）

| 状态 | 触发 | UI |
|---|---|---|
| `is-invalid` | 类型不符 / 参考图超上限（知渔：上限 9） | 红边 + tooltip「当前模型不支持该上游输入，或参考素材数量已超出模型上限」 |
| `is-running` | 该边上游正在跑 | 流动动画 |
| `stale` | 上游产物已变、下游未重跑（**知渔没有，是我们的加分项**） | 黄边 + "重跑下游" |

建边前就要校验并 toast 原因（"参考图片已达上限 9 个"），不是建完才报错。

### 3.5.4 导出/导入：抄它的格式，补它的短板

知渔：导出 = JSON（`{__canvas:'da-ai-canvas', version:2, nodes, edges, stickers}`）；
**导入 = Ctrl+V 粘贴剪贴板 JSON**，校验 `__canvas` 字段，重新分配 id 后粘贴。
短板：**格式不对时静默按文本粘贴，没有任何导入报错**。
→ 我们要做：显式的"导入工作流"入口 + 校验失败给明确原因（版本不符/缺字段/节点类型未知）+ 导入预览（会创建哪些节点、预计积分）。

### 3.5.5 任务日志要暴露"预计 / 实际 / 已退还"三个数

知渔任务日志字段：生成 4 态 + 媒体后处理 8 态（含 `refunding`/`refunded`）、
`estimatedPoints / chargedPoints / refundedPoints`、四段时间轴、复制任务 ID、重新提交、15 秒轮询。
→ 我们的 hold/settle/release 天然支持，只要把三个数暴露到画布的任务面板即可（用户敢跑长链的前提）。

### 3.5.6 技能市场（抄即梦，比抄知渔更值）

即梦的技能市场实测：**186 个技能 / 12 个分类**，每个技能 = 一份完整的 SKILL.md（最长 19,247 字），
并带 **使用量 / 点赞 / 添加 三个公开计数 + 作者署名 + 是否私有 + `original_skill_id` 二创溯源**；
官方自己也在里面发布技能。技能内部只调度约 6 个工具（文生图/图生图/首帧生视频/状态查询/多模态转视频/视频编辑）
—— **它是提示词驱动，不是图驱动**。

→ 对我们的启示（我们已有技能系统 P0/P1，只差市场层）：
1. 技能库里加"**使用量/收藏/派生链**"三个计数与作者署名（我们已有 owner-scoped 技能与版本，加字段即可）；
2. **派生要留溯源**（`derived_from`），别人基于你的技能改的，能点回原作者——这是技能市场的飞轮；
3. 官方技能与用户技能**同场展示**（我们现在的内置技能是只读的，可以标注"官方"但仍可派生）；
4. **技能就是一层提示词 + 槽位**，不要试图让用户画图才能用技能（图是进阶玩法，技能是入门玩法）。

### 3.5.7 输入框三件套：`@` 引用素材 + `/` 调用技能 + Agent 模式（即梦实测）

即梦视频里的输入框原文：`Seedance 2.5 上传参考文献、输入文本或 @ 使用正文或 / 调用技能`，
旁边还有 **`Agent模式` / `自动` / `技能` / `@`** 一排开关；技能广场里是 `/电影级长镜头运镜`、`/微表情导演`、`/叙事短片导演分镜` 这类**斜杠技能**。

→ 我们的节点 composer 也应该有这三件套：
| 语法 | 含义 | 我们的落地 |
|---|---|---|
| `@` | 引用上游节点素材（编号=入边顺序） | 已设计（P0 `collectNodeInputsFromEdges`） |
| `/` | 调用技能（内置/用户技能，斜杠菜单） | **已有技能系统，缺一个斜杠菜单入口**（低成本、高感知） |
| Agent 模式 | 让模型自己决定要不要拆步骤/调用工具 | 对应我们的"电商流水线"（`application` 节点 / 一键套图） |

**技能不该只藏在"技能库弹窗"里**——用户写提示词的地方（节点 composer、首页输入框）就该能用 `/` 拉出来。

### 3.5.8 首屏只暴露 3 个决策点（即梦的克制，我们的短板）

即梦首页「生成偏好」抽屉只有：**自动/图片/视频 + 比例九选一 + 其他设置 + 一枚模型 chip**，
后端极其复杂但首屏只给 3 个决策点。我们的 composer 现在是"参数全摊开"。
→ 我们的节点 composer 也应分两层：**默认只显示 模型 + 比例 + 预计积分**，"高级"里才展开时长/分辨率/参考上限等。

### 3.6 视频与音频生态（对标即梦 + B站流水线）

**参数面直接照抄即梦实测（一次留够，别以后再改结构）**：

| 维度 | 即梦的实测档位 | 我们的节点参数 |
|---|---|---|
| 分辨率 | 480p / 720p / 1080p | `resolution` 三档 |
| 时长 | 4–30s，**超长 30–180s** | `duration` 分档（含超长） |
| 参考输入 | **统一参考 50 个**（图 30 + 视频 10 + 音频 10，总时长 ≤30.2s） | 端口上限要按模态分别给（我们现在是 9） |
| 视频编辑 | 4–30s，提示词 ≤2000 字 | 独立动作，不跟"生成"混 |
| 数字人 | **两条独立产线**：对口型（基础 / 大师 / 快速，多人脸检测 + 静音检测，音频 1–30s）、动作模仿（大师/生动/快速） | 两个独立节点 kind，别塞进"视频"里 |
| 音频 | TTS（语速 + 情绪，**按百字计费**）、音乐生成 | 两个独立节点，TTS 按字数计价 |
| 价格展示 | **元/秒**（banner：720P 低至 0.4 元/秒，会员 5 折） | 视频按"元/秒"给用户直觉，积分按四维档折算 |
| SKU 维度 | 模型 × 分辨率 × 时长 × 有无输入视频 | 我们现在的 SKU 只有"档位"，要补后三维 |

视频节点族要有的一等公民能力（一次留够端口和参数，别以后再改结构）：
- **输入**：首帧/尾帧、参考视频、参考图（多张）、参考音频、文本脚本
- **控制**：比例、时长、分辨率、镜头运动、动作强度、换装/换人（角色一致性）
- **音频**：TTS 配音、对口型、BGM、字幕烧录
- **产物**：单镜视频、拼接成片、分镜表（shot list，可作为文本节点回流）

模板图示例（"电商口哨舞带货"一键铺开）：
`商品图(source) → 分镜脚本(text) → 首帧图(image ×N) → 逐镜视频(video ×N) → 拼接(video-out) → 配音(audio) → 成片`

### 3.7 资产与溯源

每个节点输出自动落一条资产记录（已有 generated-assets + 溯源字段），并在图上可"回填素材库/复用为下一个商品的输入"。
这就是用户说的"各种素材通过上传或生成最终串联成一个生态"。

### 4.1 四条原则

## 5. UI/UX 设计要点（对标后取长补短）

1. **节点 composer 三段式**（学知渔）：上部"输入胶囊"（上游节点缩略图 + × 可摘除 + 添加输入）→ 中部"指令"（支持 `@图片1 @文本1` 引用，Markdown）→ 下部"模型 + 参数 + 次数 + ✦ 预计 X 积分"。
2. **连线即语义**：拖出时高亮合法端口、非法端口变红并给出原因（类型不符/会成环）；连线中点可切换 relation（引用/派生）。
3. **一键铺开模板**：模板卡片 → 图上铺开节点和连线 → 只留必须用户填的槽（商品图/卖点）。
4. **跑图体验**：整图运行时节点边框走进度、失败的节点红框 + "只重跑这条链"、stale 节点黄框 + "重跑受影响的下游"。
5. **标配体验**（我们现在有规格没接线）：小地图、对齐吸附、自动整理、80 步撤销（覆盖边与视口）、便签、分组、导出/导入 JSON。
6. **移动端**：节点图不做移动编辑，只做"查看进度 + 预览 + 分享"。

**执行契约**（一次 run 的完整语义）：
1. 入参 `{ documentId, nodes, edges, targetNodeIds }` → 服务端**重新算拓扑**（不信前端算的序）；
2. 逐节点：`quoteFeature(sku, qty)` → `walletService.createHold` → 调执行原语 → 成功 `settle` / 失败 `release`；
3. 幂等键：`graph-run:<runId>:<nodeId>:<inputFingerprint>`（换了输入才会重跑，防重复扣费）；
4. 失败只把**该节点及其下游**标 `blocked`，无关分支继续；
5. 状态回写 `canvas_graph_run_steps`，前端轮询/断线重连后从库里恢复进度；
6. 并发：复用现有 `imageGenerationPool`（图片 3 并发）与 `videoQueue`（按 owner 公平）。

**验证**（成本受控）：单测（内存 sqlite 建两表 + 假执行器）→ 一条真实链路（文本→图，**1 张图**）→
不跑全量 Canary（除非改了生成管线本身）。

**每期都必须做到**：`npm test` 全绿 + 零成本契约测试 + 前端部署用 frontend 档（不跑生图 Canary），
只有"生成链路本身改了"才跑全量档。

## 7. 自洽性与风险检查

1. **不新增第三套画布**：VideoStudio 节点画布必须并入，否则每加一个能力做两遍（当前最大的结构性风险）。
2. **计费不重复**：模板运行不收费，只收节点动作；application 节点展示"内部合计"，禁止黑盒定价。
3. **老图兼容**：`sourceNodeIds[0]` 回退保留；relation 默认值不变；老文档不迁移、只按需升级。
4. **单文件巨石**：`EcCanvas/index.jsx` 6182 行、`server/index.mjs` 5274 行。抽执行器时**新代码一律新文件**，index.jsx 只做接线，避免 TDZ 事故（仓库有历史教训）。
5. **两套节点渲染并存**（旧 `workflowNodes/index.jsx` 转发到 modular）——改端口前先确认改的是哪一套。
6. **测试护栏**：378 个测试文件、画布相关 ≥60 个，节点结构变更必须同步契约测试（好处是有回归网）。
7. **成本护栏**：P0/P2 完全不花钱；P1 一次生成；P3 需要你确认预算后再跑。

## 8. 需要你拍板的决策点

1. **画布是不是唯一主战场？**（建议：是。VideoStudio 画布并入，电商/小红书/视频都从画布进入，其他页面降级为"简化入口"。）
2. **模板从哪来？**（建议：先做 5 个官方模板：女装模特、白底主图、场景图、换装短视频、口播带货；模板 = 节点图 + 技能 + 槽位。）
3. **价格档位**（第 4.2 节的表，尤其 TTS/对口型/拼接要不要单独收费）。
4. **音视频节点先做哪几个？**（建议顺序：TTS 配音 → 首尾帧视频 → 对口型 → 拼接成片。）
5. **P0 是否立刻开工**（只动前端、零成本、可单独上线，不依赖任何上游预算）。
